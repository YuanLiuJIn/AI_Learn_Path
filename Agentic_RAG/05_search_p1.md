# 05. Search-P1：路径中心奖励破解 Agentic RAG 稀疏奖励困境

> 论文：ACL 2026 收录
> 核心贡献：双轨路径评分机制 + 软性结果评分，打破 Agentic RAG 训练的稀疏奖励瓶颈。

---

## 1. 背景：Agentic RAG 训练的最大难题

```text
强化学习训练 Agentic RAG 时面临的核心问题：

Agent 的任务："搜索 → 分析 → 决定再搜还是回答"
传统奖励："最终答案是否正确"

问题：
  Agent 搜了 5 轮，最后答案错了 → 奖励 0
  Agent 搜了 5 轮，最后答案对了 → 奖励 1

  但这 5 轮中，哪些搜索步骤是正确的？哪些是浪费？
  模型无法分辨。

  这就是"稀疏奖励"问题：只在终点有信号，
  中间每一步都不知道自己做得好不好。
  导致：样本效率低、收敛困难、探索盲目。
```

**典型失效案例**（来自论文原文）：

```text
Query: "Who is the lead singer of the band performing Bang Bang Rock & Roll?"

传统方法（Search-R1）：
  直接搜 "Bang Bang Rock & Roll"
  → 返回全是歌名、歌词、翻唱版本
  → 找不到乐队名 → 检索失败

Search-P1：
  Plan: 先查专辑 → 定位乐队 → 搜主唱
  Step1: "Bang Bang Rock & Roll album"
  Step2: 找到乐队 "The Rockers"
  Step3: "The Rockers lead singer"
  → 精准命中答案
```

## 2. Search-P1 的核心架构

```text
┌─────────────────────────────────────────────────────┐
│              Search-P1 训练框架                       │
│                                                     │
│  ① 离线参考规划器生成                                │
│     用高能力模型通过拒绝采样 + 投票蒸馏                │
│     生成"黄金搜索路径"作为训练参考                     │
│                                                     │
│  ② 双轨路径评分机制                                  │
│     Track A - 自洽性评分                             │
│      模型是否忠实执行了自己的规划？                    │
│      规划步骤 vs 实际执行步骤的匹配度                  │
│                                                     │
│     Track B - 专家对齐评分                           │
│      模型的实际步骤是否覆盖了参考路径的关键节点？       │
│      顺序无关，看语义覆盖度                            │
│                                                     │
│     最终路径奖励 = max(自洽分, 对齐分)                 │
│                                                     │
│  ③ 软性结果评分                                      │
│     不只对/错二元，对"部分正确"也给分                  │
│     例：多跳问题答对一半 → 给部分奖励                  │
│          推理逻辑正确但答案有小误差 → 给推理质量奖励     │
│                                                     │
│  ④ 奖励函数总设计                                     │
│     R_total = λ_p·R_path + λ_a·R_outcome + λ_f·R_format│
│     最优配置：λ_p=0.3, λ_a=0.6                        │
└─────────────────────────────────────────────────────┘
```

## 3. 双轨路径评分机制详解

### Track A：自洽性评分

```text
S_self = r_planner × (n_exec / n_plan) × (n_exec / n_actions)

r_planner：模型是否形成了规划
n_exec：实际执行的步数
n_plan：规划的步数
n_actions：总动作数

含义：
  模型先规划了"要搜什么"
  然后实际执行了其中的一部分
  评估"规划和执行的一致程度"

  规划了 4 步，执行了 3 步，动作总数 5 步
  → S_self = 1.0 × (3/4) × (3/5) = 0.45
  → 中等分数：有规划，但执行偏离了
```

### Track B：专家对齐评分

```text
S_ref = (n_covered / |R_ref|) × (n_covered / n_actions)

n_covered：实际步骤覆盖了参考路径中的多少个关键节点
|R_ref|：参考路径的节点总数
n_actions：实际动作总数

含义：
  不看顺序，只看"关键检索节点有没有被覆盖"
  参考路径：搜专辑 → 定位乐队 → 搜主唱（3 个节点）
  模型实际：搜了歌名 → 搜了专辑 → 搜了主唱
  → 覆盖了"搜专辑"和"搜主唱"2 个节点
  → S_ref = (2/3) × (2/3) = 0.44
```

### 最终路径奖励

```text
R_path = max(S_self, S_ref)

含义：
  如果模型自己规划得好 → 用自洽分
  如果模型路径接近专家 → 用对齐分
  取最大值，鼓励两种优秀行为
```

## 4. 软性结果评分

```text
传统评分：
  答案对 → 1
  答案错 → 0
  问题：忽略了"部分正确"的宝贵训练信号

软性评分：
  R_outcome = α × r_acc + (1-α) × r_reason

  r_acc：答案准确性（0~1）
    多跳问题答对 50% → 0.5
    完全正确 → 1.0

  r_reason：推理质量（0~1）
    逻辑链完整 → 0.8
    引用正确来源 → 0.9
    推理步骤有缺失 → 0.4

  例：Agent 搜了 5 轮，答案对了一半，推理链完整
    r_acc = 0.5, r_reason = 0.8, α = 0.6
    R_outcome = 0.6 × 0.5 + 0.4 × 0.8 = 0.62
    → 不是 0！仍然有学习信号！
```

## 5. 实验效果

```text
基座模型：Qwen2.5-7B
评测：7 个公开 QA 数据集 + 业务数据集

公开数据集（平均准确率）：
  Search-R1（基线）：  39.6%
  HiPRAG：            43.0%
  Search-P1：         47.3%（+7.7% vs Search-R1，+4.4% vs HiPRAG）

多跳任务增益最明显：
  Musique：           +5.6%
  Bamboogle：         +4.0%

业务数据集：
  AD-QA 准确率提升：   +20.6%

训练效率：
  收敛速度提升 2.5 倍（60 step 达 Search-R1 150 step 效果）
  推理轮数更稳定：成功/失败轮数差异降低 47%-60%

消融实验（哪些组件贡献最大）：
  1. 参考路径对齐（Reference-Alignment）：-5.3%（贡献最大）
  2. 自洽性评分（Self-Consistency）：    -3.1%
  3. 软性结果评分（最复杂任务受益最大）： AD-QA +8.8%
```

## 6. 行为模式变化：从"盲目搜索"到"先规划后执行"

```text
Search-R1 的行为模式：
  看到问题 → 直接搜关键词 → 看结果 → 再搜 → 再搜...
  像新手：拿到一个问题就胡乱搜索

Search-P1 的行为模式：
  看到问题 → 先规划："这个问题需要分三步：①查A ②定位B ③搜C"
  → 按计划执行 → 每步验证 → 给出答案
  像专家：先想清楚路径，再一步步执行
```

---

## 7. 和 GRPO 的关系

```text
Search-P1 的路径奖励和 GRPO 可以结合：

GRPO：对同一个问题生成多个搜索路径
  每个路径用 Search-P1 的"双轨评分"打分
  组内比较 → 强化最优路径 → 弱化低效路径

结合后的优势：
  GRPO 的"组内相对比较" + Search-P1 的"路径中心奖励"
  → 模型学会了"给定一个问题，什么是好的搜索路径"
  → 不只是搜索更快，而是搜索策略本身更聪明
```

---

## 8. 一句话总结

> Search-P1 的核心创新在于"双轨路径评分"：既奖励忠实执行自己规划的 Agent（自洽性），也奖励学到专家思路的 Agent（对齐性）。配合"软性结果评分"让失败样本也能提供学习信号。最终让 Qwen2.5-7B 在 7 个数据集上平均准确率提升 7.7%，训练收敛速度提升 2.5 倍，业务场景提升 20.6%。
