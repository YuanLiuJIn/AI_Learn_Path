# 你用的 AI Skill 靠谱吗？TRACE 五维评测体系

> 来源文章：《你用的 AI Skill 靠谱吗？五大维度帮你快速判断》（作者 jasminzhao）
> 平台背景：SkillHub 是面向中文用户优化的 AI Skills 社区（官网 skillhub.cn），已积累大量 Skill。TRACE 体系由平台运营实践经验沉淀而成。
> 核心：TRACE 是一套「质量观察坐标」而非终局裁判，帮用户快速识别高质量 Skill。

---

## 〇、为什么需要评测体系

在 Agent 架构中，大模型是「大脑」，Skill 是「手」——将推理落地为可操作动作。当前 Skill 生态指数级膨胀但质量参差，用户缺筛选依据、开发者缺构建指引。TRACE 正是在此背景下提出，帮用户判断 Skill 是否值得尝试、适合什么任务、有何限制，以及开发者从哪继续优化。

> TRACE 不是终局裁判，更接近质量观察坐标。

---

## 一、TRACE 五维评测体系

五维是一条由**基础保障走向最终价值**的评估链路：

```
T(可信任) → R(可靠) → A(适用) → C(规范) → E(有效)
能不能放心用  能不能稳定用  该不该这场景用  能不能理解维护复用  是否真解决问题
```

### T — Trust 可信任度（被采用的前提）
- 迁移软件安全基本原则：最小权限、输入验证、敏感数据保护、依赖安全。
- 一个值得信任的 Skill 不应要求与任务无关的高权限，不应在用户不知情下暴露敏感信息。
- 平台硬标准检测：AI Native 扫描 → 静态分析（木马/后门）→ 动态沙箱运行验证（挖矿、偷连未知 API 一跑露馅）。
- 同时检测是否能在目标网络环境下直接跑通、是否完整支持中文交互（完全依赖海外 API 在国内基本不可用）。

**例子**：「周报生成」Skill 若嵌入无关恶意文件，平台「安检线」先用 AI Native 扫恶意行为、再静态分析扫木马后门、最后丢进动态沙箱「小黑屋」跑一圈，挖矿偷连 API 必露馅。

### R — Reliability 可靠性（稳定用）
- 软件工程中可靠性=规定条件下持续完成规定功能。对用户：同样任务是否每次正常执行、异常输入是否合理处理、失败是否给可理解反馈。
- 关注运行稳定性、功能完整性、异常处理能力。好 Skill 在常见/边界/复杂输入下一致表现，不可完成时清楚说明原因，不把调试成本转移给用户。

**例子**：
- ✅「PDF 解析」遇扫描件（无文字层）明确提示「该文件为扫描图片无法提取文本，建议先 OCR」并给后续建议。
- ❌ 同样场景无报错直接返回空/乱码，用户反复试不同文件都找不到问题。

### A — Adaptability 适用性（该不该这场景用）
- Agent 调用 Skill 依赖语义匹配（意图/Skill 描述/参数/上下文）。能力边界模糊会导致：该调用时没调、不该调用时误触发。
- 关注 Skill 与用户需求的匹配精度：适用范围是否清晰、触发条件是否明确、能力边界是否可预期。

**例子**：
- ✅「会议纪要整理」清楚说明适合会议录音转写稿/聊天记录/粗略笔记，输出含待办/责任人/截止时间/风险点；也说明不适合替代法务审阅或合同确认。
- ❌ 只写「帮你提升办公效率」，无适用输入/输出/边界，写邮件做表格读合同生成 PPT 都可能被触发，每个都只完成很浅一层。

### C — Convention 规范性（能不能理解/维护/复用）
- 成熟软件工程证明：可读性、可维护性、渐进式信息披露是降低协作成本关键。
- 关注是否具备清晰信息架构、稳定组织方式、充分但不过载的文档，以及对常见误用/已知限制/典型案例的表达。规范性决定 Skill 能否从一次性能力沉淀为可复用资产。

**例子**：
- ✅「简历优化」文档明确列输入要求/输出模板/示例简历/常见限制/隐私提醒；参数命名稳定，版本更新说明新增能力与不兼容变更。
- ❌ 名称/描述/实际能力对不上，文档只有「上传文件即可使用」，用户不知传什么格式，开发者难判断改提示词/参数/执行逻辑。

### E — Effectiveness 有效性（是否真解决问题）
- 回到最终价值：是否真帮用户完成任务。不只结果是否正确，还包括输出是否完整、符合预期格式、可直接使用，以及是否在用户原能力外提供额外信息整合/判断建议/质量提升。

**例子**：
- ✅「公众号文章润色」不只改语气，还按目标读者调标题/开头/段落节奏/小标题，少量检查即可发布。
- ❌ 只把原文替换成更华丽表达，没改善结构/例子/论证，表面字数多用户仍需重梳逻辑补案例删空话。

## 二、平台评测实践

- **评测对象**：平台上全量 Skill。
- **结果展示**：Skill 详情页以雷达图（五维得分）+ 综合评分 + 详细文字报告呈现。
- **定位**：仅供参考，帮用户建立判断、帮开发者定位改进方向，不构成终局裁判。
- **未来迭代（二期）**：加沙箱评测机制，对全量 Skill 做真实环境测试。

---

## 三、给开发者/使用者的可迁移清单

构建或选用 Skill 时按 TRACE 自检：
1. **Trust**：权限是否最小？有无密钥/敏感信息泄露风险？目标环境能否运行？
2. **Reliability**：边界/异常输入是否有合理反馈？
3. **Adaptability**：description 是否写清「能处理什么、不能处理什么」？
4. **Convention**：文档/参数命名/版本记录是否清晰？
5. **Effectiveness**：输出是否完整可用、是否带来增量价值？

> 一个 Skill 可能安全规范很好但有效性依赖具体任务；也可能某垂直场景突出但适用范围有限——结合用户目标理解这些差异，TRACE 更适合作为「使用前参考信号」而非唯一依据。
