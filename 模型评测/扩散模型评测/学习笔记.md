## 1. 前置基础知识（生成模型原理决定了评测难点）

### 1.1 扩散模型速览

**前向加噪**：\( x_t = \sqrt{\bar\alpha_t}\,x_0 + \sqrt{1-\bar\alpha_t}\,\epsilon \)
**反向去噪**：网络预测 \(\epsilon_\theta(x_t,t,c)\)，迭代还原 \(x_0\)

关键组件与评测含义：

| 组件 | 对评测的影响 |
|---|---|
| **Latent Diffusion（VAE 隐空间）** | VAE 重建损失设定了画质上限；细小文字/人脸易糊 |
| **Text Encoder**（CLIP / T5 / LLM） | 决定图文一致性上限。CLIP-only 模型对长 prompt、计数、否定词理解差 → 这正是 GenEval/T2I-CompBench 要测的 |
| **CFG scale** | 越大越贴合 prompt 但越饱和失真 → 一致性与画质的 trade-off，**评测必须固定或扫描** |
| **采样器与步数**（DDIM/DPM++/Flow Matching） | 直接影响质量与速度，是效率维度 |
| **架构**（U-Net → DiT / Flow Matching） | 新架构在长 prompt 与文字渲染上更强 |

**核心难点**：生成任务**没有唯一正确答案**，无法用 accuracy。这决定了整个评测体系必须建立在
「分布距离 + 判别式验证 + 人类偏好」三条腿上。

### 1.2 三类评测手段的定位

```
质量(Fidelity) ── FID / KID / IS ── 分布级，看整体像不像真图
对齐(Alignment) ── CLIPScore / VQAScore / GenEval ── 单图级，看画没画对
偏好(Preference) ── HPSv2 / ImageReward / PickScore / 人评 ── 单图级，看好不好看
```
**三者缺一不可，且经常互相矛盾**（FID 好但不对齐、对齐好但不美观）。能讲清这一点是面试的分水岭。

## 2. 评测维度体系

```
T2I / T2V 评测
├── 图像质量      FID, KID, IS, 人评清晰度/伪影
├── 图文一致性
│   ├── 整体语义   CLIPScore, VQAScore
│   ├── 组合性     GenEval(计数/颜色/位置/属性绑定), T2I-CompBench
│   └── 长prompt   DPG-Bench
├── 人类偏好      HPSv2, ImageReward, PickScore, Arena Elo
├── 多样性        Recall/Coverage, 同prompt LPIPS 方差, 模式坍塌检测
├── 可控性        ControlNet 条件遵循度、编辑区/非编辑区分离
├── 特定能力      文字渲染(OCR校验)、人脸/手部、风格一致性
├── 安全合规      NSFW率、名人/IP相似度、训练数据记忆化复制
├── 效率          步数、延迟、显存、单图成本
└── 视频专属
    ├── 时序一致性  主体/背景一致性、闪烁
    ├── 运动质量    运动平滑度、动态程度(防"伪静止")
    └── 物理合理性  VBench-2.0 强调
```

### 关键洞察：VBench 的「动态程度」维度
只测"时序一致性"会奖励**几乎静止的视频**（静止画面一致性满分）。VBench 专门加入 **dynamic degree** 维度与之对抗。
> 这是「指标被 hack」的经典案例，面试讲这个非常加分。

## 3. 指标数学定义与陷阱

### 3.1 FID（`doc/FID_*.pdf`）
\[ \text{FID} = \lVert \mu_r-\mu_g \rVert^2 + \mathrm{Tr}\left(\Sigma_r+\Sigma_g-2(\Sigma_r\Sigma_g)^{1/2}\right) \]
在 Inception-V3 pool3 特征上假设高斯分布，算 Fréchet 距离。

**必须知道的六个坑**：
1. **样本量敏感**：< 10k 样本时 FID 严重有偏，标准做法用 50k
2. **resize 实现差异**：PIL vs TF vs OpenCV 的双线性插值不同，FID 能差好几点 → 必须用 **clean-fid**
3. **参考集依赖**：换参考数据集数字完全不可比
4. **对图文一致性完全无感**：画错内容但画得真实，FID 照样很低
5. **与人类判断相关性弱**（尤其在高质量区间）
6. 不能跨论文比较，只能同实验内部比较

### 3.2 CLIPScore
\[ \text{CLIPScore} = w\cdot\max(\cos(E_I, E_T), 0),\ w=2.5 \]
**缺陷**：对组合关系不敏感——"红球在蓝盒左边"和"蓝球在红盒右边"分数几乎一样（词袋效应）。

### 3.3 VQAScore（`doc/VQAScore_*.pdf`）★当前最优自动一致性指标
把一致性转成 VQA 问题：给图 + 问 "Does this figure show '{prompt}'?"，
\[ \text{VQAScore} = P(\text{"Yes"} \mid \text{image}, \text{question}) \]
- 用 CLIP-FlanT5 等生成式 VQA 模型，**无需人类反馈微调**
- 在组合性 prompt 上显著超过 CLIPScore 与 LLM-judge 方案
- 配套 GenAI-Bench：1600 条真实用户组合式 prompt

### 3.4 TIFA（`doc/TIFA_*.pdf`）
LLM 从 prompt 自动生成若干 QA 对 → VQA 模型看图回答 → 准确率即为 TIFA 分。
- 优点：**可解释**（能定位哪个元素没画出来）
- 缺点：依赖 QA 生成质量与 VQA 模型能力

### 3.5 GenEval（`doc/GenEval_*.pdf`）★判别式客观评测范式
用 **目标检测器（Mask2Former）** 客观验证 6 类任务：
单物体 / 双物体 / **计数** / **颜色** / **位置** / **属性绑定**
- 不依赖人评、不依赖 LLM judge，**完全可自动化且可复现**
- 输出分维度成绩，直接指出模型短板（多数模型在"位置"和"属性绑定"上崩溃）
- **这是"把生成评测转成可判定问题"的最佳范本**

### 3.6 人类偏好模型
| 模型 | 训练数据 | 特点 |
|---|---|---|
| **ImageReward**（`doc/ImageReward_*.pdf`） | 137k 专家对比 | 同时考虑一致性/美学/无害；提出 **ReFL** 用它直接微调扩散模型 |
| **HPS v2**（`doc/HPSv2_*.pdf`） | HPD v2，798k 对比 / 433k 图 | 跨模型可比性好，配套标准化 benchmark（4 种风格 prompt） |
| **PickScore**（`doc/PickScore_*.pdf`） | Pick-a-Pic，500k+ 真实用户偏好 | CLIP-H 微调，**超过人类专家间一致性**；可用于 prompt 无关的图片排序 |

**共同陷阱 — Reward Hacking**：用这些分数做 RLHF/DPO 会导致过饱和、油画感、构图套路化。
→ 评测时必须**交叉验证**（多个偏好模型 + 人评抽检 + FID 监控画质是否漂移）。

### 3.7 视频指标
- **FVD**：I3D 特征上的 FID，同样有 FID 的所有毛病 + 对帧数/分辨率极敏感
- **VBench 16 维**（`doc/VBench_*.pdf`）：
  - 视频质量：主体一致性、背景一致性、时序闪烁、运动平滑度、**动态程度**、美学质量、成像质量
  - 视频-条件一致性：物体类别、多物体、人物动作、颜色、空间关系、场景、外观风格、时序风格、整体一致性
  - **每个维度都做了与人类偏好标注的对齐验证** ← 这是 VBench 的最大价值
- **VideoScore**（`doc/VideoScore_*.pdf`）：在 VideoFeedback（37.6k 人标）上训练的回归模型，5 维度自动打分，与人评 Spearman 显著优于 GPT-4V

## 4. 核心论文精读要点

### 4.1 VBench（`VBench_*.pdf`）★结构化评测设计范本
三步法，可迁移到任何生成任务的评测设计：
1. **维度分解**：把笼统的"视频质量好"拆成 16 个可独立测量的维度
2. **为每个维度定制 prompt suite + 专用自动指标**（如用 DINO 特征算主体一致性、用 RAFT 光流算运动平滑度）
3. **人类偏好标注验证**：每个维度都收集人评，验证自动指标与人评的一致性
后续 VBench-2.0 转向「内在真实性」：物理规律、常识合理性、人体结构正确性。

### 4.2 ImagenHub（`ImagenHub_*.pdf`）★人评 SOP 范本
统一 7 类条件图像生成任务（T2I、mask 编辑、text 编辑、主体驱动生成/编辑、多概念、控制生成）的评测：
- 统一推理流水线（固定 seed、统一参数）
- **两个人评指标**：SC（Semantic Consistency 语义一致性）、PQ（Perceptual Quality 感知质量），各分三档 {0, 0.5, 1}
- 总分 = \(\sqrt{SC \times PQ}\)（几何平均，任一项差则总分低）
- 报告 **Krippendorff's α** 保证标注可信度
> **JD 里"制定标注规范"的最佳模板，直接照抄这套 SOP 就是专业方案。**

### 4.3 T2I-CompBench（`T2I-CompBench_*.pdf`）
6000 条组合式 prompt，三大类：属性绑定（颜色/形状/纹理）、对象关系（空间/非空间）、复杂组合。
- 针对不同类别用不同评测器：BLIP-VQA（属性）、UniDet（空间）、CLIPScore（非空间）、3-in-1（复杂）
- 启发：**不同能力维度要用不同的判定器**，一个指标包打天下必然失真

### 4.4 HEIM（`HEIM_*.pdf`）
HELM 的 T2I 版：12 个维度（对齐、质量、美学、原创性、推理、知识、偏见、毒性、公平、鲁棒性、多语言、效率）× 62 个场景。
- 核心结论：**没有模型在所有维度都最好** → 评测报告不应给单一总分排名
- 大量维度必须靠人评，自动指标覆盖不了

### 4.5 GenAI-Bench / GenAI-Arena（`GenAI-Bench_*.pdf`）
- 1600 条真实用户组合式 prompt + 人类偏好标注
- 验证了 VQAScore 在这些困难 prompt 上远超 CLIPScore
- Arena 式众包投票 + Elo 榜，是生成模型主观评测的基础设施形态

### 4.6 EvalCrafter（`EvalCrafter_*.pdf`）
- 700 prompt + 17 个客观指标（视觉质量、内容质量、运动质量、文本-视频对齐）
- 关键方法：**用人评对客观指标做回归系数拟合**，让加权总分逼近人类意见
- 这个"自动指标 → 人评校准"的做法是评测岗的核心技能

## 5. 人评设计实操（生成类评测的命脉）

### 5.1 为什么必须人评
自动指标在生成领域可靠性远低于判别领域。HEIM/ImagenHub/VBench 都以人评为最终标尺。

### 5.2 设计要点
1. **拆分问题，不要问"好不好"**
   - 问题 A：图片是否画出了 prompt 描述的全部内容？（一致性）
   - 问题 B：图片本身是否清晰无畸变？（质量）
   - 合并方式用几何平均（ImagenHub 做法），避免"美但不对"拿高分
2. **双盲 + 随机顺序**：消除位置偏差与品牌偏见
3. **锚点样本**：插入已知好/坏样本校准标注员尺度
4. **标注员数量**：每样本 ≥ 3 人，报 Krippendorff's α 或 Fleiss' κ
5. **筛人机制**：黄金题不合格的标注员数据剔除
6. **Rubric 必须给正反例图**：纯文字描述无法统一尺度

### 5.3 自动指标与人评对齐验证（必做实验）
- 收集 N 个模型 × M 个 prompt 的人评分
- 计算自动指标与人评的 **Spearman ρ / Kendall τ**
- 报告在**系统级**（模型排序）和**样本级**（单图打分）两个粒度的相关性
- 结论用于决定该自动指标能否替代人评做日常回归

## 6. 工程化落地

### 6.1 评测配置的公平性清单
生成模型评测最容易被质疑不公平，以下必须统一并公开：
- 采样步数、采样器、CFG scale、seed、分辨率、宽高比
- negative prompt（有些模型默认带，有些不带）
- 是否使用 refiner / 超分后处理
- prompt 是否经过改写（很多产品有隐式 prompt rewrite，会严重影响一致性分数）
- 每个 prompt 生成几张（建议 ≥ 4 张取均值，生成方差很大）

### 6.2 工具链
| 工具 | 用途 |
|---|---|
| **clean-fid** | 修正 resize 实现差异的 FID，**必须用它而非旧脚本** |
| **VBench** | 视频生成 16 维评测 + leaderboard |
| **EvalCrafter** | 视频多指标工具箱 |
| **ImagenHub** | 条件图像生成统一评测 + 人评 SOP |
| **GenEval / T2I-CompBench** | 组合性客观评测 |
| **t2v_metrics（VQAScore 官方库）** | 一致性打分 |
| **HPSv2 / ImageReward / PickScore** | 偏好打分 |
| **GenAI-Arena** | Arena 式众包投票平台参考实现 |

### 6.3 Pipeline 特点（与 LLM 评测的差异）
- **重 GPU 推理**：生成成本远高于判分，需要批量与缓存生成结果
- **产物是图片/视频**：需要对象存储 + 去重（hash）+ 可视化 review 界面
- **人评环节是流程一部分**：需要标注平台对接，不能纯自动
- **多指标并行打分**：一批图同时跑 FID/CLIPScore/VQAScore/HPSv2，做成打分器插件化

## 7. 结果分析要点

1. **三角报告**：质量 / 一致性 / 偏好三类指标同时给，并说明它们的冲突点
2. **分维度短板定位**：GenEval 的 6 类、VBench 的 16 维，直接指出改进方向
3. **CFG 扫描曲线**：横轴 CFG，纵轴 CLIPScore/VQAScore 与 FID，展示 trade-off 曲线（比单点分数信息量大得多）
4. **失败模式画廊**：手/文字/多物体/否定词/空间关系，每类挑典型 bad case
5. **自动指标与人评的相关性**：说明你的自动指标可信度
6. **Reward hacking 检查**：偏好分升高时，FID 与多样性是否恶化
