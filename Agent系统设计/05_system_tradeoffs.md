# 05. 系统协同与权衡

> 目标：理解上下文、工具、循环如何相互影响，以及不同场景下如何做配置权衡。

## 1. 三要素的相互依赖

### 上下文 ↔ 工具

```text
好的上下文（文件结构、环境信息）
  ↓
工具调用参数更准确（路径正确、依赖明确）
  ↓
工具执行成功率提升
  ↓
减少错误和重试
  ↓
上下文不被错误污染，保持高质量
```

### 工具 ↔ 循环

```text
工具高成功率 + 智能错误反馈
  ↓
减少无效重试步骤
  ↓
相同任务需要的步数减少
  ↓
更少达到步数限制
  ↓
任务完成率提升
```

### 循环 ↔ 上下文

```text
循环步数越多
  ↓
对话历史积累越多
  ↓
上下文压力越大，需要裁剪压缩
  ↓
但裁剪可能损失关键信息
  ↓
影响后续步骤的决策质量

因此：控制循环步数 = 降低上下文压力
```

## 2. 场景化配置

| 场景 | 上下文策略 | 工具策略 | 循环策略 |
|---|---|---|---|
| **追求准确度**（复杂重构） | 最大化保留，保守压缩，全量 Memory | 全量详情，详尽描述，完整反馈 | 宽松限制，较多步数，允许探索 |
| **追求效率**（简单任务） | Cache 优先，激进压缩，按需 Memory | 渐进发现，精简描述，快速反馈 | 紧凑限制，较少步数，快速终止 |
| **追求成本**（大规模部署） | 激进裁剪，频繁压缩，精准 Memory | 渐进发现，按需加载，结果裁剪 | 严格限制，紧缩步数，早期终止 |
| **生产推荐**（平衡点） | 分区+智能，双重阈值，相关 Memory | 固定+渐进，上下文感知，智能反馈 | 步数限制，三层防护，智能终止 |

## 3. 动态调整策略

### 实时监控指标

```text
工具成功率 → 持续偏低？→ 增强上下文、改进工具描述
循环率 → 频繁循环？→ 加强循环检测、改进错误反馈
任务完成率 → 偏低？→ 放宽步数限制、优化压缩策略
平均步数 → 过多？→ 提升工具成功率、减少重试
Cache 命中率 → 偏低？→ 优化前缀稳定性、调整分区结构
平均响应时间 → 过长？→ 激进裁剪、并行化、减少步数
Token 成本 → 过高？→ 压缩更激进、渐进式发现、提升 Cache
```

### 调整决策树

```text
工具成功率 < 目标？
  → 诊断原因
    ├─ 上下文不足？→ 增加环境信息
    ├─ 描述不清？→ 增强工具描述
    └─ 参数理解偏差？→ 添加更多示例

任务完成率 < 目标？
  → 分析原因
    ├─ 步数限制过严？→ 动态提升限制
    ├─ 过度压缩？→ 放宽压缩阈值
    └─ 循环终止过早？→ 调整循环检测参数

Token 成本 > 预算？
  → 成本优化
    ├─ Cache 命中率低？→ 优化前缀设计
    ├─ 步数过多？→ 提升工具成功率
    └─ 上下文冗余？→ 激进裁剪和压缩
```

## 4. 核心指标体系

### 一级指标

| 指标 | 定义 | 影响因素 |
|---|---|---|
| 任务完成率 | 成功完成任务的比例 | 上下文质量、工具可靠性、循环控制 |
| 首次成功率 | 工具调用或操作首次成功的比例 | 工具描述质量、上下文完整性 |
| 平均完成步数 | 完成任务平均所需步骤数 | 工具执行成功率、错误反馈质量 |
| Token 效率 | 单位任务的 Token 消耗 | 裁剪策略、压缩时机、Cache 命中率 |

### 二级指标

| 指标 | 定义 | 反映什么 |
|---|---|---|
| 循环率 | 陷入无效循环的任务比例 | 循环检测有效性 |
| Cache 命中率 | LLM 请求中 Cache 命中的 Token 比例 | 前缀稳定性设计 |
| 工具执行成功率 | 工具调用成功执行的比例 | 工具设计和上下文支持 |
| 用户干预率 | 需要用户手动干预的任务比例 | Agent 自主性 |

## 5. 设计原则

```text
原则 1：可控性优先于智能性
  宁可让人类控制，也不要完全自主

原则 2：小步快跑优于大步慢走
  每步做一件事，问题早发现、易回滚

原则 3：优雅终止优于强制完成
  不完美的总结 > 无限循环

原则 4：状态透明优于黑盒执行
  用户应该清楚每步在做什么

原则 5：描述清晰度 = 成功率
  详细说明 + 具体示例 > 简短描述

原则 6：分层设计 = 效率
  固定工具完整 + 动态工具渐进

原则 7：上下文完整度 = 准确性
  环境信息 + 项目状态 > 孤立工具

原则 8：反馈质量 = 恢复能力
  原因分析 + 修复建议 > 简单报错

原则 9：结果裁剪 = 下一步质量
  智能保留 > 全量返回 > 简单截断
```

## 6. 一句话总结

> Agent 系统的优化不能只盯一个要素。上下文、工具、循环相互影响，需要整体思考。不同场景有不同的最优配置：准确度优先就放大上下文和步数，成本优先就激进压缩和裁剪。核心是通过实时监控指标动态调整，而不是找一套"万能配置"。
