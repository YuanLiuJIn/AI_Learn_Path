# 04 分阶段端到端评测

> 对应 JD：「算法手段，对基座大模型和 AI Native 应用进行分阶段、端到端评测」。
> 核心是把评测拆成"训练链路的分阶段" + "应用链路的全流程"，而不是单点打分。

---

## 0. 两个关键词

- **分阶段（staged）**：模型在训练/迭代的不同阶段，评什么不一样（base 看 PPL，chat 看 Arena）。
- **端到端（end-to-end）**：对 AI Native 应用，从用户原始输入到最后输出的整条链路一起评，而非只评模型。

---

## 1. 基座大模型的分阶段评测

训练链路：`Pretrain → Base → SFT → Reward Model → RLHF/RLVR → Chat`

| 阶段 | 评什么 | 指标 | 注意 |
|---|---|---|---|
| Pretrain | 语言建模能力 | **PPL / loss**（越低越好） | base 模型不能用 chat 模板 |
| Base | 少样本客观能力 | MMLU few-shot（loglikelihood） | 固定 shot/顺序 |
| SFT | 指令遵循 | IFEval / 格式遵循率 | 看是否过拟合 SFT 数据 |
| Reward Model | 偏好判别 | **RewardBench**（chosen>rejected） | RM 过强会导致奖励黑客 |
| RLHF/RLVR | 对齐 + 推理 | Arena Elo / MATH | **对齐税**：客观分可能降、主观升 |
| Chat（发布） | 综合能力 | MT-Bench + 业务集 + 安全 | 全维度报告 + 回归对比 |

> **对齐税（Alignment Tax）**：RLHF 后客观题分数下降、主观分上升。报告必须**同时给两侧**，否则误导训练决策（语言笔记 §1.1）。

### 分阶段评测的工程价值
- 每个 checkpoint 自动评测，画**训练曲线**，识别退化（某步推理分骤降）。
- 定位问题到阶段：客观降→SFT/数据问题；主观降→RM/RLHF 问题。

---

## 2. AI Native 应用的端到端评测

AI Native 应用 = 以大模型为核心的产品（RAG 问答、Copilot、Agent、对话助手）。端到端评测关心"最终用户拿到的结果好不好"，链路包含：检索 → 拼接 → 生成 → 后处理。

### 2.1 端到端 vs 单点
| 单点评测 | 端到端评测 |
|---|---|
| 只评生成模型 | 评整条链路（检索质量也计入） |
| "答案对不对" | "用户问题有没有被真正解决" |
| 易做 | 难做（链路长、变量多） |

### 2.2 常见应用类型与评测重点
- **RAG**：检索召回（Recall@K / nDCG）+ 生成忠实度（答案是否基于检索内容，不幻觉）+ 答案正确性。
- **Copilot（代码）**：单测通过率、编辑成功率、人工接受率。
- **对话助手**：多轮一致性、安全性、指令遵循。
- **Agent**：任务完成率、工具调用准确率、轨迹效率（见第 05 章）。

---

## 3. 评测流程的分阶段（生命周期）

把"一次发布"拆成四段评测，强度递增：

```
① 冒烟测试 (Smoke)   ── 小集(20~50题) 快速验证没崩、格式对、不报错
② 回归测试 (Regression) ── 中集 对比上一版本 delta，防退化
③ 发布门禁 (Release Gate) ── 全量 + 业务集 过阈值才准发
④ 线上监控 (Online)   ── 抽样真实流量 + 用户反馈 持续观测分布漂移
```

> 这与第 02 章 §7.2「版本门禁」呼应：分阶段评测是门禁的前置流程。

---

## 4. 端到端评测设计模式

### 4.1 可判定化（最重要的方法论）
把开放式任务转成可自动判定的题：
- RAG 忠实度 → 用「答案能否被检索片段支撑」的 NLI/LLM 判定；
- 代码 → 跑单元测试（SWE-bench 范式）；
- 图像 → 检测器（GenEval）；
- 语音 → ASR 回环算 WER。

### 4.2 分层评测（降本）
先小集快速筛模型，再大集精细评，避免每个候选都跑全量。

### 4.3 黄金集 + 探集
- **黄金集**：人工精标、稳定、做回归锚点（不能进训练）；
- **探集**：滚动更新的难例，探测能力边界（LiveBench 思路）。

## 5. 案例：RAG 端到端评测

```
用户问题
  → 检索 top-K 文档   [评 Recall@K / 相关性]
  → 拼 prompt + 生成   [评忠实度: 答案是否源自检索]
  → 最终答案          [评正确性 + 有用性]
```
- 忠实度指标：用 NLI 模型判「答案句是否被某检索片段蕴含」→ 不蕴含即幻觉。
- 端到端正确性：用 LLM-judge 或人工，看是否真正回答了问题。
- 工具：[Ragas](https://github.com/explodinggradients/ragas)（faithfulness/answer_relevancy/context_recall）。

---

## 6. 案例：Agent 端到端评测（预览）

Agent 的端到端 = 给一个真实任务，看它能否自主调工具完成：

- **任务完成率**（success rate）：最终状态是否满足目标。
- **工具调用准确率**：调用的参数/顺序对不对。
- **轨迹效率**：步数、token 成本。
- **可靠性 pass^k**：同一任务跑 k 次全成功的概率（τ-bench，见第 05 章）。
