# 08. GeoInfoAgent：GUI Agent + Agentic RAG 地理信息汇总平台

> 目标：设计一个融合 GUI Agent 和 Agentic RAG 的多源地理信息智能汇总系统。
> 适用场景：气象数据采集、环境监测、灾害预警、多源数据交叉分析。
> 简历定位：体现 Agent 系统设计能力 + 前沿技术组合 + 完整工程闭环。

## 2. GUI Agent 采集引擎

### 混合感知方案（受两篇内部技术文章启发）

```text
方案 A：DOM 文本化（适合标准网页）
  数据平台、表单筛选、表格结果
  用 Playwright 直接读 DOM → 转编号文本 → LLM 决策
  优势：快（0.5s/步）、准（无坐标误差）、便宜

方案 B：截屏识别（适合地图/卫星图/非标准界面）
  用 OmniParser 结构化识别 UI 元素
  多模态模型输出坐标 → 键鼠模拟
  优势：通用（任何界面都能用）

方案 C：网络请求捕获（最优终局）
  首次用 GUI Agent 探索 → 捕获真实 API 请求
  → 后续转 requests 直接调用
```

### 关键实现细节

```text
① 操作指令解析器（支持 9 种操作）：
   click、type、hotkey、scroll、drag、wait、screenshot、right_click、double_click

② 坐标归一化：
   模型输出 0-1000 相对坐标 → 按实际分辨率换算像素坐标
   例：模型说 (500, 300) → 1080p 屏幕 → (960, 540)

③ 记忆增强设计（防死循环）：
   记录每步的截图 MD5 + 操作类型
   连续 3 次同屏同操作 → 检测到死循环 → 切换策略或请求人工

④ LangGraph 工作流（优于硬编码循环）：
   截图 → 模型决策 → 执行操作 → 检查完成
         ↖_________________________↗
   状态机管理：AgentState 传递指令、截图路径、执行步骤、历史上下文

⑤ 中文输入方案：
   避免 pyautogui 中文输入失败 → 用剪贴板粘贴替代
```

### 两阶段采集策略

```text
首次访问（探索模式）：
  Page-Agent 风格 DOM 文本化 → 记录表单字段名、按钮文字、下拉选项

后续访问（固化模式）：
  用 Playwright 写死选择器 → 直接填写提交
  大幅提升稳定性和速度
```

## 3. Agentic RAG 检索引擎

```text
核心 Pipeline（LangGraph 实现）：

① Query Router（复杂度判断）
   简单查询 → 单次检索
   复杂查询 → 分解子问题

② Multi-Source Retriever
   向量数据库：历史报告、文档
   Web 搜索：最新事件
   SQL 查询：结构化数据

③ Self-RAG Evaluator
   相关性评分
   完整性检查
   矛盾检测

④ CRAG Corrector
   检索不足 → 换关键词重搜
   数据矛盾 → 扩大范围求证
   补充 Web 搜索

⑤ Citation Generator
   每个数据点标注来源
   检索时间、置信度
```

### 数据质量评估（Search-P1 思路）

```text
交叉验证维度：
  自洽性：同一指标在不同数据源是否一致（允许合理偏差）
  对齐性：数据是否符合专家知识的预期
  完整性：所有请求的城市和指标是否都覆盖了
  时效性：数据时间是否匹配用户要求

部分可用性处理：
  广州缺少 7/5 的降水数据 → 标注"缺失"并给出最近可用日期的数据
  气象站和卫星有 0.5mm 偏差 → 标注偏差范围，由 Reviewer 判断是否可接受
```

## 4. 分阶段实施与学习路线

### 阶段 1：单数据源基础采集（2 周）

```text
任务：
  1. Playwright 实现 CMA 数据平台自动化
  2. 登录态保存与复用
  3. 表单自动填写（关键词、时间、站点）
  4. 下载拦截与文件保存
  5. 网络请求捕获

产出：
  单人可运行的 CMA 数据采集脚本
  自动下载指定时间范围的数据
```

### 阶段 2：Agentic RAG 管道（2 周）

```text
任务：
  1. LangGraph 搭建 RAG 管道
  2. 向量数据库导入气象文档
  3. Self-RAG 检索评估节点
  4. CRAG 自动修正节点
  5. 来源追溯功能

产出：
  自然语言查询 → 自动检索相关气象数据
  自动评估质量和补充搜索
```

### 阶段 3：GUI Agent 增强（3 周）

```text
任务：
  1. 集成 OmniParser UI 元素识别
  2. 混合感知（DOM + 截图）
  3. 接入第二个数据源（卫星数据/NASA）
  4. 自适应采集策略（探索→固化）
  5. GRPO 领域特化训练（可选）

产出：
  跨数据站的 GUI Agent
  操作准确率提升对比
```

### 阶段 4：多 Agent 协作（3 周）

```text
任务：
  1. Planner Agent（任务分解与分配）
  2. Worker Pool（并行采集）
  3. Reviewer Agent（质量审核）
  4. 数据融合与交叉验证
  5. FastAPI + Web UI

产出：
  完整的 GeoInfoAgent 系统
  可视化报告展示
```

## 5. 简历描述模板

> **GeoInfoAgent：多源地理信息智能汇总平台**
> 
> 设计并实现融合 GUI Agent 与 Agentic RAG 的多源地理信息汇总系统。GUI Agent 端采用 DOM 文本化与截屏识别混合感知方案，集成 OmniParser 结构化 UI 理解与 LangGraph 状态机工作流，实现对 3 个无 API 气象数据站点的自动化采集，结合记忆增强机制防死循环、坐标归一化适配多分辨率。Agentic RAG 端基于 LangGraph 实现 Self-RAG 质量评估与 CRAG 自动修正，引入 Search-P1 风格的双轨数据质量评分（自洽性+对齐性），检索准确率较朴素 RAG 提升 35%。系统采用 Planner-Worker-Reviewer 三角色多 Agent 协作架构，5 路并行采集使单次查询耗时从 120s 压缩至 35s。
