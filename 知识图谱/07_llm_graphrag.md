# 07. LLM + 知识图谱与 GraphRAG

> 目标：理解知识图谱如何与大模型结合，构建更可解释、更适合复杂关系问题的 RAG 系统。

## 1. 普通 RAG 的局限

普通文本 RAG 流程：

```text
用户问题
  ↓
向量检索相关文档 chunk
  ↓
把 chunk 塞进 Prompt
  ↓
LLM 生成答案
```

它适合：

```text
事实问答
文档摘要
单篇或少量文档内的信息查询
```

但不擅长：

```text
多跳关系问题
全局主题总结
实体关系分析
复杂因果链
跨文档社区结构
需要可解释路径的问题
```

例如：

```text
“这些论文之间形成了哪些研究流派？”
“某个风险事件可能通过哪些企业关系传播？”
“某种疾病、症状、药物、检查之间有哪些路径？”
```

这些问题需要图结构。

## 2. GraphRAG 是什么？

GraphRAG = Graph + Retrieval-Augmented Generation。

一句话：

> GraphRAG 用知识图谱组织文档中的实体、关系和社区结构，再把图查询结果作为上下文提供给大模型。

普通 RAG 关注文本片段：

```text
Chunk 1
Chunk 2
Chunk 3
```

GraphRAG 关注知识结构：

```text
实体
关系
路径
社区
子图
摘要
```

## 3. GraphRAG 的典型流程

```text
原始文档
  ↓
实体与关系抽取
  ↓
构建知识图谱
  ↓
图社区发现 / 聚类
  ↓
生成社区摘要
  ↓
用户问题
  ↓
根据问题检索相关实体、子图、社区摘要、原文证据
  ↓
LLM 生成答案
```

## 4. GraphRAG 与文本 RAG 的区别

| 维度 | 文本 RAG | GraphRAG |
|---|---|---|
| 基本检索单元 | 文本 chunk | 实体、关系、路径、社区、子图 |
| 擅长问题 | 局部事实问答 | 多跳关系、全局总结、结构分析 |
| 可解释性 | 引用文本片段 | 引用路径和实体关系 |
| 构建成本 | 较低 | 较高，需要抽图和维护图谱 |
| 质量风险 | chunk 召回不准 | 抽取错误、图谱不完整 |

## 5. LLM 在知识图谱中的作用

### 5.1 LLM 辅助抽取

```text
文本 → LLM → 实体、关系、事件、属性
```

优点：

```text
少样本能力强
能处理复杂句式
能快速适配新领域
```

风险：

```text
幻觉
关系类型不稳定
实体边界不一致
输出格式不稳定
```

需要配合：

```text
Schema 约束
JSON 结构化输出
置信度
证据片段
规则校验
人工抽检
```

### 5.2 LLM 生成图查询

用户问：

```text
“阿司匹林治疗哪些症状？”
```

LLM 可以生成 Cypher：

```cypher
MATCH (:Drug {name:'阿司匹林'})-[:TREATS]->(s:Symptom)
RETURN s.name
```

这个方向叫 Text2Cypher 或 Text2SPARQL。

### 5.3 LLM 解释图查询结果

图数据库返回：

```text
阿司匹林 → 治疗 → 发热
阿司匹林 → 缓解 → 疼痛
阿司匹林 → 风险 → 胃出血
```

LLM 负责组织自然语言回答：

```text
阿司匹林常用于缓解发热和疼痛，但存在胃出血等风险，使用前应注意禁忌和剂量。
```

## 6. GraphRAG 的检索模式

### 6.1 局部检索 Local Search

围绕问题中的实体找邻居和路径。

```text
Query 提到实体 A
  ↓
实体链接到图谱节点 A
  ↓
检索 A 的一跳/两跳邻居
  ↓
返回相关子图
```

适合：

```text
实体问答
关系查询
路径解释
```

### 6.2 全局检索 Global Search

先对图做社区发现和社区摘要，再回答全局问题。

```text
知识图谱
  ↓
社区发现
  ↓
每个社区生成摘要
  ↓
用户问全局问题
  ↓
检索相关社区摘要
  ↓
综合回答
```

适合：

```text
“这批文档主要讲了哪些主题？”
“这个领域有哪些研究方向？”
“不同主题之间有什么关系？”
```

### 6.3 路径检索 Path Search

查找实体之间的路径。

```text
A → ? → ? → B
```

适合：

```text
因果链
供应链
论文引用链
风险传播链
推荐解释
```

## 7. GraphRAG 的上下文组装

GraphRAG 给 LLM 的上下文通常包括：

```text
相关实体列表
关系三元组
路径证据
社区摘要
原文引用
置信度
时间信息
来源信息
```

示例：

```text
实体：阿司匹林、发热、疼痛、胃出血
关系：
  阿司匹林 -缓解-> 发热
  阿司匹林 -缓解-> 疼痛
  阿司匹林 -可能导致-> 胃出血
证据：来自文档 X 第 3 段
```

## 8. GraphRAG 的工程难点

```text
实体抽取不稳定
实体对齐困难
图谱更新成本高
关系抽取错误会污染路径
图查询和向量检索如何融合
子图太大导致上下文超限
LLM 生成查询可能不合法
```

常见解决方式：

```text
Schema 约束抽取
小步构图，持续校验
图检索 + 向量检索混合
路径裁剪
社区摘要
查询模板与 Text2Cypher 结合
结果必须带来源证据
```

## 9. 知识图谱作为 Agent 记忆

Agent 的长期记忆可以用图谱表示：

```text
用户 → 偏好 → Python
用户 → 正在学习 → 知识图谱
知识图谱 → 包含主题 → GraphRAG
用户 → 完成项目 → 多模态检索学习专题
```

相比普通文本记忆，图记忆优势是：

```text
关系清晰
可多跳查询
可合并实体
可解释
适合长期演化
```

## 10. 一句话总结

> LLM 擅长语言理解和生成，知识图谱擅长结构化关系和可解释推理。GraphRAG 把二者结合：用 LLM 从文档中抽取图谱，用图结构组织实体关系和社区，再把相关子图、路径和证据喂给 LLM，从而更好地回答多跳关系、全局总结和复杂分析问题。
