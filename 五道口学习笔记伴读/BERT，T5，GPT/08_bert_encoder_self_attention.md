## 〇、30 秒直觉：注意力 = "调一杯鸡尾酒"

一句话版本：**Self-Attention 就是让每个词，从整句话里按"相关度"取信息来更新自己**。

再具体一点，把它想成调酒——每个词最后得到的新向量是一杯**按配方调出来的酒**：

| 步骤 | 调酒 | 矩阵运算 |
|---|---|---|
| 尝一口打个分 | 每个原料"合不合我口味" | `Q · Kᵀ` |
| 换算成配方 | 百分比，加起来 100% | `softmax` |
| 按配方倒酒摇匀 | 把各原料原液掺起来 | `权重 · V` |

图书馆版本（07 用过的比喻）同样成立，两个比喻分工不同：

| 角色 | 图书馆里的意思 | 一句话 |
|---|---|---|
| **Q**（Query，查询） | 你心里带着的问题 | "我此刻在**找什么**" |
| **K**（Key，键） | 每本书封面上的索书标签 | "我**能匹配什么**" |
| **V**（Value，值） | 书里的正文 | "我**实际有什么**" |

**最关键的一句：被混合的是 V，不是 K。** K 只负责"被打分"，V 才负责"被取走"——这是三个矩阵存在的全部理由。

> 注意这个"自"（Self）：Q、K、V **全部来自同一个输入序列**——不是拿外部问题去查文档，是句子自己内部互相查。

## 一、总公式与形状全景

BERT 的自注意力核心就一个公式：

```
Attention(Q, K, V) = softmax( Q · Kᵀ / √d_k ) · V
                        └──── 权重 W ────┘
```

记 `hidden = 768`（d_model），BERT-base 用 **12 个头**，所以每个头：

```
d_k = 768 / 12 = 64
```

以第 2 步喂进去的 bank 句为例（batch=1、22 个 token，先暂时丢掉 batch 维看单样本，`N=22`），形状一路流动：

| 步骤 | 形状 | 是什么 |
|---|---|---|
| 输入 embedding `X`（07 的 `hidden_states[0]`） | `[22, 768]` | 22 个词，每词 768 维 |
| 乘三个矩阵得 `Q/K/V` | `[22, 768]` × 3 | 每个词的"问题/标签/正文" |
| 切成 12 个头，看其中 1 个头 | `[22, 64]` × 3 | 每个头只处理 64 维子空间 |
| 打分 `Q · Kᵀ` | `[22, 22]` | 第 i 行 = 第 i 个词看全句 22 个词的原始分 |
| `÷ √64` 再 `softmax` | `[22, 22]`，**每行和为 1** | 真正的注意力权重 |
| `权重 · V` | `[22, 64]` | 第 i 行 = 第 i 个词按权重混合后的新向量（单头） |
| 12 个头拼回去 | `[22, 768]` | 多头注意力输出（再过一层投影 W_o） |

> **shape 记忆锚**：`[N, 768]` 进来，`[N, 768]` 出去——**形状不变**，变的只是每个词的数值（07 说的"原地更新"）。中间那张 `[N, N]` 就是 07 里 `attentions` 的 `[1, 12, 22, 22]` 中的每个 `[22, 22]`。

## 二、先用 3 个词、2 维，把全流程手算一遍

64 维算不动，先用 **`d_k = 2`、3 个词** 把四个步骤完整走一遍。真实情况只是把 2 换成 64、把 3 换成 22，数学一模一样。

句子：`[river, bank, robber]`。假设 `Wq/Wk/Wv` 训练完毕，得到（V 的第 1 维代表"水/地理"气息，第 2 维代表"犯罪"气息）：

```
Q（我想找什么）        K（我能匹配什么）      V（我有什么内容）
river  [1.0, 0.0]     river  [1.0, 0.0]     river  [2, 0]   ← 全是"水"
bank   [0.8, 0.6]     bank   [0.6, 0.8]     bank   [1, 1]
robber [0.0, 1.0]     robber [0.0, 1.0]     robber [0, 2]   ← 全是"犯罪"
```

### ① 打分 `S = Q · Kᵀ`

`S[i, j]` = 第 i 行的 Q 与第 j 行的 K **对应位置相乘再相加**（点积）：

```
S[river, ·] = [1*1+0*0,      1*0.6+0*0.8,      1*0+0*1     ] = [1.0, 0.60, 0.0]
S[bank,  ·] = [0.8*1+0.6*0,  0.8*0.6+0.6*0.8,  0.8*0+0.6*1 ] = [0.8, 0.96, 0.6]
S[robber,·] = [0*1+1*0,      0*0.6+1*0.8,      0*0+1*1     ] = [0.0, 0.80, 1.0]
```

形状：`[3,2] @ [2,3] = [3,3]` → 这就是那张 `[N, N]` 表，**N 个词两两打一遍分**。

### ② `÷ √d_k = ÷ √2 ≈ ÷ 1.414`

```
river : [0.707, 0.424, 0.000]
bank  : [0.566, 0.679, 0.424]
robber: [0.000, 0.566, 0.707]
```

（为什么要除，见 4.2。这里数值太小看不出差别，真实 64 维时不除会出大事。）

### ③ softmax（逐行，`dim=-1`）

以 river 行为例：`e^0.707 = 2.028`、`e^0.424 = 1.528`、`e^0 = 1`，和 = 4.556：

```
river : [2.028, 1.528, 1.000] / 4.556 = [0.445, 0.335, 0.219]   行和 = 1.0 ✓
bank  : [1.761, 1.972, 1.528] / 5.261 = [0.335, 0.375, 0.290]   行和 = 1.0 ✓
robber: [1.000, 1.761, 2.028] / 4.789 = [0.209, 0.368, 0.423]   行和 = 1.0 ✓
```

### ④ 混合 `输出 = 权重 · V`

river 的新向量 = `0.445·V(river) + 0.335·V(bank) + 0.219·V(robber)`：

```
river  = 0.445*[2,0] + 0.335*[1,1] + 0.219*[0,2] = [1.225, 0.773]   ← "水"那一维更大
bank   = 0.335*[2,0] + 0.375*[1,1] + 0.290*[0,2] = [1.045, 0.955]   ← 两边都沾，居中
robber = 0.209*[2,0] + 0.368*[1,1] + 0.423*[0,2] = [0.786, 1.214]   ← "犯罪"那一维更大
```

### 看结果 —— 这就是 07 现象的答案

- `river` 端：**偏向"水"**；
- `robber` 端：**偏向"犯罪"**；
- `bank`：**两边都沾一点，卡在中间**。

现在把 bank 挪到另一句话里（旁边是 `robber / vault` 而不是 `river / fishing`）：

- bank 自己的 Q **没变**（同一个词、同一个 `Wq`）；
- 但对面的 **K 全变了** → 打分变了 → 配方变了 → 调出来的酒就变了。

**"同一个 bank 在不同句子里是两个向量"**——07 验证了现象，这一节是产生现象的齿轮。

## 三、跟着 notebook 手算真模型（不是玩具）

notebook 用的不是手写的小矩阵，而是 **`bert-base-uncased` 真实权重**（注意 07 用的是中文 `bert-base-chinese`；本篇 notebook 取英文模型，道理完全一样，`seq_len` 那封 newsgroup 邮件截断到 201）。

### 3.1 先弄清楚一件事：`nn.Linear` 存 `(out, in)`，为什么前向是 `x @ Wᵀ + b`？

先不管 PyTorch，从数学写起。一个线性层要算的是：

```
y_j = W[j,0]·x_0 + W[j,1]·x_1 + ... + W[j,in-1]·x_{in-1} + b_j     （对每个输出维 j）
```

也就是：**W 的第 j 行，负责产出第 j 个输出**。所以 W 很自然地写成 `[out, in]`——**每行一个输出神经元**，一行里存着它对所有输入的权重。这是 PyTorch（及几乎所有框架）的**存储约定**。

现在把 N 个样本堆成矩阵 `X: [N, in]`（PyTorch 惯例：**每行一个样本**），要得到 `Y: [N, out]`：

```
X[N, in]  需要乘一个  [in, out]  的矩阵   →   只能用 Wᵀ
Y = X @ W.T + b          # [N,in] @ [in,out] = [N,out] ✓
```

写成形状就一目了然：**`(N, in) @ (in, out)` 中间那个 `in` 必须相等才能消掉**，所以必须转置。

```python
import torch
lin = torch.nn.Linear(768, 768)
W = lin.weight    # torch.Size([768, 768])  ← (out_features, in_features)
b = lin.bias      # [768]

x = torch.randn(22, 768)
y = x @ W.T + b                          # [22, 768]   手写前向
torch.allclose(y, lin(x), atol=1e-6)     # True
```

> **记住一句就够**：`(out, in)` 是"**怎么存**"，`x @ Wᵀ` 是"**怎么用**"；中间的转置是矩阵乘法的维度匹配逼出来的，不是额外操作。

### 3.2 切出"第 0 个头"的 Q、K、V

**头是怎么切出来的**：一个 `[768, 768]` 的 `Wq`，它的 **768 个输出维 = 12 个头 × 每头 64 维**。

⚠️ **这里有个极易踩的坑**（正是由 3.1 的 `(out, in)` 引起）：

> 因为 `Wq` 是 `(out, in)`，**输出维是"行"不是"列"**。所以第 0 个头用的是 **前 64 行**，不是前 64 列：
>
> ```python
> Wq_0 = Wq[:64, :]     # [64, 768]  ✅ 前 64 个输出维
> # Wq[:, :64]          # [768, 64]  ❌ 这是"前 64 个输入维"，语义完全不对
> ```
>
> 由于 BERT 恰好 `in == out == 768`，两种切片**形状上不报错**，所以写错了也跑得通、只是结果错——必须靠理解 `(out, in)` 来防住它。

等价写法（notebook 的写法，也是更推荐的写法）：

```python
Q_0 = emb_output @ Wq.T[:, :64] + bq[:64]    # [201, 64]  ✅
```

`Wq.T` 是 `[in, out]`，此时**列**才是输出维，所以 `[:, :64]` 正确。两种写法数值完全一样（因为 `Wq.T[:, :64] == Wq[:64, :].T`）。

三个头向量：

```python
Q_0 = emb_output @ Wq.T[:, :64] + bq[:64]    # [201, 64]
K_0 = emb_output @ Wk.T[:, :64] + bk[:64]    # [201, 64]
V_0 = emb_output @ Wv.T[:, :64] + bv[:64]    # [201, 64]
```

**注意：切的是输出维，输入仍是完整 768。** 每个头都"看得见"整句的完整 768 维信息，只是各自只**产出** 64 维的摘要。12 个头不是"把输入切成 12 块各自为政"。

> HuggingFace 真正实现不会先切权重再算，而是**一次算完整 768 再 `view/transpose` 切头**——一次大 matmul 比 12 次小 matmul 快得多，数值完全等价。这就是 08B 分块矩阵实现的主题。

### 3.3 打分：`Q · Kᵀ / √64`，再过 softmax

```python
d_k = 64
attn_weights = (Q_0 @ K_0.T) / math.sqrt(d_k)     # [201, 201]
attn_weights = torch.softmax(attn_weights, dim=-1)

# 验证：每一行（每个词）对全句的注意力加起来必须 = 1
attn_weights.sum(dim=-1)     # 全部 ≈ 1.0
```

`attn_weights[i, j]` 的含义：**第 i 个词（查询方）分配给第 j 个词（被看方）的信息占比**。行和为 1 = "每个词把 100% 的注意力配额分给全句"。

> 注意区分：**`Q·Kᵀ` 是"原始分"（score），softmax 之后才是"权重"**。07 里 `attentions` 存的是 softmax 之后的版本。

### 3.4 混合：`权重 · V`

```python
context_0 = attn_weights @ V_0      # [201, 64]
```

第 i 行 = `Σ_j weights[i, j] · V[j]`：把自己看得最重的那些词的"正文"，按权重掺到一起。

> **回到 bank 例句**（07 的三兄弟）："bank(河岸)"发 Query 出去找，"river / fishing / bank"的 Key 匹配度高 → softmax 后它们权重高 → 混合出的新向量里带着"水边"的气息；而"bank(劫匪)"那一路高权重给的是"robber / vault"。**同一个词，因上下文不同，查到的内容不同，更新后的向量自然不同**——这正是 07 验证"三个位置三个向量"的内部机制。

## 四、四个"为什么"（本集最该记住的）

### 4.1 为什么点积 `Q · Kᵀ` 就叫"打分"？

因为**点积就是相似度**，两个角度理解：

- **几何角度**：`q·k = |q|·|k|·cosθ`。两向量方向越一致，cosθ 越接近 1，点积越大。
- **逐维角度**：64 个维度上，同号相乘得正、异号得负，最后求和 = "**在多少个维度上达成了一致**"的累积值。

而"什么算一致"不是人规定的，是 `Wq / Wk` 这两个**可学习矩阵**学出来的。训练前它们随机；训练后 `Wq` 学会"把 bank 变成一个'我在找地理/自然类伙伴'的查询"，`Wk` 学会"把 river 变成一个'我是水系标签'的键"，两者一点积自然就高。

> **为什么不用余弦相似度？** 点积**不做归一化**，保留了向量模长——"这个词本身有多重要"这个信息不会被抹掉；而且点积在 GPU 上就是一次 matmul，是最快的操作。

### 4.2 为什么除 `√d_k`？（最该记住的一个 why）

**一句话：不除的话 softmax 会"撑死"，梯度归零，模型直接学不动。**

点积是 64 项相加。假设每项大致是 ±1 量级的随机数，64 项正负相消后，结果的**方差 = 64，标准差 = 8**——分数会飘到 ±8 甚至 ±16 的量级。

而 softmax 里有个 `exp`，对大数极其敏感。看同一组"意思相同、量级不同"的分数：

| | softmax 前的分数 | softmax 结果 |
|---|---|---|
| **不除** | `[8, 1, 0]` | `[0.9988, 0.0009, 0.0003]` ← 几乎 one-hot |
| **÷ 8** | `[1, 0.125, 0]` | `[0.560, 0.234, 0.206]` ← 有区分度 |

不除的后果有两个，一个比一个严重：

1. 输出几乎等于"只取分数最高的那一个词"（**硬选择**），其余词的信息全丢了；
2. softmax 在这个区域的**梯度 ≈ 0**，反向传播传不回去 → **训练停摆**。

除以 `√d_k` 就是把分数**统一压回 ±1 量级**，让 softmax 待在"梯度大、区分度好"的舒适区。

> 直觉：不管头多宽（64 / 128…），**点积的平均大小总是随维数膨胀**，`÷√d_k` 是给分数"统一降压"。
> 注意 `d_k` 是**每头的 64**，不是 768——因为膨胀来自"点积累加了多少项"，而每头只累加 64 项。

### 4.3 softmax 到底在干什么？为什么是 `dim=-1`？

它把一个"任意实数分数向量"变成"一份配额"，干了三件事：

1. **负数 → 正数**：`exp` 恒正，权重不会是负的（"负权重"没有意义）；
2. **归一化**：`Σ = 1`，于是天然是"各部分占比"，可以直接当加权平均系数用；
3. **软化的 argmax**：`exp` 放大差距（分数高一点，权重高不少），但**处处可导**——这让整个模块能塞进反向传播里被端到端训练。

**为什么必须是 `dim=-1`（按行）？**
因为第 i 行的语义是"第 i 个词把注意力分给全句"。配额是**按"发出查询的那一方"守恒**的：每个词有 100% 的注意力可分，不能多也不能少。所以必须在"被看方"那个维度（即 j，最后一维）上归一化。

### 4.4 为什么是 Q、K、V 三个，而不是一个？

因为**打分和取内容必须分工**：

- 打分用的是 Q×K 的匹配度（"你的问题合不合我的标签"）；
- 取内容用的是 V（"把正文端出来"）。

如果只有一摊向量既当标签又当正文，"查到的内容"就和"匹配依据"绑死了，模型没法独立学习"**我该看谁**"和"**看了之后拿什么**"这两件事。分成 `Wq / Wk / Wv` 三个可学习矩阵，三种角色各练各的。

### 4.5 为什么 12 个头？每头凭什么只拿 64 维？

- **算力账**：注意力的复杂度主要在 `Q·Kᵀ`，是 `N² × d`。
  - 单头 768 维：`N² × 768`
  - 12 头 × 64 维：`12 × (N² × 64) = N² × 768` —— **完全一样**。
  - 所以多头是"免费"的：同样的算力，换来 12 组独立的匹配规则。
- **分工账**：不同头倾向学会不同关系（有人盯指代、有人盯局部句法、有人盯语义相关），12 个头 = 12 种"从不同角度查资料"同时进行，最后拼起来。
- **窄反而是特性**：每头只有 64 维、容量小，逼着它只能专注学一种关系。要是给每头 768 维，12 个头很容易学成 12 个一模一样的"大而全"匹配器，多头就白设了。
- **不是数学定律**：唯一硬约束是 `d_model % num_heads == 0`（能整除才能均分）。BERT-base 选了 12 头，`768 / 12 = 64` 就自然成了每头维度。

## 五、从单头回到完整的一层（08 → 03 架构闭环）

手算只覆盖了"核心 64 维单头"，要回到 07 里的完整输出，还得补这四步：

```python
# ① 拼头：[B, h, N, 64] → [B, N, 768]
ctx = ctx.transpose(1, 2).contiguous().view(B, N, 768)

# ② 输出投影 W_o（HuggingFace: layer.attention.output.dense）
proj = layer.attention.output.dense(ctx)              # [B, N, 768] @ [768,768]ᵀ

# ③ 残差 + LayerNorm
attn_out = layer.attention.output.LayerNorm(proj + x)  # x 是本层输入

# ④ FFN（逐词独立：768→3072→GELU→768；eval 模式下 dropout 自动关闭）
ffn   = layer.output.dense(torch.nn.functional.gelu(layer.intermediate.dense(attn_out)))
out   = layer.output.LayerNorm(ffn + attn_out)         # 完整 BertLayer 的出口
```

> 这四步里的 **残差 + LayerNorm** 是本篇只点到为止的部分，完整讲解（为什么必须有残差、`LayerNorm` 公式手算、Post-LN vs Pre-LN）见 [09_bert_add_norm_residual.md](./09_bert_add_norm_residual.md)。

1. **拼头**：12 个头各自的 `[N, 64]` 沿最后一维拼成 `[N, 768]`。
2. **输出投影 `W_o`（`[768, 768]`，为什么必须有它）**：拼头只是"12 份结果首尾相接"，头与头之间**没有任何信息交流**——头 0 的输出永远待在第 0~63 通道。`W_o` 是全连接，让每个输出维度都能看到全部 12 个头的成果，做一次**跨头混合**。没有它，多头就退化成 12 个互不相干的模型。
3. **残差 + LayerNorm**：
   - **残差 `x + AttnOutput`** = 一条**保底通道**。就算这层注意力学废了（输出≈0），`x` 也能原样传下去，梯度也能顺着这条路直达浅层——这是 12 层深网络能训得动的关键。
   - **LayerNorm**：对每个词自己的 768 维做标准化（均值 0、方差 1，再学一个缩放平移），防止数值在 12 层里越传越飘。
4. **FFN**：`768 → 3072 → 768`，**逐词独立**（同一个 MLP 作用在每个位置上）。分工是：**注意力负责"信息路由"（谁看谁），FFN 负责"信息加工"（看到了之后怎么想）**。

### 5.1 padding mask：为什么必须是 `-10000`，且必须在 softmax 之前？

一个 batch 里句子长度不齐，短的被 `<PAD>` 补到 22。这些位置不是真词，不能参与"看与被看"：

```python
scores = scores.masked_fill(attention_mask == 0, -10000.0)   # softmax 之前！
attn   = scores.softmax(dim=-1)
```

原理：`e^(-10000) = 0`，softmax 之后这些位置的权重**严格 = 0**，既不掺内容，也不分走配额。

**为什么必须在 softmax 之前？** 因为 softmax 之后所有值都落在 (0,1) 且和为 1，你没法"减掉"某个位置——改一个就会破坏"行和为 1"。只有在**该行内部归一化之前**动手，才能让被屏蔽的位置自己变成 0，**同时把配额让给其他词**。

> 补充：GPT 这类自回归模型还有个 **causal mask**（屏蔽"未来"位置，词只能看自己左边，即下三角掩码），原理完全一样。BERT 是双向的，不需要。

> 对照 07：`attentions[0]` 的形状 `[1, 12, 22, 22]` = 第 0 层 12 个头各一张"行和为 1"的表，就是这里的 `attn_weights`。

## 六、常见误区（手算完最容易踩的 5 个坑）

1. **误区：`Q · Kᵀ` 就是注意力权重。**
   不是。那是**原始分（score）**；必须过 `softmax`、每行和为 1 之后才是"权重"。07 里 `attentions` 存的是 softmax 之后的版本。
2. **误区：Q = K = V，因为它们都来自同一个输入。**
   不是。"都来自同一个输入"叫**自**注意力；但它们各自乘了**不同的可学习矩阵** `Wq / Wk / Wv`，学成三个不同角色（问题 / 标签 / 正文）。绝不是一个矩阵复制三份。
3. **误区：每个头都在完整的 768 维上做注意力。**
   不是。每头只有 **64 维**（`768 ÷ 12`），各自在低维子空间工作，拼回去才看全 768。这也是"多头"和"一个大头"的本质差别。
4. **误区：手算完 64 维核心就以为一层只有注意力。**
   核心之外还有：拼头、`W_o` 输出投影、残差连接、LayerNorm、FFN。08 手算的是"最关键的引擎"，不是整台车。
5. **误区：切第 0 个头就是 `Wq[:, :64]`。**
   大错且**不报错**。`nn.Linear` 的 weight 是 `(out, in)`，**输出维是行**：应该 `Wq[:64, :]` 或 `Wq.T[:, :64]`。因为 BERT 恰好 `in == out == 768`，写反了形状也对、能跑通，但语义全错。详见 3.2。

## 七、速记卡

| 疑问 | 一句话答案 |
|---|---|
| `Q·Kᵀ` 为什么是打分 | 点积 = 相似度（同维正负累积和）；"什么算相似"由 `Wq/Wk` 学出来 |
| 为什么 `÷√d_k` | 点积方差随 `d_k` 膨胀（64 项 → 标准差 8），会把 softmax 推进饱和区、梯度归零；除完压回 ±1 |
| softmax 干什么 | 负数→正数、归一化成和为 1 的配额、可导的软 argmax；必须 `dim=-1` 按行 |
| `权重·V` 是什么 | 按配额的加权平均；one-hot = 复制，均匀 = 求平均，中间 = 软选择 |
| 为什么三个矩阵 | 分离"匹配依据(K)"与"取出内容(V)"，否则表达能力被锁死 |
| `(out,in)` 却用 `Wᵀ` | `(out,in)` 是存储约定；`X[N,in]` 要乘 `[in,out]` 才得 `[N,out]`，维度匹配逼出来的 |
| 头怎么切 | 按**输出维**顺序切 12 段，头 h 拿第 `[h*64, (h+1)*64)`；输入仍是完整 768 |
| 为什么 12 头 / 64 维 | 算力与单头相同（`12×64 = 768`），却换来 12 组匹配规则；窄 = 逼它们分工 |
| 为什么要 `W_o` | 拼头后 12 个头互不交流，`W_o` 做一次跨头混合 |
| mask 为什么在 softmax 前 | `e^-10000 = 0`；softmax 后再改会破坏"行和为 1" |

**公式一句话**：`权重 = softmax(Q·Kᵀ / √d_k)`，`新向量 = 权重 · V`
**三角色**：**Q = 我想找什么，K = 我能匹配什么，V = 我有什么**；score 高 = 我重点取你
**手算最小闭环**：`[N,768] → 单头 [N,64] → 分数 [N,N] → softmax → 混合 [N,64]`

## 八、自测（合上文档，先答再对）

1. 一句话向没学过的人解释：为什么"bank"在河岸句和劫匪句里最终是两个向量？
2. `attn_weights` 形状 `[22, 22]`，第 7 行第 10 列这个数代表什么？把这一行全加起来应该等于几？
3. 如果把 `d_k` 从 64 换到 128 而不除以 `√d_k`，softmax 前的分数会怎样？为什么？
4. `nn.Linear(768, 768)` 的 `weight.shape` 是什么？为什么前向要写成 `x @ W.T + b`？
5. 切第 0 个头，应该 `Wq[:64, :]` 还是 `Wq[:, :64]`？写反了会报错吗？
6. 为什么 padding mask 要在 softmax **之前**加，而不是之后？

<details>
<summary>参考答案</summary>

1. 每个词会向全句发"查询"并按相关度取信息；bank(河岸) 的重点取到了 river/fishing 的内容，bank(劫匪) 取到的是 robber/vault，混合后的向量自然分道扬镳。
2. 第 7 个词（查询方）分配给第 10 个词（被看方）的信息占比；行和 = 1（softmax 归一化过）。
3. 分数整体变大（量级约 `√128`），softmax 输入进入饱和区、梯度趋近 0，模型很难学。所以要么除 `√d_k`，要么换别的缩放手段。
4. `[768, 768]`，即 `(out_features, in_features)`。因为 `X` 是 `[N, in]`（每行一个样本），要得到 `[N, out]` 就必须乘一个 `[in, out]` 的矩阵，即 `Wᵀ`。
5. `Wq[:64, :]`（或等价的 `Wq.T[:, :64]`），因为 `(out, in)` 里输出维是**行**。**不会报错**——BERT 的 `in == out == 768` 让两种写法形状都是 `[768, 64]`，但结果语义全错，最危险。
6. softmax 之后所有值都在 (0,1) 且行和为 1，改任何一个都会破坏归一化；只有在行内归一化之前置 `-10000`，才能让被屏蔽位置自己变成 0 并把配额让给其他词。
</details>

## 九、费曼三连问（合上文档自测）

1. **一句话**：Self-Attention = 每个词先拿"问题 Q"去比全句的"标签 K"得到一张"我该看谁"的权重表，再按这张表去取各词的"正文 V"，混合成自己的新向量。
2. **手推**：任取两个 token 的向量 `x₁、x₂`，写出这 2 个词的单头 score 矩阵（`[2,2]`）每一格的代数式，并指出 softmax 在哪一维做、为什么。
3. **讲出去**：给一个只会"余弦相似度"的人解释，为什么 Q、K、V 要三个矩阵而不是直接拿原向量相似度做权重——重点说清"匹配依据"与"取出内容"为什么要分离。
