# 方向二：AI 论文精读

> 面向 AI 相关专业学生，深入讲解论文的核心 trick、方法设计和实验思路。

## 节目形式

```text
PPT + Manim 公式动画 + Motion Canvas 架构图
每期 20-35 分钟
```

## 风格要求

```text
不讲"这篇论文做了什么"
而是讲"这个领域之前卡在哪？大家试过什么办法都不行？这篇想到了什么关键 trick？"
实验部分不讲数据，而是讲"这个实验在验证什么假设"
每篇论文最后给一个"一句话 trick"和"三个延伸方向"
```

## 论文清单

### 一、大模型基础

#### 论文 1：Attention Is All You Need（Transformer 开山之作）

```text
年份：2017 | NeurIPS
一句话 trick：扔掉 RNN，只用 Self-Attention

为什么重要：
  它建立了所有现代大模型的骨架。
  GPT、BERT、Llama、Qwen……血脉里都流着这篇的基因。

讲解重点：
  1. RNN 两个致命问题：不能并行 + 长距离依赖衰减
  2. Self-Attention 如何解决：每个词直接看到所有词
  3. Multi-Head：多组 Q/K/V 同时看
  4. Positional Encoding：注意力不知道顺序，需要注入位置信息
  5. 残差连接：让 100 层网络也能训练

视觉素材：
  RNN 串行 vs Transformer 并行动画
  QK^T 矩阵 + softmax 热力图
  Encoder-Decoder 架构全景
```

#### 论文 2：Llama 3 技术报告

```text
年份：2024 | Meta
一句话 trick：开源大模型的工程标杆

为什么重要：
  详细披露训练数据配比、架构选择、安全对齐策略。
  是目前最完整的大模型工程实践参考。

讲解重点：
  1. 数据配比：多少代码、多少网页、多少书籍
  2. 架构选择：为什么选 Dense 而不是 MoE
  3. 训练稳定性：怎么防止训崩
  4. 安全对齐：怎么减少有害输出
  5. 评测结果：和 GPT-4、Claude 的对比

视觉素材：
  训练数据配比饼图
  不同规模模型的 Scaling 曲线
  安全评估雷达图
```

#### 论文 3：DeepSeek-V3 技术报告

```text
年份：2024 | DeepSeek
一句话 trick：MoE + Multi-head Latent Attention，极低成本训练

为什么重要：
  用极低的成本（约 550 万美元）训练出接近 GPT-4o 的模型。
  证明了"高效架构设计"比"堆算力"更重要。

讲解重点：
  1. MoE 架构：不是所有参数都参与每次计算
  2. Multi-head Latent Attention：压缩 KV Cache
  3. 负载均衡策略：防止某些专家过载
  4. 训练成本拆解
  5. 和 Llama 3 的对比

视觉素材：
  MoE 路由机制动画
  MLA vs 标准 Attention 的显存对比
  训练成本对比图
```

#### 论文 4：LoRA（参数高效微调）

```text
年份：2021 | ICLR 2022
一句话 trick：冻结原始权重，只训练两个小矩阵的乘积

为什么重要：
  让"在消费级显卡上微调大模型"成为可能。
  全量微调要几百 GB 显存，LoRA 只需要几 GB。

讲解重点：
  1. 直觉：不重写整本书，在旁边贴便利贴
  2. 数学：W' = W + B×A，B 和 A 是低秩矩阵
  3. rank 怎么选
  4. 哪些层加 LoRA 效果最好
  5. 全量微调 vs LoRA 的效果和显存对比

视觉素材：
  全量微调 vs LoRA 的矩阵运算对比
  rank 对效果的影响曲线
  显存占用对比柱状图
```

#### 论文 5：DPO（直接偏好优化）

```text
年份：2023 | NeurIPS 2023
一句话 trick：把 RLHF 的三步（Reward Model + PPO）压缩成一步

为什么重要：
  RLHF 训练复杂、不稳定。DPO 直接用偏好数据优化模型，
  不需要单独的 Reward Model 和强化学习。

讲解重点：
  1. RLHF 的问题：Reward Model 训练难、PPO 不稳定
  2. DPO 的核心公式：把偏好概率直接写成 loss
  3. 为什么 DPO 等价于隐式的 Reward Model
  4. DPO 的局限：数据分布变了可能失效
  5. 和 RLHF 的效果对比

视觉素材：
  RLHF 三步 vs DPO 一步的流程图对比
  DPO 公式推导动画
  效果对比柱状图
```

### 二、Agent

#### 论文 7：ReAct（思考 + 行动交替）

```text
年份：2022 | ICLR 2023
一句话 trick：让模型边想边做，而不是想好了再做

为什么重要：
  它是几乎所有 Agent 系统的核心范式。
  思维链（CoT）只思考，ReAct 把思考和行动交替进行。

讲解重点：
  1. CoT 的局限：只能想，不能做
  2. Act-only 的局限：只能做，不会反思
  3. ReAct 循环：Thought → Action → Observation → Thought
  4. 一个完整例子推演
  5. 为什么交替比先想再做更好

视觉素材：
  CoT vs Act-only vs ReAct 的对比动画
  完整任务推演流程图
```

### 四、多模态检索

#### 论文 15：CLIP

```text
年份：2021 | OpenAI
一句话 trick：用 4 亿图文对训练，让文本和图片进入同一个向量空间

为什么重要：
  它是图文检索的基础，所有"文本搜图片"系统的底层。

讲解重点：
  1. 对比学习：正确图文对拉近，错误图文对推远
  2. 为什么 4 亿对噪声数据比精心标注的数据更有效
  3. zero-shot 分类：不用训练就能分类
  4. CLIP 的局限：细粒度属性、抽象概念

视觉素材：
  对比学习示意图
  zero-shot 分类流程
  CLIP 向量空间可视化
```

#### 论文 16：ColPali

```text
年份：2024
一句话 trick：用视觉语言模型直接理解 PDF 页面，不再需要 OCR + 文本化

为什么重要：
  很多企业知识不是纯文本，而是 PDF、扫描件、图表混排文档。
  ColPali 直接从页面图像生成检索向量。

讲解重点：
  1. 传统文档检索的 OCR + 文本化流程的局限
  2. ColPali 的视觉直接检索
  3. Late Interaction：不压缩成单个向量
  4. ViDoRe 基准

视觉素材：
  传统流程 vs ColPali 流程对比
  Late Interaction 机制动画
```

### 六、推理优化

#### 论文 20：FlashAttention

```text
年份：2022 | Stanford
一句话 trick：不是改 Attention 公式，而是改变计算顺序，减少 GPU 显存读写

为什么重要：
  几乎所有大模型训练和推理都在用 FlashAttention。
  它让长序列处理从"不可能"变成"可能"。

讲解重点：
  1. Attention 的显存瓶颈：O(n²) 中间矩阵
  2. GPU 显存层级：HBM vs SRAM
  3. 核心 trick：把大矩阵切成小块，在 SRAM 里算完再写回
  4. Tiling + Recomputation
  5. FlashAttention-2 的改进

视觉素材：
  GPU 显存层级图
  分块计算动画
  标准 Attention vs FlashAttention 的显存对比
```

#### 论文 21：vLLM / PagedAttention

```text
年份：2023 | UC Berkeley
一句话 trick：像操作系统管理内存一样管理 KV Cache，消除碎片

为什么重要：
  KV Cache 是推理时最大的显存占用，vLLM 的 PagedAttention
  让显存利用率从 20-40% 提升到接近 100%。

讲解重点：
  1. KV Cache 的碎片问题
  2. PagedAttention：把 KV Cache 切成固定大小的 block
  3. 类比：操作系统虚拟内存的分页机制
  4. 吞吐量对比
  5. 和你的 SFT 模型部署的关系

视觉素材：
  内存碎片 vs 分页管理的对比动画
  吞吐量对比柱状图
```

## 每期通用结构

```text
0-3 分钟：Hook —— 一个极端例子展示"不解决这个问题会有多惨"
3-6 分钟：背景 —— 之前的方法为什么不行（配失败原因动画）
6-15 分钟：核心方法 —— "一句话 trick" + 公式推导 + 直觉解释
15-22 分钟：实验 —— "这个实验在验证什么"（不是念数据）
22-26 分钟：影响 —— 后续哪些论文基于这个思路
26-28 分钟：局限 —— 这篇论文没解决的问题
28-32 分钟：在你的项目里怎么用 —— 结合 UE5 测试项目
32-35 分钟：总结卡片 + 延伸阅读
```
