# 03. 知识图谱构建 Pipeline

> 目标：理解知识图谱如何从文本、表格、数据库和文档中被构建出来。

## 1. 知识图谱从哪里来？

知识图谱的数据来源通常包括：

```text
结构化数据：数据库表、CSV、Excel
半结构化数据：HTML、JSON、XML、百科 infobox
非结构化数据：文本、PDF、网页、新闻、论文、报告
多模态数据：图片 OCR、视频 ASR、图表解析
人工知识：专家规则、领域词表、标注数据
```

不同数据源的构建难度不同：

```text
数据库/表格 → 图谱：相对容易，字段映射即可
网页/百科 → 图谱：中等，需要解析模板和链接
自然语言文本 → 图谱：最难，需要信息抽取
```

## 2. 总体构建流程

```text
原始数据
  ↓
数据清洗与解析
  ↓
实体识别 NER
  ↓
关系抽取 RE
  ↓
属性抽取
  ↓
事件抽取
  ↓
实体消歧与对齐
  ↓
知识融合
  ↓
质量评估
  ↓
写入图数据库
```

## 3. 从结构化数据构建图谱

例如有一张药品表：

```text
Drug(id, name, indication, side_effect, manufacturer)
```

可以映射成：

```text
(:Drug {id, name})
(:Disease {name: indication})
(:SideEffect {name: side_effect})
(:Company {name: manufacturer})

(:Drug)-[:TREATS]->(:Disease)
(:Drug)-[:HAS_SIDE_EFFECT]->(:SideEffect)
(:Drug)-[:PRODUCED_BY]->(:Company)
```

这种方法叫 RDB2Graph 或表结构映射。

关键是设计映射规则：

```text
哪些表变成实体
哪些字段变成属性
哪些外键变成关系
哪些枚举字段变成概念节点
```

## 4. 实体识别 NER

NER = Named Entity Recognition，命名实体识别。

任务：从文本中识别实体 mention。

```text
输入：
  阿司匹林可用于缓解发热和疼痛。

输出：
  阿司匹林 → Drug
  发热 → Symptom
  疼痛 → Symptom
```

常见方法：

```text
词典匹配
规则模板
CRF / BiLSTM-CRF
BERT / RoBERTa / DeBERTa
LLM 抽取
```

## 5. 关系抽取 RE

关系抽取负责判断实体之间的关系。

```text
输入：
  阿司匹林可用于缓解发热。

实体：
  阿司匹林、发热

输出：
  (阿司匹林)-[TREATS]->(发热)
```

关系抽取方法：

```text
规则模板：X 可用于治疗 Y
监督学习：给定实体对，分类关系类型
联合抽取：同时抽实体和关系
远程监督：用已有图谱自动生成训练样本
LLM 抽取：用 prompt 或结构化输出抽关系
```

## 6. 属性抽取

属性抽取是从文本中抽实体的属性。

```text
文本：
  布洛芬常见剂量为每次 200mg。

输出：
  (:Drug {name:'布洛芬', common_dose:'200mg'})
```

常见属性：

```text
出生日期
剂量
价格
面积
成立时间
风险等级
置信度
```

## 7. 事件抽取

事件比关系更复杂。

关系通常是：

```text
A -[关系]-> B
```

事件包含：

```text
事件类型
触发词
参与者
时间
地点
结果
```

例如：

```text
2024 年，A 公司收购 B 公司。
```

抽取：

```text
事件类型：Acquisition
触发词：收购
收购方：A 公司
被收购方：B 公司
时间：2024 年
```

图谱表示：

```text
(:AcquisitionEvent {time:'2024'})
(:Company {name:'A'})-[:ACQUIRER]->(:AcquisitionEvent)
(:Company {name:'B'})-[:ACQUIRED_TARGET]->(:AcquisitionEvent)
```

## 8. 实体消歧 Entity Disambiguation

同一个名字可能指不同实体。

```text
苹果：水果
苹果：公司
乔丹：篮球运动员
乔丹：国家 Jordan
```

实体消歧要根据上下文判断具体指谁。

```text
“苹果发布了新手机” → 公司
“苹果含有丰富维生素” → 水果
```

常用信号：

```text
上下文文本
实体类型
别名词典
共现实体
链接关系
向量相似度
```

## 9. 实体对齐 Entity Alignment

实体对齐是判断不同来源里的实体是否是同一个。

```text
北京大学
北大
Peking University
PKU
```

它们应该对齐到同一个实体 ID。

常用方法：

```text
规则：标准化名称、别名表
字符串相似度：编辑距离、Jaccard
属性相似度：地址、时间、编号
关系上下文：邻居是否相似
Embedding：实体表示相似
人工审核：高风险实体需要人工确认
```

## 10. 知识融合

知识融合负责把多个来源的知识合并。

问题包括：

```text
重复实体
冲突属性
关系冲突
来源可信度不同
时间版本不同
```

例如：

```text
来源 A：某公司成立时间 = 2010
来源 B：某公司成立时间 = 2011
```

需要根据：

```text
来源权威性
更新时间
证据数量
业务规则
人工审核
```

确定最终结果。

## 11. LLM 在知识图谱构建中的作用

LLM 可以辅助：

```text
Schema 设计建议
实体和关系抽取
属性抽取
事件抽取
实体消歧
自然语言到 Cypher/SPARQL
图谱质量检查
```

但不能完全无脑依赖 LLM。

需要控制：

```text
结构化输出格式
置信度
证据引用
去幻觉
人工抽检
规则校验
```

推荐做法：

```text
LLM 负责候选抽取
规则/模型/人工负责校验
图数据库负责持久化和约束
```

## 12. 构建质量评估

常见指标：

```text
实体识别 Precision / Recall / F1
关系抽取 Precision / Recall / F1
实体对齐准确率
重复率
冲突率
覆盖率
图连通性
孤立节点比例
人工抽检通过率
```

## 13. 一句话总结

> 知识图谱构建是从原始数据到结构化知识网络的过程，核心步骤包括实体识别、关系抽取、属性抽取、事件抽取、实体对齐、知识融合与质量评估。LLM 可以显著降低抽取门槛，但高质量图谱仍然需要 Schema 约束、规则校验、来源治理和人工抽检。
