# 03. 工具系统设计

> 目标：理解工具系统的四大目标、渐进式发现、增强描述、上下文感知、智能反馈和结果裁剪。

## 1. 工具系统的四大目标

```text
可调用性 ── 可靠性
    \        /
     安全性
    /        \
可扩展性 ── 性能
```

| 目标 | 含义 |
|---|---|
| 可调用性 | LLM 能准确理解工具用途，参数格式清晰无歧义 |
| 可靠性 | 高执行成功率，低重试率，完善的错误处理 |
| 安全性 | 沙箱约束，权限控制，审计追踪 |
| 可扩展性 | 支持工具生态扩展，外部工具集成，Skill 编排 |

## 2. 核心挑战

### 挑战 1：LLM 理解偏差

```text
现象：参数格式错误、路径引用错误、工具选择不准确
根因：工具描述不够清晰、缺少具体示例、参数说明存在歧义
影响：执行失败率高、需要多次重试
```

### 挑战 2：上下文与工具脱节

```text
现象：不清楚项目文件结构、不了解当前工作状态
根因：环境信息未充分提供、工具缺少上下文感知
影响：路径错误、文件冲突
```

### 挑战 3：错误反馈不足

```text
现象：仅返回简单错误信息，不清楚如何修复
根因：错误消息太简单、缺少修复建议
影响：重试率高、任务容易失败
```

### 挑战 4：工具列表过载

```text
现象：大量工具（可能上百个），详细描述占用大量 Token
根因：全量加载所有工具，每个都提供完整描述
影响：上下文浪费、工具选择错误率上升、成本增加
```

### 挑战 5：工具结果过载

```text
现象：终端输出数千行，超出上下文窗口
根因：未对结果进行裁剪，全量返回
影响：关键信息被截断、上下文污染
```

## 3. 渐进式发现

核心思想：区分固定工具和动态工具，对动态工具按需加载。

### 三层架构

```text
第一层：工具摘要（Token 极低）
  只显示工具的分类和数量
  例如："3 个外部服务：GitHub [12 tools]、数据库 [8 tools]..."

第二层：工具列表（按需获取）
  当 LLM 决定使用某个服务时，才加载该服务的工具详情
  例如：加载 GitHub 服务的 12 个工具描述

第三层：实际调用
  通过 Function Calling 执行具体工具
```

### 效果对比

```text
全量加载：系统工具 + 30 个外部工具 + 8 个 Skill
  → 约 12,000 Token

分层设计：系统工具（完整）+ 外部摘要 + Skill 摘要
  → 约 2,300 Token

初始节省：约 80%
```

## 4. 增强型工具描述

核心原则：**描述清晰度 = 成功率**。

### 对比

```text
❌ 简单描述：
  write_to_file: Write content to file
  path: file path
  content: file content

✓ 增强描述：
  用途说明：一句话概述 + 详细功能说明 + 适用场景
  参数详解：名称、类型、是否必需、取值范围、默认值、具体示例
  使用示例：典型用法、边界情况、常见错误
  注意事项：副作用、前置条件、限制约束
  安全约束：权限要求、审计信息
```

## 5. 上下文感知工具

让工具执行时拥有充分的环境信息：

```text
环境信息注入：
  项目根目录
  当前工作目录
  项目文件结构
  Git 状态
  依赖信息
```

效果：路径错误率大幅降低，首次成功率显著提升。

## 6. 智能错误反馈

错误时不只说"失败了"，还要说"为什么"和"怎么办"。

### 四层反馈

```text
Level 1：错误事实（What）
  工具名称、失败状态、基本错误信息

Level 2：详细分析（Why）
  尝试的具体操作、问题诊断、可能原因

Level 3：修复建议（How）
  具体的修复步骤、替代方案、示例代码

Level 4：辅助信息（Context）
  相关环境信息、类似成功案例
```

## 7. 结果智能裁剪

保留关键信息，省略冗余细节。

### 裁剪规则

```text
1. 保留开头 N 行（捕获初始输出和警告）
2. 保留结尾 N 行（捕获最终结果和状态）
3. 中间显示截断信息（明确告知省略了多少内容）
4. 错误信息优先保留（即使在中间部分）
5. 成功标志必须保留
6. 统计信息保留
```

## 8. 工具设计的黄金法则

```text
法则 1：描述清晰度 = 成功率
  详细说明 + 具体示例 > 简短描述

法则 2：分层设计 = 效率
  固定工具完整 + 动态工具渐进

法则 3：上下文完整度 = 准确性
  环境信息 + 项目状态 > 孤立工具

法则 4：反馈质量 = 恢复能力
  原因分析 + 修复建议 > 简单报错

法则 5：结果裁剪 = 下一步质量
  智能保留 > 全量返回 > 简单截断
```

## 9. 一句话总结

> 工具系统的核心是让 LLM "准确理解、成功执行、失败恢复"。渐进式发现解决 Token 浪费，增强描述提升首次成功率，上下文感知减少路径错误，四层反馈让失败可恢复，结果裁剪防止上下文污染。
