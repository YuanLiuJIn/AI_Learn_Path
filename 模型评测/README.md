## 四大模态评测的共通方法论（跨方向主线）

无论哪种模态，评测体系的构建都遵循同一套骨架，这是评测岗的核心能力：

1. **能力维度拆解** —— 把"模型好不好"拆成可测量的正交维度（VBench 的 16 维、MMBench 的层次化分类是范本）
2. **评测集构建** —— 数据来源、难度分布、标注规范（Rubric）、标注员一致性（κ / α）
3. **指标定义** —— 客观可判定指标优先；开放式任务转化为判别式问题（GenEval 用检测器、VQAScore 用 VQA、TTS 用 ASR 算 WER，都是同一思路）
4. **自动指标与人类对齐** —— 用 Spearman / Kendall τ 验证自动指标与人评的相关性（EvalCrafter、HEIM、UTMOS 的核心工作）
5. **偏差与污染治理** —— 位置偏差、长度偏差、视觉冗余、数据污染、Goodhart 定律
6. **工程化落地** —— 自动化 Pipeline、结果可复现（seed/模板/解码参数固定）、嵌入训练迭代闭环

## 建议学习顺序（评测岗渐进路线）

> 整体遵循「**方法论 → 基准刻度 → 工程工具 → 实战产出**」四段式，论文阅读与笔记阅读交叉进行。论文主线详见 `核心论文阅读路线.md`。

**阶段 0 · 定位（0.5 天）**
1. 读 `岗位JD调研_大厂模型评测.md`，明确目标岗位分层与能力要求。

**阶段 1 · 方法论底座（1 周）**
2. 打通 `Model_Evaluation/` 通用方法论（评测概览、Benchmark 全景、污染与可靠性、LLM-as-Judge、框架、Agent 评测）。
3. 读 `核心论文阅读路线.md` 主线 A：综述与方法论（2303.18223 → 2307.03109 的 3W 框架 → 2211.09110 HELM → 2411.15594 LLM-as-Judge），建立「评什么/在哪评/怎么评」的元框架。

**阶段 2 · 能力刻度与基准（2 周，按主攻方向选读）**
4. 读 `核心论文阅读路线.md` 主线 B：基准与数据集——推理（MMLU）、代码/Agent（HumanEval / SWE-bench）、中文对齐（AlignBench）、人类偏好（Chatbot Arena）。
5. 对照 `08_常见评测数据集与方法.md` 与四个模态笔记，把每个基准落到「维度 + 指标 + 判分」三件套。

**阶段 3 · 工程化与体系建设（2 周）**
6. 系统补齐 `核心能力图谱/` 的 9 章（原理→指标→数据集→体系→工程→训练→**实践进阶**），这是评测岗能力底座。
7. 读 `核心论文阅读路线.md` 主线 C：专项工具——TrustLLM（可信度 6 维）、AgentBench（Agent 评测）、OpenCompass 2.0（100+ 数据集框架）；配套 `03_自动化评测工具开发.md` 做工程落地。

**阶段 4 · 实战与产出（持续）**
8. 按目标岗位深挖对应模态目录（主攻 1-2 个深入，其余了解）。
9. 完成各方向 README 末尾「动手任务」，产出可写进简历的项目（参考 `简历项目写法.md`）；用 `核心论文阅读路线.md` 的「分场景阅读建议」查漏补缺。

**分场景速查**：学术调研 → A→B推理→A4；企业选型 → C3→B4→A4；自动评测/判别模型 → A4→C3→B4；Agent 评测 → C2→B2→C1；中文对齐 → B3→`08章`中文集→A2。
