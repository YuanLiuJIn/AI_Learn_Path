# 01. 知识图谱概述

> 目标：理解知识图谱是什么，它解决什么问题，以及它和数据库、搜索引擎、向量库的区别。

## 1. 从一个直觉例子开始

假设有三句话：

```text
姚明出生于上海。
姚明曾效力于休斯顿火箭队。
休斯顿火箭队属于 NBA。
```

人读完后能理解：

```text
姚明 → 出生地 → 上海
姚明 → 效力球队 → 休斯顿火箭队
休斯顿火箭队 → 所属联盟 → NBA
```

知识图谱做的事情，就是把自然语言里的知识变成这种结构化的图：

```text
(姚明)-[出生地]->(上海)
(姚明)-[效力球队]->(休斯顿火箭队)
(休斯顿火箭队)-[所属联盟]->(NBA)
```

## 2. 知识图谱是什么？

一句话：

> 知识图谱是用“实体—关系—实体”或“实体—属性—值”的形式组织知识的图结构。

最基本单元叫三元组：

```text
(subject, predicate, object)
主语       谓词       宾语
```

例如：

```text
(姚明, 出生地, 上海)
(巴黎, 所属国家, 法国)
(青霉素, 治疗, 细菌感染)
```

图里：

```text
节点 = 实体 / 概念 / 值
边 = 关系
属性 = 节点或边上的补充信息
```

## 3. 知识图谱解决什么问题？

### 3.1 解决知识分散问题

原始知识散落在：

```text
文档
网页
表格
数据库
PDF
日志
人工经验
```

知识图谱把它们统一成结构化关系网络。

### 3.2 解决关系查询问题

普通搜索擅长找文档，但不擅长回答关系问题。

例如：

```text
“某药物可能影响哪些疾病的治疗？”
“某家公司间接控制了哪些公司？”
“某篇论文的核心方法被哪些后续论文继承？”
```

这些问题依赖路径和关系，不只是关键词匹配。

### 3.3 解决可解释推理问题

知识图谱可以给出路径证据：

```text
A 公司 → 投资 → B 公司 → 控制 → C 公司
所以 A 公司可能间接影响 C 公司。
```

这比纯向量相似度更可解释。

## 4. 知识图谱和关系数据库的区别

关系数据库以表为中心：

```text
Person(id, name, age)
Company(id, name)
Employment(person_id, company_id, role)
```

知识图谱以关系网络为中心：

```text
(张三)-[任职于 {职位: 算法工程师}]->(某公司)
(某公司)-[位于]->(北京)
```

对比：

| 维度 | 关系数据库 | 知识图谱 |
|---|---|---|
| 数据模型 | 表 | 图 |
| 关注点 | 行、列、事务 | 实体、关系、路径 |
| 查询优势 | 聚合、事务、结构固定 | 多跳关系、关联发现、语义查询 |
| Schema | 通常强约束 | 可强可弱，更灵活 |
| 典型问题 | 统计报表、业务交易 | 问答、推荐、风控、关系推理 |

## 5. 知识图谱和向量数据库的区别

向量数据库擅长相似度：

```text
“这段话和哪些文档语义相似？”
“这张图片和哪些图片相似？”
```

知识图谱擅长关系结构：

```text
“A 和 B 之间通过哪些路径相连？”
“哪些实体满足这组关系约束？”
“某个概念的上位概念和下位概念是什么？”
```

对比：

| 维度 | 向量数据库 | 知识图谱 |
|---|---|---|
| 核心表示 | 向量 | 图结构 |
| 擅长 | 语义相似度 | 关系、路径、推理 |
| 可解释性 | 较弱 | 较强 |
| 查询方式 | Top-K 相似检索 | 图查询、多跳路径、规则推理 |
| 典型应用 | RAG 召回、推荐、相似搜索 | 知识问答、实体关系分析、GraphRAG |

最好的系统往往二者结合：

```text
向量检索负责“找到相关内容”
知识图谱负责“解释关系和组织结构”
```

## 6. 知识图谱的三类典型应用

### 6.1 知识问答

用户问：

```text
“阿司匹林不能和哪些药物同时服用？”
```

系统可以查：

```text
(阿司匹林)-[相互作用]->(药物X)
(药物X)-[风险]->(出血风险增加)
```

输出带证据的回答。

### 6.2 推荐系统

例如电影推荐：

```text
用户喜欢电影 A
电影 A → 导演 → 导演 X
导演 X → 导演 → 电影 B
电影 A → 类型 → 科幻
电影 C → 类型 → 科幻
```

可以根据路径解释推荐理由。

### 6.3 风险分析

例如企业关系分析：

```text
公司 A → 投资 → 公司 B
公司 B → 法定代表人 → 张三
张三 → 同时任职 → 公司 C
公司 C → 涉及风险事件 → 事件 E
```

知识图谱可以发现间接风险链路。

## 7. 知识图谱的技术栈

```text
知识建模：本体、Schema、实体类型、关系类型
知识抽取：NER、关系抽取、事件抽取、属性抽取
知识融合：实体对齐、消歧、冲突解决
图存储：RDF Store、属性图数据库
图查询：SPARQL、Cypher、Gremlin
图推理：规则、本体、路径、约束
图学习：TransE、RotatE、R-GCN、GNN
应用层：问答、推荐、搜索、GraphRAG、Agent
```

## 8. 一句话总结

> 知识图谱是一种把知识组织成实体关系网络的技术。它不只是存储数据，更重要的是表达关系、支持多跳查询、提供可解释推理，并与向量检索和大模型结合，成为知识问答、GraphRAG、推荐和复杂关系分析的重要基础。
