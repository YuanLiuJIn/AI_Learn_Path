# 06. 环境与评测

> 目标：理解 Agent RL 的训练环境需求和主流评测基准。

## 1. 环境的重要性

```text
Agent RL 的核心是"在环境中试错"

环境决定了：
  模型能学到什么
  奖励信号从哪来
  训练的难度和成本
  评测的真实性
```

## 2. 环境类型

### 代码环境

```text
代表：SWE-bench

任务：给定一个 GitHub Issue，让 Agent 修 Bug

环境：
  代码仓库
  命令行工具（编译、测试、Git）
  文件系统

奖励：
  所有测试通过 → 成功
  部分通过 → 部分成功
  编译失败 → 失败
```

### Web 环境

```text
代表：WebArena

任务：在真实网站上完成任务
  搜索信息、填写表单、购物等

环境：
  真实网站（Amazon、Wikipedia、GitHub 等）
  浏览器自动化

挑战：
  网站可能变化
  网络延迟
  反爬机制
```

### OS 环境

```text
代表：OSWorld

任务：在操作系统上完成任务
  打开应用、编辑文件、发送邮件等

环境：
  真实或虚拟操作系统
  鼠标键盘操作
  文件系统

挑战：
  操作空间大
  状态难观测
  动作粒度选择
```

### 数据库环境

```text
代表：Spider、BIRD

任务：自然语言转 SQL，查询数据库

环境：
  关系型数据库
  SQL 执行引擎

奖励：
  查询结果正确 → 成功
```

## 3. 环境的核心需求

```text
1. 高并发
   一次 RL 训练需要同时跑数百个环境实例
   每个实例独立，互不干扰

2. 高可靠
   环境不能频繁崩溃
   崩溃时不能影响训练

3. 可重置
   每个 episode 结束后环境要能快速重置
   保证每次训练的初始条件一致

4. 沙箱隔离
   环境操作不能影响真实系统
   代码执行要在沙箱中
   文件操作要在隔离目录
```

## 4. 主流评测基准

### SWE-bench

```text
任务：修 GitHub Issue
规模：2294 个真实 Issue
指标：Resolved Rate（问题解决率）
当前 SOTA：~50%
```

### WebArena

```text
任务：真实网站交互
网站：Amazon、Wikipedia、GitLab、Reddit 等
指标：任务成功率
```

### AgentBench

```text
任务：8 种环境的多维 Agent 评测
  操作系统、数据库、知识图谱、游戏等
指标：各环境单独评测
```

### GAIA

```text
任务：需要多步推理和工具使用的问答
特点：问题设计为对人类简单、对 AI 困难
指标：准确率
```

## 5. 环境工程的关键挑战

### 沙箱管理

```text
需要：
  数百个并发沙箱
  每个沙箱独立文件系统
  命令执行隔离
  超时控制
  资源限制

常用方案：
  Docker 容器
  Kubernetes 编排
  自定义沙箱服务
```

### 环境失败处理

```text
环境失败 ≠ 模型失败

需要区分：
  环境崩溃 → 重试，不计入模型表现
  模型错误 → 记录为失败轨迹
  超时 → 需要判断是模型慢还是环境慢
```

## 6. 一句话总结

> Agent RL 的环境需求远比单轮 RL 复杂。需要高并发沙箱、代码/Web/OS 等多种环境、以及能区分"环境失败"和"模型失败"的工程能力。评测上，SWE-bench、WebArena、AgentBench 是当前主流的 Agent 评测基准。
