# 01. 多模态检索概述

> 目标：理解多模态检索是什么，它和传统搜索、文本 RAG、向量数据库有什么区别。

## 1. 从传统搜索说起

传统搜索主要处理文本：

```text
输入：关键词
例如：“Transformer 注意力机制”
输出：包含这些词或语义相关的网页/文档
```

但真实世界的数据远不止文本：

```text
文档、PDF、网页、代码、日志
图片、截图、设计稿、医学影像
音频、会议录音、客服通话
视频、课程录像、短视频、监控片段
表格、结构化数据库
点云、传感器数据
```

多模态检索要解决的问题是：

> 不管数据原本是什么形态，都能被统一理解、统一索引、统一检索。

## 2. 什么是多模态检索？

一句话：

> 多模态检索 = 支持跨文本、图片、音频、视频等多种模态的语义检索系统。

它可以支持这些查询方式：

```text
文本搜文本：     “什么是 RAG？” → 找相关文章
文本搜图片：     “一只猫坐在沙发上” → 找相关图片
文本搜视频：     “讲 Transformer 的片段” → 找视频时间段
图片搜图片：     上传一张商品图 → 找相似商品图
图片搜文本：     上传一张架构图 → 找相关技术文档
音频搜文本：     上传一段语音 → 找对应会议纪要
文本搜表格：     “Q2 销售额最高的区域” → 找相关表格或数据记录
```

## 3. 多模态检索的核心思想

核心思想是把不同模态映射到统一表示空间。

```text
文本：“海边落日”
      ↓ Text Encoder
向量：[0.13, -0.27, ...]

图片：海边落日照片
      ↓ Image Encoder
向量：[0.12, -0.25, ...]

如果两个向量距离很近，系统就认为它们语义相似。
```

这背后依赖的是多模态表示学习，比如 CLIP、ALIGN、BLIP、ImageBind 等。

## 4. 多模态检索和普通向量检索的区别

普通向量检索通常只关心：

```text
文本 → Embedding → 向量库 → Top-K
```

多模态检索更复杂：

```text
多模态原始数据
  ↓
清洗 / 解码 / 切分 / OCR / ASR / Caption / 脱敏
  ↓
不同模态的 Embedding
  ↓
全文索引 + 稀疏向量索引 + 稠密向量索引 + 元数据索引
  ↓
混合召回 + 融合排序 + Rerank
  ↓
返回文本、图片、视频片段、表格、结构化结果
```

也就是说，多模态检索不是一个单点算法，而是一条工程链路。

## 5. 为什么不能只用关键词检索？

关键词检索擅长精确匹配，但不懂语义。

例如用户搜：

```text
“怎么提升模型推理速度”
```

关键词检索可能漏掉：

```text
“降低 LLM inference latency”
“提高吞吐量的模型服务优化”
“推理加速实践”
```

因为字面词不一样。

语义向量检索可以把这些表达放到相近位置。

## 6. 为什么不能只用向量检索？

纯向量检索也有问题。

例如用户搜：

```text
“错误码 50013”
```

这时候用户需要精确匹配 `50013`，而不是语义相似的错误码。

纯向量可能召回：

```text
错误码 50014
错误码 40013
错误码 50103
```

所以工业系统通常使用混合检索：

```text
最终结果 = 关键词召回 + 稀疏向量召回 + 稠密向量召回 + Rerank
```

## 7. 多模态检索的典型架构

```text
┌──────────────────────────────────────┐
│            多模态原始数据             │
│ 文本 / 图片 / 视频 / 音频 / 表格 / 点云 │
└──────────────────────────────────────┘
                ↓
┌──────────────────────────────────────┐
│             数据处理层                │
│ 清洗、去重、脱敏、OCR、ASR、Caption、切分 │
└──────────────────────────────────────┘
                ↓
┌──────────────────────────────────────┐
│             表示与索引层              │
│ Dense Embedding / Sparse / BM25 / 元数据 │
└──────────────────────────────────────┘
                ↓
┌──────────────────────────────────────┐
│             检索与排序层              │
│ Hybrid Search / Rerank / CBO / 权限过滤 │
└──────────────────────────────────────┘
                ↓
┌──────────────────────────────────────┐
│              应用层                   │
│ RAG / Agent / 智能搜索 / 推荐 / 内容理解 │
└──────────────────────────────────────┘
```

## 8. 多模态检索的价值

### 8.1 支撑多模态 RAG

传统 RAG 只查文本：

```text
用户问题 → 检索文本 chunk → LLM 回答
```

多模态 RAG 可以查：

```text
文本、图片、图表、视频片段、音频转写、截图、表格
```

### 8.2 支撑 Agent 记忆和工具调用

Agent 可以把多模态检索当工具：

```text
Agent：我需要查历史截图和文档
  ↓
调用多模态检索
  ↓
拿到相关截图、说明文档、历史工单
  ↓
继续推理和执行
```

### 8.3 支撑智能搜索和推荐

用户可以自然语言搜索，也可以上传图片或视频片段搜索相似内容。

## 9. 一句话总结

> 多模态检索的本质，是把不同形态的数据统一表示、统一索引、统一召回，并通过混合检索与重排，把最相关的文本、图片、视频、音频或结构化信息返回给上层 AI 应用。
