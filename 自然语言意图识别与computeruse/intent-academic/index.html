模糊语境修正
与不确定性追问

面向 Computer Use 的意图理解、结构化决策与数据飞轮

刘晋元学术汇报 · Natural Language × Computer Use
#intent #clarification #computer-use

大家好，我是刘晋元。今天汇报的主题是模糊语境修正与不确定性追问，以及它如何与 Computer Use 结合。我们关注的不是让模型更快地点击按钮，而是先让它理解用户真正想完成什么。

整项工作分成两个部分。第一部分训练 Qwen 系列模型，让它识别模糊语境、判断是否需要追问，并输出固定格式的任务描述。第二部分把这个结构化结果交给 Computer Use 智能体，在特定网站上完成执行，再把失败和修正数据回流，形成一个可迭代的数据飞轮。

今天会先介绍整体方案，再回顾两条相关研究线，最后落到我们准备解决的研究空白。

01 · research question

用户说得不完整时，
模型应该先问还是先做？

模糊语境

指代不清、约束缺失、多个任务目标同时存在。

不确定性

模型无法可靠判断唯一意图，直接执行可能造成错误操作。

执行风险

Computer Use 的错误不是一句话错，而可能留下真实的状态副作用。

核心目标：把“澄清”建模为一个可学习的决策，而不是固定触发的问句模板。

这一页先把问题说清楚。现实用户的指令经常是不完整的，比如“把这个发给他”“帮我处理一下”“订一个合适的”。语言模型如果只追求立即行动，就会把自己的猜测当成用户意图。

在纯文本对话里，答错一次可能只是回复不准确；但在 Computer Use 场景里，错误会变成点击、提交、删除或发送，代价明显更高。所以问题不是“模型能不能生成一个澄清问题”，而是它能不能识别什么时候值得停下来问。

我们的研究目标因此可以概括为一句话：让澄清成为一个决策。模型需要同时考虑意图分歧、追问成本、执行风险和当前上下文，最后选择澄清、直接执行或安全拒绝。

02 · system overview

两部分模型，一条理解—执行—反馈闭环

Part 1 · Understand

训练 Qwen（8B / 9B / 27B）识别模糊语境、判断不确定性、生成澄清，并输出固定格式：

{ intent, confidence, clarify, action }

Part 2 · Act

接收结构化 output，在特定网站执行 Computer Use；探索 DPO、OPD、GRPO，学习动作选择与异常恢复。

observe → act → verify → recover
↺
数据飞轮

理解偏差、追问结果、执行失败与用户修正，统一沉淀为下一轮训练样本。

这页是整项工作的架构图。Part 1 负责把自然语言转换成更稳定的中间表示。这个表示不只是一个意图标签，还要包含置信度、是否追问、追问内容和最终动作计划。

Part 2 负责真正执行。它观察网页状态、选择动作、验证结果，遇到异常时尝试恢复。这样两个部分之间有一个清晰的接口：Part 1 输出固定格式，Part 2 消费这个格式。

最关键的是数据飞轮。每次运行都会产生新的信息：用户补充了什么、哪一次追问是多余的、哪个动作导致失败、错误后是否能恢复。这些都可以重新整理成训练数据，同时改进理解模型和执行模型。

03 · part 1 / related work

已有工作覆盖了澄清的不同切面

01
CLAIM · arXiv:2608.11631

用多模型答案分歧的熵量化查询不确定性，自动合成数据，以 SFT + GRPO 训练结构化澄清决策模型。

02
AmbiK · ACL 2025

构建歧义指令、澄清问答、意图与任务规划数据集，连接语言歧义和下游任务。

03
AT-CoT · SIGIR 2025

先预测歧义类型，再据此生成澄清，强调类型驱动的思维链。

共同启示：澄清可以被结构化、被训练，也可以被评测。

Part 1 的相关工作大致有三条路线。CLAIM 关注不确定性估计，把多个模型答案之间的分歧转化为熵，再自动构造澄清样本，最后用 SFT 和 GRPO 训练统一模型。

AmbiK 更偏数据集和任务定义，它把歧义指令、澄清问答、意图和任务规划放到一起，让研究者可以分析澄清对下游任务的帮助。

AT-CoT 则强调先判断歧义类型，再生成对应的问题。它的价值在于让澄清不再完全依赖自由生成，而是有了一个中间推理步骤。

这些工作共同说明，澄清不是无法研究的临场行为，可以有明确的输入、输出和训练目标。但它们也为我们留下了更细的研究空间。

04 · part 1 / gap

研究空白：何时问、问几轮、允许几种意图

单轮 → 多轮

CLAIM 主要覆盖单轮澄清；真实任务往往需要逐步补齐约束。

唯一答案 → 多意图

AmbiK 的歧义任务偏向一个正确意图，可能让模型形成僵硬映射。

一定追问 → 追问决策

AT-CoT 假设要生成澄清，缺少“不需要问”的负例与成本建模。

PROPOSED FOCUS多轮澄清 + 多意图分布 + 是否追问的决策学习

把相关工作放在一起，我们看到三个明显空白。第一，很多设置是单轮的，而真实交互通常不是一次问题就能补齐所有信息。模型需要记住已经问过什么，还要知道下一轮最值得问哪一个约束。

第二，歧义不一定只有一个正确答案。用户说“找一个便宜的方案”，可能有多个合理目标。更好的数据应该保留意图分布和用户偏好，而不是把所有样本压成唯一标签。

第三，生成澄清本身不等于做对决策。有时继续问会增加交互成本，有时直接执行反而更安全。因此我们计划显式建模“问、做、拒绝或等待确认”之间的选择。

05 · part 2 / related work

Computer Use 研究正在从成功率走向过程可靠性

OSWorld-Pro

300+ 任务、2,800+ 子目标的过程式评测，用 LLM-Judge 定位过程失败。

process evaluation

LegacyWorld

以原子性评测 Windows 遗留工作流：成功或不留下残留副作用。

atomicity

AnTrap

运行时异常四层十类；GRPO 可处理单步陷阱，但难解决上下文死锁。

runtime traps

共同启示：最终任务成功不足以解释模型为何成功或失败。

Part 2 的研究重点已经从单纯的任务成功率，逐渐转向过程可靠性。OSWorld-Pro 把任务拆成很多子目标，并用过程评测定位失败发生在哪一步。

LegacyWorld 提出原子性视角：一个工作流不仅要最终完成，还不能留下中间副作用。这对真实电脑操作非常重要，因为错误点击可能在最终结果看不出来之前就改变了系统状态。

AnTrap 则整理了运行时异常，尝试用序列级 GRPO 解决状态和动作层面的单步陷阱。但它也指出，上下文死锁并不是简单增加一个动作奖励就能解决的。

对我们的启发是，意图理解、执行过程和异常恢复必须被放到同一个评测框架里。

06 · part 2 / gap

从“完成了”进一步追问：
为什么能完成，失败后能否恢复？

A
评测成本与可复现性

强依赖昂贵 Judge、单次运行和保密测试集，难以稳定比较不同方法。

B
训练信号不完整

Prompt-only 方案无法区分模型能力与训练带来的收益，数据规模小又容易过拟合。

C
上下文级失败

单步异常可以被修正，但跨多轮的错误假设、死锁和错误恢复仍缺少统一建模。

Part 2 的研究空白也可以归纳成三点。第一是评测。若只能依赖昂贵模型作为 Judge，或者只能运行一次，实验结论很难复现，也很难支撑长期迭代。

第二是训练信号。Prompt-only 方法容易把基座模型的能力误认为方法本身的收益。另一方面，如果训练集很小，模型可能只是记住了工程化模板，没有真正学会恢复策略。

第三是上下文级失败。一个动作失败还比较容易处理，但如果模型一开始就错误理解了用户目标，后续每一步都可能围绕错误假设继续推进，最后形成上下文死锁。

这正好与 Part 1 的追问决策相连：早期更好的澄清，可能比后期更复杂的恢复更便宜。

07 · proposed study

一套可训练、可评测、可回流的统一方案

①
数据构造

生成多意图、缺约束和多轮澄清样本，保留不确定性与用户修正。

②
理解模型

SFT 学固定格式；DPO / GRPO 学追问决策、成本和安全边界。

③
执行模型

在特定网站上训练观察、动作、验证与异常恢复策略。

④
闭环评测

同时报告意图准确率、追问效率、任务成功率、残留副作用与恢复率。

最终目标：让“先理解，再行动”成为 Computer Use 的默认工作流。

基于前面的空白，我们的计划不是只增加一个更大的模型，而是把数据、训练和评测一起设计。

数据侧重点是保留不确定性。一个样本不只记录最终答案，还要记录有哪些可能意图、为什么需要追问、用户补充了什么，以及这个追问是否真正降低了风险。

训练侧可以分阶段进行：先用 SFT 学会稳定输出固定格式，再用偏好优化或 GRPO 学会在“追问和直接执行”之间做选择。执行侧则关注观察、动作、验证和恢复四个环节。

评测不能只看最终成功率，还要看追问效率、过程错误、残留副作用和恢复率。只有这些指标一起改善，才能说明模型真的学会了可靠交互。

takeaways · Q&A

让智能体先确认，
再可靠地行动

模糊语言理解是 Computer Use 的前置安全层；结构化 output 是两阶段模型之间的接口；数据飞轮让失败成为训练信号。

多轮澄清多意图可恢复执行

最后总结三句话。第一，模糊语言理解不是 Computer Use 的附属功能，而是它的前置安全层。模型如果没有理解用户真正的目标，后面的点击越准确，风险反而越大。

第二，固定格式的结构化 output 是两个部分之间的关键接口。它让理解模型和执行模型可以分别训练、分别评测，也让数据飞轮有明确的记录位置。

第三，失败不是只能被统计的坏结果。追问失败、动作失败和恢复失败，都可以被整理成下一轮训练信号。

谢谢大家，欢迎讨论：哪些任务适合追问，怎样定义安全的“不追问”，以及如何用更低成本做可复现的 Computer Use 评测。
