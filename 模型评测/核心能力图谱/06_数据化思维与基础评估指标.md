## 0. 为什么评测岗必须精通基础指标

- 分维度报告本质是**分类/排序指标**的矩阵；
- "模型 A 比 B 高 2 分"要靠**置信区间**判断是否显著；
- 人评数据质量靠 **Cohen's κ / Krippendorff's α**；
- 给训练侧的归因靠**切片分析 + 错误类型分解**。

## 1. 分类指标：ACC / Precision / Recall / F1

### 1.1 混淆矩阵（一切的起点）
```
                预测正    预测负
真实正(TP)      TP        FN   (漏报)
真实负(FN→实际是TN) TN     FP   (误报)
```
- **TP** 真阳、**TN** 真阴、**FP** 假阳、**FN** 假阴。

### 1.2 四个基础指标
$$
\text{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN}
$$
$$
\text{Precision}=\frac{TP}{TP+FP}\quad\text{(预测为正的里面有多少真正)}
$$
$$
\text{Recall}=\frac{TP}{TP+FN}\quad\text{(真实正的里面找出多少)}
$$
$$
F_1=\frac{2\cdot P\cdot R}{P+R}\quad\text{(P/R 的调和平均)}
$$

> **评测视角**：
> - 安全拒答评测里，Recall 低 = 漏放有害内容（危险）；Precision 低 = 过度拒答（影响体验）。
> - 多选题 Accuracy 要注意选项偏置（CircularEval 见多模态笔记 §3）。
> - 类别不平衡时 Accuracy 会骗人（全预测多数类也有高 ACC）→ 看 F1 / 每类 Recall。

### 1.3 多分类扩展
- **Macro-F1**：每类 F1 平均（平等看待每类）。
- **Micro-F1**：汇总所有 TP/FP/FN 再算（受大类主导）。
- 选哪个要在报告里写清。

## 2. 排序指标：AUC / ROC

### 2.1 ROC 曲线
横轴 FPR（假阳率）= FP/(FP+TN)，纵轴 TPR（召回）= TP/(TP+FN)。不同阈值下画曲线。

### 2.2 AUC
ROC 曲线下面积，**衡量模型把正例排到负例前面的能力**，与阈值无关：
- AUC=1 完美，0.5 随机，<0.5 比随机还差。
- **评测视角**：奖励模型（RM）筛选、检索排序、judge 一致性校验常用 AUC；Arena 的 BT 拟合也属排序框架。

```python
from sklearn.metrics import roc_auc_score
auc = roc_auc_score(y_true, y_score)   # y_score 是模型给的正类概率
```

## 3. 生成/文本指标

- **EM（Exact Match）**：完全匹配，严苛。
- **Token-level F1**：预测与标准答案的词级重叠（抽取式 QA 常用）。
- **BLEU / ROUGE / METEOR**：n-gram 重叠，机器翻译/摘要，与人对齐弱，仅参考。
- **WER/CER**（语音）：(S+D+I)/N，见语音笔记 §3.1。

## 4. 置信区间与显著性（"差 2 分"可信吗）

### 4.1 Bootstrap 置信区间
从样本有放回重采样 B 次，算每次指标，取 2.5%/97.5% 分位：
```python
import numpy as np
def bootstrap_ci(scores, B=1000):
    means = [np.mean(np.random.choice(scores, len(scores))) for _ in range(B)]
    return np.percentile(means, [2.5, 97.5])
```
- 两个模型的 CI 重叠 → 差异**不显著**，别下结论。

### 4.2 为什么重要
评测集就几百题，分数波动大。不报 CI，训练侧可能根据噪声乱改策略。

## 5. 标注一致性（人评可信度）

- **Cohen's κ**（两人）：$\kappa=\frac{p_o-p_e}{1-p_e}$，$p_o$ 观察一致率，$p_e$ 随机一致率。
- **Fleiss' κ / Krippendorff's α**（多人）：多人标注一致性。
- **经验阈值**：<0.4 差、0.4-0.6 一般、0.6-0.8 好、>0.8 很好。人评方案 κ<0.6 必须回炉改 Rubric。

## 6. 数据化思维：怎么从数据给结论

评测报告不是分数表，是**可执行结论**。模板：

```
① 总体：分维度得分 + 与基线/上版本的 delta（带 CI）
② 切片：按领域/难度/长度/人群分组，找短板子群
   （如 WER 在"口音+噪声"组骤升）
③ 错误分解：把错题聚类成类型
   （知识缺失 / 推理断链 / 格式不遵循 / 幻觉 / 拒答过度 / 抽取失败）
④ 能力边界：按难度分档看衰减曲线，找"崩溃点"
⑤ 归因：某维度低 → 数据不足? SFT 配比? 对齐过度?
⑥ 建议：具体、可验证（"补 X 类数据 500 条，预期 Y 维度 +3 分"）
```

> 这套写法贯穿所有模态笔记的 §7「结果分析」，是 JD「数据化思维 + 给出分析结论」的直接落地。

## 7. 评测报告数据化模板（可直接套用）

| 模块 | 内容 | 用到的指标 |
|---|---|---|
| 概览 | 总分 + delta + CI | ACC / Elo / F1 |
| 维度雷达 | 各维度得分 | 分维度 F1/Acc |
| 切片短板 | 子群表现 | 分组 Recall/WER |
| 错误画廊 | bad case 类型占比 | 错误类型计数 |
| 显著性 | 是否显著优于基线 | bootstrap CI |
| 归因建议 | 训练侧动作 | 维度→数据/训练映射 |
