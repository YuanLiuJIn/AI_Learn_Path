# 03. 多轮 Agent RL

> 目标：理解多轮任务中 RL 的特殊挑战，以及代表性框架的解决方案。

## 1. 单轮 RL vs 多轮 Agent RL

```text
单轮 RL：
  Prompt → 模型生成一次 → 判断对错 → 奖励
  环境简单，训练相对稳定

多轮 Agent RL：
  Prompt → 模型思考 → 调用工具 → 观察结果 → 再思考 → ...
  可能 5-50 轮交互
  环境复杂，每轮依赖前面结果
```

### 多轮任务的典型场景

```text
修 Bug：
  理解 Issue → 定位代码 → 写修复 → 编译 → 跑测试
  → 失败 → 分析错误 → 修改 → 再编译 → 通过

浏览网页：
  打开浏览器 → 搜索 → 点击结果 → 阅读 → 填写表单
  → 提交 → 验证结果

操作软件：
  打开应用 → 点击菜单 → 输入数据 → 确认 → 检查输出
```

## 2. 多轮 Agent RL 的核心挑战

### 挑战 1：训练不稳定

```text
单轮 RL 已经不容易稳定
多轮 RL 的奖励信号更稀疏、方差更大
训练几百步后崩溃是常态
```

### 挑战 2：Re-tokenize 问题

```text
训练时：模型一次生成整个轨迹（多轮），
        然后做 tokenize，计算 loss

推理时：模型一轮一轮生成，每轮是独立的前向传播

如果训练和推理的 tokenization 不一致
→ 训练好的策略推理时可能不 work
```

### 挑战 3：上下文爆炸

```text
多轮交互会产生大量对话历史
Agent 的上下文窗口容易被撑爆
需要智能裁剪或压缩
```

### 挑战 4：奖励信号稀疏

```text
很多多轮任务只有"最终结果"才有明确奖励
中间步骤缺乏信号 → 训练困难

需要 Process Reward Model 或中间奖励设计
```

### 挑战 5：环境复杂度

```text
代码编译、浏览器交互、文件系统操作...
需要高并发、高可靠的沙箱环境
环境失败 ≠ 模型失败（需要区分）
```

## 3. 代表性框架

### AgentRL

```text
核心贡献：
  全异步生成-训练架构
  支持多任务多轮 RL 训练
  开源模型上训练后超越 GPT-5 和 Claude-Sonnet-4

关键设计：
  推理和训练完全异步
  推理池持续生成轨迹
  训练池持续消费轨迹更新模型
  两者解耦，互不阻塞
```

### RAGEN + StarPO

```text
核心贡献：
  StarPO：轨迹级别的 Agent RL 框架
  统一了 State、Thinking、Action、Reward

关键设计：
  每个 step 有明确的：
    State：当前环境状态
    Thinking：模型推理过程
    Action：模型执行的动作
    Reward：环境返回的奖励
```

### AgentGym-RL

```text
核心贡献：
  长程决策的 Agent RL 框架
  支持多种环境（Web、OS、数据库等）

关键设计：
  轨迹级别训练
  支持异步环境交互
  统一的轨迹格式
```

### Verlog

```text
核心贡献：
  专门处理变长 episode 的 RL 框架
  解决不同任务 episode 长度差异大的问题

关键设计：
  动态 batch
  按 episode 长度分组
  避免短 episode 等长 episode
```

## 4. 多轮 RL 的训练技巧

### 技巧 1：课程学习

```text
从简单任务开始：
  1 轮 → 3 轮 → 5 轮 → 10 轮 → 更长

逐步增加任务复杂度
避免一开始就面对过难的任务
```

### 技巧 2：中间奖励

```text
不是只有最终结果才有奖励

中间步骤也可以给奖励：
  工具调用成功 → +0.1
  编译通过 → +0.3
  测试通过 → +1.0
  最终完成 → +2.0

这需要 Process Reward Model 或规则设计
```

### 技巧 3：轨迹过滤

```text
不是所有轨迹都用来训练

过滤规则：
  太短的轨迹（可能是失败）→ 跳过
  太长的轨迹（可能陷入循环）→ 跳过
  没有工具调用的轨迹 → 跳过
  奖励为 0 的轨迹 → 跳过
```

### 技巧 4：跨会话续传

```text
大型任务可能需要多轮对话才能完成 RL 训练

利用 SQLite 持久化中间状态：
  对话 1：生成 100 条轨迹
  对话 2：继续生成 100 条
  对话 3：汇总训练

参考 Agent 系统设计中的跨会话续传机制
```

## 5. 和你的 UE5 测试 Agent 的关联

```text
你的测试 Agent 天然是多轮的：
  读取 JSON 用例 → 执行步骤 → 观察结果 → 判断通过/失败

如果引入 Agent RL：
  1. 定义奖励函数
     测试通过 → +1
     性能不退化 → +0.5
     步骤数少 → +0.2
     崩溃 → -2

  2. 让 Agent 自主探索
     尝试不同的操作顺序
     学习最优的等待条件
     学习何时截图、何时采集性能

  3. 用 GRPO 训练
     同一任务生成多个执行轨迹
     比较轨迹质量
     强化好的策略
```

## 6. 一句话总结

> 多轮 Agent RL 的核心挑战是训练不稳定、奖励稀疏、环境复杂。解决方案包括异步架构、Process Reward、轨迹过滤、课程学习。当前最值得关注的框架是 AgentRL（全异步）、Slime（Agent 解耦）和 RAGEN（轨迹级训练）。
