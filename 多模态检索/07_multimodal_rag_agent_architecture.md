# 07. 多模态 RAG、Agent 与系统架构

> 目标：把多模态数据处理层、混合检索层、RAG/Agent 应用层串成一条完整工程链路。

## 1. 总体架构

```text
多模态原始数据
  ↓
数据处理层
  ├─ 清洗
  ├─ 去重
  ├─ 脱敏
  ├─ 切分
  ├─ OCR / ASR / Caption / 标签生成
  ├─ Embedding
  └─ 数据治理
  ↓
检索引擎层
  ├─ 全文检索
  ├─ 稀疏向量检索
  ├─ 稠密向量检索
  ├─ 多模态语义检索
  ├─ Rerank
  └─ CBO 查询优化
  ↓
应用层
  ├─ RAG
  ├─ Agent
  ├─ 智能搜索
  ├─ 知识库问答
  └─ 推荐 / 内容理解
```

## 2. 数据处理层的职责

数据处理层负责把原材料变成可检索资产。

输入：

```text
文本、PDF、网页、图片、音频、视频、表格、点云
```

输出：

```text
doc_id
chunk_id
modality
content_text
ocr_text
asr_text
caption
tags
embedding
metadata
permission
quality_score
source_uri
version
```

它解决的问题：

```text
数据脏 → 清洗
数据重复 → 去重
数据敏感 → 脱敏
数据太长 → 切分
数据不可读 → OCR/ASR/Caption
数据不可搜 → Embedding
数据不可管 → 元数据与血缘治理
```

## 3. 检索引擎层的职责

检索引擎层负责在线召回和排序。

它接收：

```text
用户 query
过滤条件
权限上下文
业务约束
TopK
```

它返回：

```text
相关文本 chunk
相关图片
相关视频片段
相关音频转写
相关表格
相关结构化记录
相关性分数
引用信息
```

典型查询流程：

```text
Query Understanding
  ↓
多路召回
  ├─ BM25
  ├─ Sparse
  ├─ Dense
  ├─ 多模态向量
  └─ 业务规则召回
  ↓
候选合并去重
  ↓
权限过滤
  ↓
Rerank
  ↓
Top-K 返回
```

## 4. 多模态 RAG 架构

传统文本 RAG：

```text
用户问题
  ↓
检索文本 chunk
  ↓
LLM 基于文本回答
```

多模态 RAG：

```text
用户问题 / 图片 / 截图 / 音频
  ↓
多模态检索
  ├─ 文本文档
  ├─ 图片 / 图表
  ├─ 视频片段
  ├─ 音频转写
  ├─ 表格
  └─ 结构化数据
  ↓
上下文组装
  ↓
多模态模型或 LLM
  ↓
答案 + 引用 + 证据
```

## 5. 多模态 RAG 的三种实现方式

### 5.1 文本化路线

把所有模态先转成文本：

```text
图片 → OCR + Caption
视频 → ASR + OCR + Caption
音频 → ASR
表格 → Markdown / JSON
```

然后走文本 RAG。

优点：

```text
实现简单
兼容普通 LLM
检索链路成熟
```

缺点：

```text
丢失视觉细节
复杂图表和空间关系表达不完整
```

### 5.2 向量化路线

为不同模态生成向量，统一检索。

```text
文本 → Text Embedding
图片 → Image Embedding
视频 → Video/Text Embedding
音频 → Audio/Text Embedding
```

优点：

```text
支持跨模态检索
能召回非文本内容
```

缺点：

```text
需要多模态模型
对齐质量影响检索效果
```

### 5.3 原生多模态路线

检索结果保留原始图片/视频帧，再交给多模态模型理解。

```text
Query
  ↓
检索相关图片/视频帧/文档
  ↓
多模态模型直接看图或视频帧
  ↓
生成答案
```

优点：

```text
保留视觉信息
适合图表、截图、页面理解
```

缺点：

```text
成本高
上下文组织复杂
延迟较高
```

## 6. Agent 如何使用多模态检索？

Agent 可以把多模态检索当作工具。

```text
用户：帮我分析这张系统报错截图，找可能原因
  ↓
Agent 思考：需要理解截图 + 查历史案例 + 查文档
  ↓
工具 1：OCR/图片理解
工具 2：多模态检索相关截图和文档
工具 3：日志查询或代码搜索
  ↓
Agent 综合结果
  ↓
输出排查路径
```

在 Agent 中，多模态检索常承担三类角色：

```text
外部知识库：查文档、图片、视频、表格
长期记忆：查历史任务、用户偏好、历史截图
环境理解：查 UI 截图、页面结构、操作记录
```

## 7. 一个完整例子：文本搜会议视频片段

目标：用户搜索一句话，找到相关会议视频片段，并生成答案。

### 离线阶段

```text
会议视频
  ↓
视频解码
  ↓
镜头切分 / 抽帧
  ↓
ASR 语音转文字
  ↓
OCR 识别 PPT 文字
  ↓
关键帧 Caption
  ↓
片段级内容融合：ASR + OCR + Caption
  ↓
生成文本向量和视频向量
  ↓
写入全文索引、向量索引、元数据索引
```

### 在线阶段

```text
Query：“讲 RAG 架构的那段会议视频”
  ↓
BM25 召回：匹配 RAG、架构
  ↓
Dense 召回：语义相关片段
  ↓
Sparse 召回：关键词扩展
  ↓
权限过滤
  ↓
Rerank
  ↓
返回视频片段：起止时间 + ASR + OCR + 关键帧
```

### RAG 生成阶段

```text
Top-K 视频片段
  ↓
组装上下文
  ↓
LLM / 多模态模型
  ↓
回答：第 23 分 10 秒开始讲 RAG 架构，主要包括检索、重排、生成三个模块……
```

## 8. 多模态检索系统的关键设计问题

### 8.1 Chunk 怎么切？

文本按段落切，视频按时间切，图片按对象或页面区域切。

切得太大：

```text
召回不精确，上下文浪费
```

切得太小：

```text
语义不完整，答案缺上下文
```

### 8.2 多模态结果怎么组装给模型？

可以组装成：

```text
文本摘要
图片引用
视频时间戳
OCR/ASR 证据
表格片段
来源链接
```

### 8.3 权限怎么处理？

企业场景必须在检索阶段做权限过滤。

```text
不能先召回后泄露
不能把无权限内容放进 LLM 上下文
```

### 8.4 结果如何可解释？

RAG 和搜索通常需要返回证据：

```text
命中文档
命中图片
命中视频时间段
命中字段
命中关键词
相似度分数
```

## 9. 一句话总结

> 多模态检索在系统中连接“数据”和“智能”：数据处理层把原始多模态数据变成可检索资产，检索引擎层负责多路召回、融合排序和重排，RAG/Agent/搜索应用则把这些结果转化成回答、行动和推荐。
