## 0. 为什么评测岗要会训练

- 能区分「评测发现的问题」是数据问题、训练问题还是模型天花板；
- 能做**训练侧评测**（Reward Model 评测、SFT 过拟合检测）；
- 能设计「评测→数据→再训练」闭环，而不是只报分。

---

## 1. 训练通用基础

- **Loss**：模型优化的目标（交叉熵/MAE/MSE），训练时下降、验证时监控是否过拟合。
- **优化器**：SGD / Adam / AdamW（权重衰减），学习率 schedule（cosine warmup）。
- **过拟合信号**：训练 loss 降但验证/评测 loss 升 → 数据少或 epoch 多。
- **验证集/测试集**：验证集调参，测试集（评测集）**绝不进训练**，否则污染。

> 评测视角：你复现的分数差，可能只是对方把测试集泄露进了训练（污染检测见语言笔记 §5.2）。

## 2. NLP / LLM 训练链路

```
Pretrain（海量语料，MLM/CLM）
  → SFT（指令数据，监督微调）
      ├─ 全参微调（Full FFT）
      ├─ LoRA（低秩适配，只训增量）
      └─ QLoRA（4/8bit 量化 + LoRA，省显存）
  → Reward Model（人类偏好数据）
  → RLHF（PPO）/ RLVR（可验证奖励）
  → Chat（部署）
```

### 2.1 SFT（监督微调）
用 (instruction, output) 对做 next-token prediction。注意：
- **格式遵循**：chat template 必须和评测时一致。
- **过拟合**：SFT 数据少会背答案，评测泛化差。

### 2.2 LoRA（评测岗最常实操）
只训练低秩矩阵 $W=W_0+\Delta W=W_0+BA$（$r\ll d$），显存省 2/3。
```python
from peft import LoraConfig, get_peft_model
cfg = LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj","v_proj"])
model = get_peft_model(model, cfg)
```
> 评测视角：LoRA 秩/学习率直接影响微调后评测分数，是评测对比要控制的变量。

### 2.3 RLHF / RLVR
- **PPO**：用 Reward Model 给生成打分，策略梯度更新，配 critic/ref 模型（复杂）。
- **DPO**：直接用语料 (chosen, rejected) 做偏好优化，无需独立 RM（更简单，当前主流）。
- **RLVR**：奖励来自可验证信号（代码单测通过、数学答案正确），减少 RM 偏差。

**评测视角**：RLHF 引入**对齐税**（客观降、主观升）；DPO 过度优化会"奖励黑客"。这些都要在评测报告里同时呈现两侧分数（见第 04 章 §1）。

**论文/代码**：InstructGPT (arXiv:2203.02155)、PPO (arXiv:1707.06347)、DPO (arXiv:2305.18290)、LoRA (arXiv:2106.09685)；[trl](https://github.com/huggingface/trl)、[peft](https://github.com/huggingface/peft)

## 3. CV 训练

### 3.1 分类（ResNet/VGG）
- recipe：ImageNet 预训练 → 迁移学习（冻结 backbone 或微调）→ 自己数据集。
- 数据增强：RandomCrop/Flip/Mixup/CutMix。
- 评测：Top-1/Top-5（第 01 章 §3.4）。

### 3.2 检测（YOLO / RCNN）
- YOLO：端到端回归，anchor-based / anchor-free（v8 起）。
- Faster R-CNN：RPN + RoI Pooling。
- 训练要点：正负样本平衡（NMS、IoU 匹配阈值）、学习率 warmup。
- 评测：mAP@0.5 / mAP@0.5:0.95（第 01 章 §4.3）。

**代码库**：[torchvision](https://github.com/pytorch/vision)、[detectron2](https://github.com/facebookresearch/detectron2)、[ultralytics](https://github.com/ultralytics/ultralytics)、[mmdetection](https://github.com/open-mmlab/mmdetection)

## 4. MLLM 训练

### 4.1 典型两阶段
1. **特征对齐（Alignment）**：用图文对训练一个轻量 connector（线性层 / Q-Former / MLP），把视觉特征对齐到 LLM 词空间。此阶段**冻结** LLM 和视觉编码器。
2. **指令微调（Instruction Tuning）**：解冻或部分解冻，用多模态指令数据训练，学"看图说话/推理"。

### 4.2 连接结构对比
| 结构 | 代表 | 特点 |
|---|---|---|
| Linear/MLP connector | LLaVA | 简单，1 层或 2 层 MLP |
| Q-Former | BLIP-2 / InstructBLIP |  bottleneck 查询，压缩视觉 token |
| Resampler | Flamingo | 重采样到固定 token 数 |

### 4.3 评测视角
- 对齐阶段冻结 LLM → 此阶段评测看"视觉特征能否被 LLM 理解"（用 MMBench 简单题）。
- 指令阶段解冻 → 看综合能力（MMMU/POPE）。
- 视觉 token 数量（压缩率）显著影响长图/高分辨率评测分数——对比时要固定。

**论文**：LLaVA (arXiv:2304.08485)、BLIP-2 (arXiv:2301.12597)、InstructBLIP (arXiv:2305.06500)；[LLaVA](https://github.com/haotian-liu/LLaVA)

## 5. 训练指标 ≠ 评测指标（关键认知）

| 维度 | 训练指标 | 评测指标 |
|---|---|---|
| 优化目标 | loss / PPL | 任务准确率 / Elo / F1 |
| 监控频率 | 每 step | 每 epoch / checkpoint |
| 过拟合信号 | 验证 loss 升 | 评测集分数停滞/下降 |
| 反馈延迟 | 即时 | 滞后（尤其 RLHF） |

> 评测岗的价值：训练侧只看 loss 会"瞎"，评测指标才是业务语言。两者要同时看。

---

## 6. 训练侧评测（评测岗专属能力）

- **Reward Model 评测**：RewardBench（chosen 得分 > rejected），四大类（Chat/Chat-Hard/Safety/Reasoning）。
- **对齐税监控**：RLHF 前后客观题 vs 主观题双侧对比曲线。
- **SFT 过拟合检测**：保留 SFT 数据外的 held-out 集，看泛化 gap。
- **数据污染检测**：训练前后切分题分数差（第 02 章 §7.4）。
