# 01. Agentic RAG 概述：RAG 的五个进化阶段

> 目标：理解 RAG 如何从"检索一次、生成一次"进化到"Agent 自主规划多步检索"。

---

## 1. 先建立直觉：传统 RAG 为什么不够？

```text
传统 RAG（Naive RAG）：

用户："最近公司在 AI 安全方面有哪些新政策？"

  ① 检索：用这句话去知识库搜 → 返回 5 个相关文档片段
  ② 增强：把 5 个片段拼到 prompt 里
  ③ 生成：LLM 基于这 5 个片段生成回答

问题：
  - 只搜一次，搜得不准就完了
  - 不会判断"搜到的内容够不够"
  - 不会拆解复杂问题（"AI安全"可能涉及技术安全、合规政策、行业标准）
  - 不会验证答案的正确性
```

---

## 2. RAG 的五个进化阶段

```
阶段 1：Naive RAG（2022）
  全文/向量检索 → 拼接 → 生成
  痛点：语义理解不足、输出质量不稳、优化空间有限

阶段 2：Advanced RAG（2023）
  三段式优化：
    检索前：文档结构优化、索引改进、Query 改写（HyDE假设文档嵌入）
    检索中：域内微调 Embedding 模型、混合检索
    检索后：重排序（Rerank）、上下文压缩
  仍是一轮检索

阶段 3：Modular RAG（2023-2024）
  模块化设计：检索模块、记忆模块、路由模块可插拔
  支持混合检索（BM25 + 向量 + API 调用等）
  灵活组合组件应对复杂场景

阶段 4：Graph RAG（2024）
  知识图谱 + RAG
  用图结构组织文档关系，支持多跳推理和关系理解
  挑战：高质量图构建成本高、混合检索复杂度大

阶段 5：Agentic RAG（2024-2025）★
  Agent 接管整个检索流程：
    - 自主分解问题
    - 多步检索（搜了不满意，换个关键词再搜）
    - 动态决策：自主调用搜索引擎/计算器等工具
    - 实时评估：判断检索质量，不够就重试
    - 流程优化：实时评估检索结果、迭代查询
```

## 3. Agentic RAG 和其他阶段的本质区别

```text
┌──────────────────────────────────────────────────┐
│ 传统 RAG：预先写死的检索策略                      │
│                                                  │
│  用户问题                                         │
│    ↓                                             │
│  固定流程：向量搜索 → Top-K → LLM 生成             │
│                                                  │
│  问题：路径写死了，无法应对复杂/多变的需求          │
└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│ Agentic RAG：Agent 自主决定检索策略               │
│                                                  │
│  用户问题                                         │
│    ↓                                             │
│  Agent 思考：                                      │
│    "这个问题需要拆解吗？"                          │
│    "先搜什么？从哪个知识库搜？"                     │
│    "搜到的结果够用吗？"                            │
│    "要不要换个角度再搜？"                           │
│    "答案可信吗？需要查证吗？"                       │
│    ↓                                             │
│  自主规划 → 多步执行 → 自我验证 → 迭代修正          │
└──────────────────────────────────────────────────┘
```

## 4. 一个具体例子看清差异

```text
问题："对比 2024 年和 2025 年 AI 监管政策的变化"

Naive RAG 的做法：
  检索："对比 2024 年和 2025 年 AI 监管政策的变化"
  → 返回 5 个文档片段，可能只覆盖某一年、某个国家
  → 生成回答（可能片面、不完整）

Agentic RAG 的做法：
  Agent 自主思考：
    Step 1: "这个问题涉及多个时间、多个地区，需要拆解查询"
    Step 2: 先检索 "2024 AI regulation policy"
            → 得到 5 个结果
            → 自主判断："只覆盖了美国，信息不够"
    Step 3: 补充检索 "2024 AI regulation EU China"
            → 得到 3 个更多样的结果
    Step 4: 同样方式检索 2025 年
    Step 5: 对比两批结果，生成结构化回答
    Step 6: 自我验证："覆盖了美欧中三个地区的两年政策，信息完整"
            → 输出最终答案

关键差异：
  Naive RAG = 发一次搜索，拿到什么用什么
  Agentic RAG = 像一个研究员，规划检索、分析结果、补搜缺口、验证质量
```

## 5. Agentic RAG 的四大核心能力

```text
① 规划（Planning）
  自主分解复杂问题为子问题
  "先查主体法规，再查实施细则，最后查执法案例"

② 工具调用（Tool Use）
  不止向量数据库，还能：
    - Web 搜索
    - SQL 数据库查询
    - API 调用（如金融数据接口）
    - Python 计算器

③ 反思与验证（Reflection）
  "搜到的 5 个结果，3 个是 2023 年的旧数据 → 需要重新搜"
  "生成答案中'GDP 增速 5.2%'这个数字，和原文不符 → 修正"

④ 记忆（Memory）
  记住之前搜索过的内容
  避免重复搜索
  积累"这个知识库擅长什么/不擅长什么"的经验
```

## 6. 三种 Single-Agent 架构

从 Agentic RAG Survey 论文的分类：

```text
架构 A：Single-Agent + 线性流程
  Agent 按固定顺序执行：
  问题分析 → 检索 → 评估 → 生成
  适合：简单查询、不需要迭代修正

架构 B：Single-Agent + 循环流程
  Agent 循环执行直到满意：
  检索 → 评估 → {若不足→重新检索} → 生成
  适合：复杂查询、需要多轮搜索

架构 C：Single-Agent + 自适应流程
  Agent 完全自主：
  自主决定下一步是"检索"还是"直接回答"还是"调用计算器"
  适合：混合查询（既需要检索也不需要检索）
```

## 7. 和传统单步 RAG 的对比总结

| 维度 | Naive RAG | Agentic RAG |
|---|---|---|
| **检索次数** | 1 次 | 自主决定（可能 0-N 次） |
| **检索策略** | 固定 | 动态调整 |
| **问题分解** | 不分解 | 自主分解子问题 |
| **质量评估** | 无 | 自主评估并决定是否重新搜索 |
| **工具多样性** | 仅向量搜索 | 向量搜索 + Web + DB + API + 计算器 |
| **适应性** | 差 | 强 |
| **成本** | 低 | 较高（多次 LLM 调用） |
| **适用场景** | 简单事实查询 | 复杂推理、多步对比、需验证的查询 |

---

## 8. 一句话总结

> Agentic RAG 让检索不再是一次性的、写死的操作，而是由 AI Agent 自主规划、执行、验证、迭代的动态过程。从"搜一次拿结果"变成"像个研究员一样多轮探索直到找到满意答案"。
