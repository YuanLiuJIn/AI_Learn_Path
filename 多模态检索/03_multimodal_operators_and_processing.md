# 03. 多模态算子与数据处理流水线

> 目标：理解多模态算子是什么，以及原始数据如何被加工成可检索资产。

## 1. 什么是算子？

在数据系统里，算子就是流水线中的一个标准处理单元。

传统大数据算子：

```text
Filter：过滤行
Map：逐条转换
Join：两张表连接
GroupBy：分组聚合
Sort：排序
```

多模态算子则面向文本、图片、音频、视频、点云等非结构化数据。

一句话：

> 多模态算子 = 可复用、可组合、可分布式执行的多模态数据处理函数。

## 2. 多模态算子的例子

### 2.1 文本算子

```text
文本清洗：去 HTML、去乱码、标准化空格
语言检测：判断中文、英文、混合语言
质量过滤：过滤低质量、广告、模板内容
PII 脱敏：手机号、邮箱、身份证替换
文本切块：按标题、段落、token 数切分
文本去重：Exact Dedup、Fuzzy Dedup、Substring Dedup
文本 Embedding：生成向量
```

### 2.2 图片算子

```text
图片解码：JPEG/PNG/WebP → Tensor
尺寸归一化：Resize、Center Crop
质量检测：模糊检测、低分辨率过滤
OCR：提取图片中的文字
目标检测：识别人、车、商品、按钮
人脸/车牌脱敏：检测区域并模糊
图片 Caption：生成图片描述
图片 Embedding：CLIP/Image Encoder 向量
```

### 2.3 音频算子

```text
音频解码：MP3/WAV/AAC → waveform
降噪：去背景噪声
VAD：语音活动检测
ASR：语音转文字
说话人分离：区分不同说话人
音频 Embedding：声音语义向量
```

### 2.4 视频算子

```text
视频解码：读取视频流
抽帧：按时间或场景变化取关键帧
镜头切分：把长视频切成片段
视频 OCR：识别画面文字
视频 ASR：提取音轨并转文字
关键帧 Caption：描述画面内容
视频片段 Embedding：生成片段级向量
```

### 2.5 点云算子

```text
点云过滤：去噪、下采样
坐标变换：坐标系统一
地面识别：分离地面点
目标检测：车辆、行人、障碍物识别
点云 Embedding：生成空间语义向量
```

## 3. 为什么需要算子体系？

没有算子体系时，每个业务都要重复造轮子：

```text
业务 A 自己写 OCR
业务 B 自己写图片脱敏
业务 C 自己写视频抽帧
业务 D 自己写文本去重
```

问题：

```text
重复开发
质量不一致
性能不可控
难以分布式化
难以统一治理
```

有算子体系后：

```text
OCR(image)
FACE_BLUR(image)
ASR(audio)
TEXT_DEDUP(text)
EMBED_TEXT(text)
EMBED_IMAGE(image)
```

好处：

```text
复用能力
统一优化
统一监控
统一资源调度
统一数据血缘
```

## 4. 多模态数据处理流水线

以文档知识库为例：

```text
PDF / Word / HTML / 图片扫描件
  ↓
解析：提取文本、图片、表格、版面结构
  ↓
清洗：去噪、去模板、去乱码
  ↓
切分：按标题、段落、语义块切 chunk
  ↓
增强：OCR、表格结构化、图片 Caption
  ↓
脱敏：隐私信息替换或打码
  ↓
Embedding：文本块、图片、表格生成向量
  ↓
写入索引：全文索引 + 向量索引 + 元数据索引
```

以视频检索为例：

```text
视频文件
  ↓
视频解码
  ↓
镜头切分 / 抽帧
  ↓
ASR 提取语音文本
  ↓
OCR 提取画面文字
  ↓
关键帧 Caption
  ↓
生成片段级文本表示：ASR + OCR + Caption
  ↓
生成视频片段 Embedding
  ↓
写入检索引擎
```

## 5. 多模态算子的工程要求

### 5.1 可组合

算子应该像积木一样组合：

```text
ImageDecode → FaceDetect → FaceBlur → ImageEncode
```

### 5.2 可分布式

大规模数据必须并行处理：

```text
1000 万张图片 → 切成多个 partition → 多节点并行跑算子
```

### 5.3 可异构执行

不同算子适合不同硬件：

```text
CPU：解码、过滤、格式转换、轻量文本处理
GPU：深度模型推理、Embedding、OCR/ASR/检测模型
```

### 5.4 可观测

需要记录：

```text
处理多少条数据
失败多少条
平均耗时
GPU 利用率
输出质量分
算子版本
模型版本
```

### 5.5 可治理

处理后的数据要可追踪：

```text
这个向量由哪个模型生成？
这个 chunk 来自哪个原始文件？
这个 OCR 结果置信度多少？
这个字段是否经过脱敏？
```

## 6. Embedding 构建在流水线中的位置

Embedding 通常不是第一步，而是后置步骤。

原因：

```text
脏数据直接生成向量 → 检索质量差
重复数据直接生成向量 → 索引膨胀
敏感数据直接生成向量 → 存在安全风险
未切分长文档直接向量化 → 语义过粗
```

推荐顺序：

```text
解析 → 清洗 → 切分 → 脱敏 → 增强 → Embedding → 建索引
```

## 7. 一句话总结

> 多模态算子是多模态数据处理流水线中的标准化处理单元。它把 OCR、ASR、抽帧、脱敏、去重、Embedding 等能力封装成可组合、可分布式、可调度的组件，让原始多模态数据变成可检索、可治理、可消费的知识资产。
