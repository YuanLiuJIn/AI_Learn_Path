# 01. Agent RL 概述：从 Chatbot 到 Agent 的范式转移

> 目标：理解为什么 SFT 的上限有限，以及 RL 如何让 Agent 突破这个上限。

## 1. 三个时代的进化

### Chatbot 时代

```text
模型只会"说话"，不会"做事"

交互模式：
  用户输入 → LLM 生成回答 → 用户自己把回答变成行动

局限：
  高认知负荷（用户需要盯着屏幕）
  低效率（结果需要手动搬运到业务场景）
  不能自主完成复杂任务
```

### SFT Agent 时代

```text
用高质量"指令-工具调用"数据微调模型

交互模式：
  用户指令 → LLM 调用工具 → 返回结果

局限：
  模型上限受限于训练数据的质量
  只能模仿，不能超越人类标注者
  遇到训练数据没见过的场景容易失败
  蒸馏顶尖模型越来越难（不提供完整思维链、数据投毒）
```

### Agent RL 时代

```text
让模型在真实环境中试错、获得奖励、自主进化

交互模式：
  用户指令 → Agent 自主探索 → 环境反馈 → 奖励信号 → 策略优化

核心突破：
  从"模仿人类"到"超越人类"
  从"静态数据"到"动态环境交互"
  从"单轮问答"到"多轮工具调用"
  从"被动学习"到"主动探索"

类比 AlphaGo：
  SFT = 模仿人类棋谱
  RL = 自我对弈 → 超越人类
```

## 2. 为什么 SFT 不够？

```text
1. 数据质量天花板
   最好的数据来自顶尖模型（OpenAI、Claude），但蒸馏越来越难
   巨头不再提供原始思维链，甚至数据投毒
   依赖蒸馏意味着永远追不上

2. 分布外泛化差
   SFT 只会模仿见过的模式
   遇到训练数据没覆盖的场景 → 表现骤降

3. 缺乏自主纠错
   SFT 模型不会"反思"
   做错了就错了，不会自我修正

4. 上限受限于标注者
   人类标注者可能犯错、可能不够高效
   模型永远超不过给它标注的人
```

## 3. RL 如何突破上限？

```text
核心机制：探索-验证-再探索的飞轮

1. 探索（Exploration）
   Agent 在环境中尝试不同的行为
   不一定总是选"当前认为最好"的

2. 验证（Verification）
   环境给出奖励信号
   可以是：代码是否通过测试、任务是否完成、答案是否正确

3. 学习（Learning）
   根据奖励信号更新策略
   好的行为被强化，坏的行为被抑制

4. 再探索
   用更新后的策略再次探索
   左脚踩右脚，螺旋上升
```

## 4. 从单轮 RL 到多轮 Agent RL

### 单轮 RL（当前主流）

```text
典型场景：数学题、代码生成

用户提问 → 模型生成回答 → 判断对错 → 奖励

特点：
  一次生成，一次判断
  环境简单（只有 Reward Model 或规则判断）
  训练相对稳定
```

### 多轮 Agent RL（未来方向）

```text
典型场景：修 Bug、浏览网页、操作软件

用户指令 → Agent 多轮交互
  第 1 轮：理解任务、搜索信息
  第 2 轮：尝试方案 A → 失败 → 分析原因
  第 3 轮：尝试方案 B → 成功 → 返回结果

特点：
  多轮交互，每轮依赖前面结果
  环境复杂（代码编译、网页交互、文件系统）
  训练挑战大（Re-tokenize、上下文管理、长程依赖）
```

## 5. 关键挑战

```text
1. 训练稳定性
   当前 RLHF 往往数百步后即面临崩溃
   需要反复"短期训练-采样-SFT"循环

2. 多轮任务一致性
   多轮 RL 需要处理 Re-tokenize 问题
   训练和推理的上下文处理方式可能不一致

3. 环境复杂度
   Agent 环境越来越复杂（代码、浏览器、操作系统）
   需要高并发、高可靠的沙箱环境

4. 奖励信号稀疏
   多轮任务往往只有最终结果才有奖励
   中间步骤缺乏信号 → 训练困难

5. 计算资源
   RL 训练需要同时跑推理和训练
   比 SFT 贵得多
```

## 6. 一句话总结

> Agent RL 的本质是把 LLM 从"模仿者"变成"探索者"。通过让模型在真实环境中试错、获得奖励、自主进化，突破 SFT 的数据质量天花板。从 Chatbot 到 SFT Agent 再到 RL Agent，每一步都让模型更接近"能自主完成复杂任务的智能体"。
