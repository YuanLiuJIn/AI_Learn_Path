# 05. 向量索引与 ANN 检索

> 目标：理解向量索引为什么存在，以及 HNSW、IVF、PQ、DiskANN、RaBitQ、SIMD、缓存预取、级联裁剪分别解决什么问题。

## 1. 向量检索的基本问题

给定一个 query 向量：

```text
q = [0.12, -0.33, 0.87, ...]
```

在海量向量集合中找到最相似的 Top-K：

```text
x1, x2, x3, ..., xN
```

最直接的办法是暴力搜索：

```text
for every x in database:
    score = similarity(q, x)
return top_k(score)
```

如果有 10 亿条向量，每条 768 维，暴力计算不可接受。

所以需要 ANN：Approximate Nearest Neighbor，近似最近邻。

> ANN 不追求 100% 精确，而是在召回率、延迟、内存、成本之间做工程平衡。

## 2. 向量索引的核心权衡

向量索引永远在权衡：

```text
召回率 Recall：结果准不准
延迟 Latency：查询快不快
吞吐 Throughput：每秒能处理多少请求
内存 Memory：索引占多少内存
构建成本 Build Cost：建索引慢不慢
更新成本 Update Cost：增删改方便吗
```

没有一种索引适合所有场景。

## 3. Flat 暴力索引

Flat 就是不建复杂索引，直接全量扫描。

```text
Query → 和所有向量算相似度 → Top-K
```

优点：

```text
结果最准确
实现简单
适合小规模数据或评估基线
```

缺点：

```text
大规模下太慢
计算成本高
```

## 4. IVF：倒排文件索引

IVF 的思想：先聚类，再只搜相关桶。

离线建索引：

```text
所有向量
  ↓ KMeans 聚类
得到 nlist 个中心点
  ↓
每个向量分配到最近的中心点桶里
```

在线查询：

```text
Query
  ↓
先找最近的 nprobe 个中心点
  ↓
只在这些桶里搜索
  ↓
Top-K
```

直觉：

```text
不用全库搜，只搜 query 附近的几个区域。
```

优点：

```text
内存相对可控
查询速度快
适合大规模
```

缺点：

```text
可能漏掉桶外的近邻
nlist/nprobe 需要调参
聚类质量影响召回
```

## 5. HNSW：图索引

HNSW 可以理解成“向量世界里的高速导航图”。

建图时：

```text
每个向量是一个节点
相似向量之间连边
形成多层小世界图
```

查询时：

```text
从高层入口开始
  ↓
贪心寻找更近节点
  ↓
逐层下降
  ↓
在底层精细搜索
  ↓
Top-K
```

直觉：

```text
高层负责快速定位大致区域
底层负责局部精细搜索
```

优点：

```text
召回率高
延迟低
工程实践成熟
```

缺点：

```text
内存占用较高
构建成本较高
更新和删除复杂
```

核心参数：

```text
M：每个节点连接多少邻居，越大召回越高但内存越大
efConstruction：建图时搜索宽度，越大图质量越好但构建越慢
efSearch：查询时搜索宽度，越大召回越高但延迟越高
```

## 6. PQ / SQ：量化压缩

原始 float32 向量很占内存：

```text
768 维 × 4 字节 = 3072 字节 / 向量
10 亿条 ≈ 3TB
```

量化的目标：

```text
用更少字节表示向量
用近似距离替代精确距离
```

### 6.1 Scalar Quantization

把每个 float 映射成 int8 或更低比特。

```text
0.1234 → 127
-0.384 → 43
```

优点：简单。

### 6.2 Product Quantization

把向量切成多个子向量，每个子向量用一个码本表示。

```text
768 维向量
  ↓
切成 96 个 8 维子向量
  ↓
每个子向量找最近的 codeword
  ↓
用 code id 表示
```

查询时通过查表快速估计距离。

优点：

```text
压缩率高
适合大规模
可与 IVF 组合成 IVF-PQ
```

缺点：

```text
有量化误差
精度依赖码本质量
```

## 7. DiskANN：把索引放到 SSD

当向量规模太大，内存放不下时，就需要磁盘型 ANN。

DiskANN 的核心目标：

```text
尽量少访问 SSD
每次访问尽量顺序或批量
保留少量热数据在内存
用图搜索保持高召回
```

常见思路：

```text
内存中存导航结构 / 缓存热节点
SSD 中存完整邻接表和向量
查询时通过少量 SSD 访问完成搜索
```

适合：

```text
十亿级以上向量
内存成本敏感
延迟要求仍然较高
```

## 8. RaBitQ 量化压缩

RaBitQ 是一种面向高维向量的随机量化方法。

核心思想：

> 把 D 维高维向量压缩成低比特表示，例如 D-bit 字符串，用很小的空间近似估计距离或相似度。

原始向量：

```text
[0.123, -0.384, 0.772, ..., 0.031]
```

量化后：

```text
[1, 0, 1, 1, 0, ..., 1]
```

典型检索流程：

```text
Query
  ↓
用量化向量快速粗排
  ↓
得到候选 Top-N
  ↓
用原始向量或更高精度向量精排
  ↓
返回 Top-K
```

价值：

```text
显著减少内存
提高缓存命中
加速距离计算
保留可控的误差界
```

注意：

```text
量化不是最终答案，而是候选生成和粗排手段。
高质量系统通常还会做原始向量重算或 Rerank。
```

## 9. Multi-Path 并行查询

图索引搜索可能陷入局部最优。

单路径：

```text
入口 A → B → C → D
```

Multi-Path：

```text
路径 1：入口 A → B → C
路径 2：入口 X → Y → Z
路径 3：入口 M → N → P
          ↓
       合并候选
          ↓
       Top-K
```

好处：

```text
提升召回率
降低尾延迟
利用多核并行
避免单路径局部最优
```

代价：

```text
CPU 消耗更高
候选去重与合并更复杂
需要控制并行路径数量
```

## 10. SIMD 加速

SIMD 是 CPU 的向量化指令。

普通计算：

```text
一次算一个数字
```

SIMD：

```text
一次算一组数字
```

向量检索中常用 SIMD 加速：

```text
内积
L2 距离
余弦相似度
Hamming 距离
量化向量解码
Top-K 比较
```

对于二值向量，可以用：

```text
XOR + POPCNT
```

快速计算 Hamming 距离。

## 11. 缓存预取

图索引会随机访问大量节点和邻居向量。

```text
当前节点 → 邻居列表 → 邻居向量 → 邻居的邻居
```

随机访问容易 cache miss。

缓存预取的做法：

```text
当知道下一批邻居 ID 时，提前把它们的向量加载到 CPU cache。
```

例如：

```text
当前节点邻居：[23, 88, 901, 77]
系统提前 prefetch 这些节点的向量
```

好处：

```text
减少内存等待
提高吞吐
降低尾延迟
```

## 12. 级联裁剪

级联裁剪就是：

> 用便宜方法先过滤大部分候选，再用昂贵方法精算少量候选。

典型流程：

```text
第 0 级：元数据过滤
  只保留权限、时间、类型符合的数据

第 1 级：量化向量粗排
  从千万级缩小到 Top-10000

第 2 级：原始向量精排
  从 Top-10000 缩小到 Top-1000

第 3 级：Hybrid 融合
  合并 BM25 / Sparse / Dense 候选

第 4 级：Rerank 模型
  从 Top-1000 选出 Top-20
```

优点：

```text
降低计算量
降低模型调用成本
保持较高召回
让延迟更稳定
```

## 13. 如何选择索引？

| 场景 | 推荐 |
|---|---|
| 小规模、高精度评估 | Flat |
| 百万到千万级、内存充足 | HNSW |
| 大规模、希望控制内存 | IVF / IVF-PQ |
| 十亿级、内存敏感 | DiskANN / SSD 图索引 |
| 极致压缩与粗排 | PQ / SQ / RaBitQ |
| 高质量 RAG | Dense + BM25 + Rerank，而不是只靠向量索引 |

## 14. 一句话总结

> 向量索引的本质是在召回率、延迟、内存和成本之间做权衡。HNSW 用图提高召回和速度，IVF 用聚类缩小搜索范围，PQ/RaBitQ 用量化压缩降低内存，DiskANN 用 SSD 承载超大规模，SIMD 和缓存预取负责底层加速，级联裁剪负责把昂贵计算留给少量高质量候选。
