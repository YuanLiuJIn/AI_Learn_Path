# 03. 数据污染与评测可靠性

> 目标：理解为什么很多 Benchmark 分数不可信，以及如何做更可靠的评测。

---

## 1. 什么是数据污染？

```text
数据污染（Data Contamination）：
  评测集的题目出现在了模型的训练数据里
  模型"见过这道题" → 分数虚高
  这个分数不代表真实能力，只代表"背题能力"

例子：
  你把期末考试的卷子提前给了学生
  学生拿了 95 分
  但你真的能说这个学生学得好吗？
```

### 污染有多严重？

```text
2024 年研究发现：
  - 部分开源模型在 MMLU 上的"真实分"比"报告分"低 5-15%
  - 越大的模型污染问题越严重（训练数据越难追溯）
  - GSM8K、MMLU 等老评测集污染尤其普遍
```

---

## 2. 污染的类型

```text
Type 1：直接污染
  评测题目原文出现在训练数据中
  例：MMLU 的某道题被爬虫抓取后进了训练集

Type 2：间接污染
  评测题目被改写后出现在训练数据中
  例：原题 "1+1=?" → 训练数据中有 "What's 1+1?"

Type 3：语料污染
  评测集的相关讨论、解析出现在训练数据中
  例：某 GitHub Issue 的修复方案被讨论过

Type 4：偏好泄漏（LLM-as-Judge 特有）
  裁判模型和生成模型有渊源（同厂商/同训练数据）
  → 裁判无形中偏袒"自己人"
```

---

## 3. 如何检测污染？

```text
方法 1：N-gram 重叠检测
  查评测文本片段是否出现在训练数据中
  工具：lm-eval-harness 内置污染检测

方法 2：加密评测
  对评测数据进行加密/改写
  模型没见过加密版 → 分数更真实

方法 3：在线生成新题
  每次评测从题库动态抽取新题
  例：LiveBench 从最新论文、新闻中生成题目

方法 4：难度曲线分析
  按理说，题目越难分越低
  如果某道"很难"的题分数异常高→怀疑污染
```

---

## 4. Goodhart 定律

```text
Goodhart 定律：
  "当一个指标成为目标，它就不再是好指标"

在 LLM 评测中：
  当 "MMLU 分数" 成为大家追逐的目标
  → 公司开始在训练数据中混入 MMLU 题目
  → 分数越来越高，但真实能力没有提升
  → MMLU 作为评测的意义被摧毁

例子：
  GSM8K 曾是数学能力的黄金标准
  近两年来，各模型分数趋近天花板
  不是因为数学能力强了，而是因为"刷题"了
  业界已开始转向更难的新评测（MATH、AIME）
```

---

## 5. 提高评测可靠性的策略

```text
策略 1：多评测交叉验证
  不只信一个评测，用 3-5 个同类评测取一致性

策略 2：用防污染评测
  LiveBench、Chatbot Arena 这类动态评测天然防污染

策略 3：人工抽检
  从评测结果中随机抽 100 条，人工复核
  如果自动评分和人工判断差异大 → 评测有问题

策略 4：私有评测集
  构建未公开的内部评测数据
  公司绝不公开 → 外部模型绝无可能"背题"

策略 5：任务泛化评测
  不只测"原题"，测原题的变体
  如果变体分数骤降 → 模型是背题而非理解
```

---

## 6. 一句话总结

> 评测分数 ≠ 真实能力。数据污染使很多 Benchmark 分数虚高 5-15%。可靠评测需要交叉验证、防污染设计、私有评测和人工抽检。记住 Goodhart 定律：当分数成为目标，它就不再是好指标。
