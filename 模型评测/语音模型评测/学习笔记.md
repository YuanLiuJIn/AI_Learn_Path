## 1. 前置基础知识（语音特性决定评测方法）

### 1.1 语音信号与建模基础

```
波形 (16kHz PCM)
  │
特征：Mel-spectrogram / FBank / MFCC
  │
离散化：语义 token（HuBERT/w2v-BERT k-means）+ 声学 token（EnCodec/SoundStream RVQ）
  │
建模：ASR(语音→文本) / TTS(文本→语音) / SpeechLM(语音→语音)
```

**关键认知**：语音同时携带两类信息
- **语言学信息**（说了什么）→ 可转成文本评测（WER）
- **副语言信息**（怎么说的：情感、口音、年龄、语速、环境音）→ **转文本后完全丢失**

> 这是语音评测与 LLM 评测最本质的差别，也是当前研究热点（SD-Eval、AudioBench 的动机）。

### 1.2 各任务的技术栈与评测切入点

| 任务 | 代表模型 | 评测切入点 |
|---|---|---|
| ASR | Whisper, Paraformer, FunASR | WER/CER、跨域鲁棒性、流式延迟 |
| TTS | VITS, CosyVoice, F5-TTS, Seed-TTS | MOS、可懂度(WER)、音色相似度(SIM)、韵律 |
| 自监督表征 | wav2vec2, HuBERT, WavLM | SUPERB 下游任务综合分 |
| 语音 LLM | Qwen-Audio, SALMONN, GPT-4o-audio | 指令遵循、音频理解、副语言感知 |
| 全双工对话 | Moshi, GLM-4-Voice | 延迟、打断、轮次自然度（**无统一标准，机会点**） |

### 1.3 影响评测分数的关键变量

| 变量 | 影响 | 应对 |
|---|---|---|
| **文本归一化** | WER 可差 2-5 个绝对点 | 统一 normalizer（Whisper EnglishTextNormalizer 是常用基线），并公开脚本 |
| 采样率 / 编码 | 16k vs 24k、mp3 压缩损失 | 统一重采样与格式 |
| 音频时长切分 | 长音频切分策略影响 ASR 结果 | 固定 VAD 参数 |
| 参考音频（TTS zero-shot） | prompt 音频质量决定克隆效果 | 固定 prompt 集 |
| MOS 标注批次 | 不同批次系统性偏移 | 同批放入 GT 与 baseline 一起评 |
| 解码/推理参数 | beam size、temperature | 固定并记录 |

## 2. 评测维度体系

```
语音模型评测
├── ASR
│   ├── 准确率        WER / CER
│   ├── 鲁棒性        噪声/远场/口音/领域外/code-switch
│   ├── 多语言        FLEURS(102语种), Common Voice
│   └── 效率          RTF、首字延迟、流式稳定性
├── TTS
│   ├── 自然度        MOS / CMOS  ← 主观
│   ├── 自动自然度    UTMOS / NISQA / DNSMOS  ← 客观代理
│   ├── 可懂度        用 ASR 转写算 WER/CER
│   ├── 音色相似度    SIM (WavLM-TDNN cosine)
│   ├── 韵律/情感     F0 RMSE、时长误差、情感分类准确率
│   └── 鲁棒性        长句、数字、多音字、中英混读、漏读/重复率
├── 语音表征          SUPERB 系列（冻结上游 + 轻量下游）
├── 语音大模型
│   ├── 语音指令遵循  Dynamic-SUPERB, AIR-Bench
│   ├── 音频理解      AudioBench, MMAU（语音/音乐/环境音）
│   ├── 助手能力      VoiceBench（知识/指令/安全 + 扰动）
│   └── 副语言响应    SD-Eval（情感/口音/年龄/背景音）
├── 语音增强/分离     PESQ, STOI, SI-SDR, DNSMOS
├── 音频生成          FAD, CLAP Score
└── 全双工实时        首包延迟、打断响应时间、轮次自然度（自定义）
```

## 3. 指标数学定义与陷阱

### 3.1 WER / CER
\[ \text{WER} = \frac{S+D+I}{N} \]
（替换+删除+插入）/ 参考词数。中文用字级 CER。

**六个必须注意的点**：
1. **归一化决定成败**：标点、大小写、数字（"2024" vs "二零二四"）、繁简、儿化音、英文缩写
2. WER 可以 > 100%（插入过多）
3. 长音频要报**加权平均**（按词数加权），不能对每条求平均
4. 领域词/专名错误的业务影响远大于虚词，可加**关键词错误率（KWER）**
5. 流式场景还要看**尾部延迟**与**修正次数**（re-write）
6. **Whisper 论文的方法论**（`doc/Whisper_*.pdf`）：强调 **zero-shot 跨数据集鲁棒性**才是真实能力，单一测试集刷 SOTA 会过拟合

### 3.2 TTS 主观指标
- **MOS**：1-5 绝对评分（ITU-T P.800）。要求：≥15 名标注员、耳机、安静环境、含锚点样本
- **CMOS**：A/B 对比，-3~+3，**比 MOS 敏感得多**，模型接近人类水平时必须用 CMOS
- **SMOS**：相似度 MOS（音色克隆场景）
- **不可跨论文比较**：不同批次的 MOS 有系统性偏移 → 必须在同一批次内同时评 GT + baseline + 你的模型

### 3.3 TTS 客观四件套（当前行业标准，Seed-TTS 确立）
| 指标 | 方法 | 含义 |
|---|---|---|
| **WER/CER** | Whisper/Paraformer 转写合成音频 vs 原文 | 可懂度 & 漏读重复检测 |
| **SIM** | WavLM-TDNN 说话人 embedding cosine | 音色相似度 |
| **UTMOS** | 自动 MOS 预测模型 | 自然度代理 |
| **CMOS/MOS** | 人评 | 最终标尺 |

### 3.4 UTMOS（`doc/UTMOS_*.pdf`）
VoiceMOS Challenge 2022 冠军系统：SSL 特征（wav2vec2）+ 强/弱学习器融合 + listener-dependent 建模（把标注员 ID 作为输入，建模个体偏好）。
- 当前 TTS 论文最常报的自动 MOS
- **注意局限**：在训练分布外（新语言、新模型架构）预测不准，只能作为**相对比较**与**回归监控**，不能替代人评做终审

### 3.5 DNSMOS（`doc/DNSMOS_*.pdf`）
非侵入式（无需参考音频）语音质量评估，P.835 三分量：
- **SIG**（语音信号质量）、**BAK**（背景噪声侵扰度）、**OVRL**（整体）
- 用于语音增强/降噪评测，与 PESQ 相比更贴近人耳且不需要 clean 参考

### 3.6 其他
- **PESQ / STOI / SI-SDR**：侵入式增强指标，需要 clean 参考
- **FAD**：音频生成的 FID，VGGish/PANNs 特征
- **CLAP Score**：文本-音频一致性（对应图像的 CLIPScore）
- **EER / minDCF**：说话人验证

## 4. 核心论文精读要点（doc/）

### 4.1 SUPERB（`SUPERB_*.pdf`）★范式奠基
**核心设计**：**冻结上游 SSL 模型**，只训练轻量下游头（线性层/2 层 LSTM），在 10+ 任务上评测。
- 覆盖：PR、ASR、KS、QbE、SID、ASV、SD、ER、IC、SF
- 意义：把「表征好不好」变成可比较的统一指标，且**计算成本低、对所有上游公平**
- **面试价值**：能讲清"为什么要冻结上游" → 保证比较的是表征质量而非微调能力，并降低算力门槛

### 4.2 Dynamic-SUPERB（`Dynamic-SUPERB_*.pdf` + `Phase-2`）
- 从「固定任务集 + 微调」转向「**指令驱动 + zero-shot**」，55 个任务（Phase-2 扩到 180 任务，含语音/音乐/环境音、回归与序列生成）
- 社区协作式构建，任务可持续扩充
- 关键发现：**多任务指令微调能带来 unseen 任务的泛化**，但模型在需要精细声学理解的任务上普遍差
- 对应 JD：这就是"指令时代的语音评测范式"，构建自己的语音评测体系可直接借鉴其任务模板格式

### 4.3 VoiceBench（`VoiceBench_*.pdf`）★语音助手评测标杆
评测 LLM-based 语音助手的三大能力：**通用知识、指令遵循、安全**
最大贡献是**系统性扰动设计**，把真实世界因素注入测试：
- **说话人变化**：不同音色、年龄、口音、语速
- **环境噪声**：背景噪音、混响
- **内容噪声**：口语化表达、语法错误、重复、口头禅
- 结论：现有语音助手与「ASR + LLM 级联」相比仍有明显差距，且在扰动下性能大幅衰减
- **方法论迁移**：任何业务评测集都应该做「扰动版本」，测的是鲁棒性而非温室性能

### 4.4 AudioBench（`AudioBench_*.pdf`）与 AIR-Bench（`AIR-Bench_*.pdf`）
- **AudioBench**：8 类任务 26 个数据集，三个层次——语音理解（ASR/QA）、**声音特征理解（情感/性别/口音）**、音频场景理解
- **AIR-Bench**：两级设计
  - **Foundation 级**：19 个任务的单选题，客观可判定
  - **Chat 级**：开放式音频对话，GPT-4 judge 打分（含参考答案 + 音频元信息）
  - 这种「客观基础 + 开放对话」双层设计是音频大模型评测的通用架构
- 共同要点：**judge 只能看到文本，所以必须把音频的元信息（情感标签、说话人属性）注入 judge 的参考信息**，否则无法评判副语言相关的回答

### 4.5 MMAU（`MMAU_*.pdf`）
10k 条人工标注的语音/音乐/环境音，27 项技能，要求**专家级推理**（不只是识别，还要推断）。
- 揭示当前音频 LLM 距离人类差距巨大（人类 82% vs 最强模型 ~50%）
- 是音频理解能力上限的探针

### 4.6 Whisper（`Whisper_*.pdf`）★评测方法论
- 68 万小时弱监督训练，核心主张：**不在单一测试集上微调，评测 zero-shot 跨域泛化**
- 提出用 **"有效鲁棒性"（effective robustness）**：在 LibriSpeech 上同等表现的模型，比较它们在其他域的表现差距
- 论文附录的**文本归一化方案**已成为业界事实标准
- **面试价值**：能讲"为什么 LibriSpeech test-clean 上 SOTA 不代表能用"

### 4.7 Seed-TTS（`Seed-TTS_*.pdf`）与 FLEURS（`FLEURS_*.pdf`）
- Seed-TTS：确立 zero-shot TTS 的 **WER + SIM** 客观评测标准（seed-tts-eval 已开源，中英测试集），配合 CMOS 人评
- FLEURS：102 语种 ASR/翻译/语种识别，多语言评测标准集

## 5. 语音评测集构建实操

### 5.1 数据来源与合规
- 真实用户音频：**隐私合规是第一关**（需授权、脱敏、去标识）
- 录音棚采集：质量可控、成本高，适合 TTS 参考集
- 公开数据集：注意许可证与污染（LibriSpeech 极可能在训练集中）
- 合成扰动：对干净音频加噪/混响/变速，可低成本造鲁棒性测试集（VoiceBench 做法）

### 5.2 覆盖度设计清单（ASR 场景）
说话人（性别/年龄/口音）× 环境（安静/噪声/远场/车载）× 内容（通用/领域术语/数字/中英混）× 时长分布

### 5.3 MOS 人评规范
1. 标注员 ≥ 15 人，每条音频 ≥ 5 人评
2. 统一耳机、安静环境，开场做听力校准
3. 插入**锚点样本**（GT 真人录音、已知劣质样本）校准尺度
4. 随机顺序 + 双盲
5. 剔除锚点判断异常的标注员
6. 报告置信区间（MOS ± 95% CI）与标注员一致性
7. 模型接近人类水平时改用 **CMOS**（更敏感）

## 6. 工程化落地

### 6.1 工具链
| 工具 | 用途 |
|---|---|
| **jiwer** | WER/CER 计算 |
| **Whisper normalizer** | 文本归一化参考实现 |
| **s3prl** | SUPERB 官方评测工具链 |
| **ESPnet / SpeechBrain / WeNet / FunASR** | 端到端工具箱，自带评测 recipe |
| **seed-tts-eval** | zero-shot TTS 的 WER+SIM 标准脚本 |
| **UTMOS / NISQA / DNSMOS** | 自动质量评分 |
| **VoiceBench / AudioBench / AIR-Bench / Dynamic-SUPERB** | 语音大模型评测 |
| **fadtk** | FAD 计算 |

### 6.2 Pipeline 要点
```
音频数据集 (含元信息: 说话人/环境/领域标签)
   │
[可选] 扰动生成 (加噪/混响/变速)  ← 鲁棒性评测
   │
模型推理 (ASR转写 / TTS合成 / SpeechLM回复)
   │
判分层
  ├─ 文本类: normalizer → jiwer → WER/CER
  ├─ 音频类: ASR回环(WER) + WavLM(SIM) + UTMOS
  └─ 对话类: judge（需注入音频元信息）
   │
分层聚合 (按说话人/环境/领域切片，看短板分布)
   │
报告 + 人评抽检
```

### 6.3 特有工程难点
- **音频存储与传输**：数据量大，需缓存与流式加载
- **判分模型依赖多**：ASR、说话人模型、MOS 模型各一个，需版本锁定（换 ASR 版本会导致 WER 变化）
- **人评闭环成本高**：自动指标做日常回归，人评做版本终审，两级机制
- **延迟评测**：需精确测 TTFB/首包音频延迟，与效果指标分开报告

## 7. 结果分析要点

1. **切片分析**：按口音/噪声/领域/时长分组看 WER，找出短板人群（比总体 WER 有价值得多）
2. **鲁棒性衰减曲线**：SNR 从 20dB 降到 0dB 的性能曲线
3. **错误类型分解**：替换/删除/插入的比例 → 删除多说明漏识别（VAD 问题），插入多说明幻觉（Whisper 类模型常见）
4. **TTS 四件套一起看**：只报 MOS 高但 WER 高 = 好听但读错，业务不可用
5. **自动指标与人评相关性**：UTMOS 与 CMOS 的 Spearman，决定能否用自动指标做日常门禁
6. **语音大模型**：区分「ASR 错误导致的失败」与「LLM 理解失败」——做级联基线对比即可归因
