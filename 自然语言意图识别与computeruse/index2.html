PART 01 / 训练路线 · SFT → RL04 — 06

SFT 固化「何时追问 + 固定格式」，GRPO 找回多样性

SFT 给协议与契约，RL 给校准与分布宽度；两段训练目标不同，评测指标也必须不同。

阶段一 · SFT：学会“要不要问” 01

数据与目标
  1. 不可执行才问：缺失槽位、指代不明、多候选、高风险动作 → 输出最小澄清问题；可执行则直接给计划，数据显式带 ask / act 决策位。
  2. 正负样本成对出现：强行猜测（默认选第一个文件）与过度澄清（追问已说明信息）都标为错误，否则模型会退化成“永远问”或“永远不问”。
  3. 输出契约固定 {decision, intent, slots, missing, question, plan[], confidence, verify}；格式合法性交给 JSON Schema，不占语义学习容量。
  4. 路径：Qwen + LoRA（LLaMA-Factory）先验证协议，再全参微调。
风险：SFT 是分布收紧算子——模板化、熵下降、confidence 校准被破坏，必须单独测多样性与校准。

阶段二 · GRPO / RLVR：把分布重新撑开 02

目标与奖励
  1. 选 GRPO：同一 prompt 采样一组回答、组内相对优势替代 critic，成本低；组内多样本本身就是多样性信号。
  2. 奖励 R = R_task + λ₁R_clarify + λ₂R_format − λ₄R_over − λ₅R_wrong，把“多意图都合理”写进奖励：同一模糊指令的多种合理澄清均判对。
  3. 防熵塌缩：DAPO clip-higher + 动态采样、Dr. GRPO 去长度 / 难度归一化偏差、小 KL，避免把已变窄的分布再压窄。
  4. 指标：pass@k（k 增大）与熵、澄清类型分布；RL 的价值是让 pass@k 回升，而非只顶高 pass@1。
判据：澄清准确率↑、过度澄清率↓、格式违规率→0，且 pass@k 与熵不低于 SFT 基线。

依据：GRPO arXiv:2402.03300 · DAPO 2503.14476 · Dr. GRPO 2503.20783 · RL 后 pass@k 收窄 2504.13837 · SFT 记忆 vs RL 泛化 2501.17161 · RLHF 降低多样性 2310.06452 · ProRL 长时间 RL 保持探索 2505.24864 · 格式约束影响推理表现 2408.02442；受限解码可参考 XGrammar 2411.15100。

HYPOTHESISSFT 管“会不会问 + 格式合法”，GRPO 管“问得准 + 问得活”，用多意图奖励与 pass@k 检验多样性能否回到基座。

PART 02 / 训练路线 · DOM 解析 × VLA06 — 06

两条实现路线，一套双层奖励

读 DOM / HTML 的文本 Agent 精确、可断言；VLA 从像素直出动作、跨应用泛化；奖励拆成过程路径与最终结果两层，让模型学会多条可达解法。

路线一 · 读 DOM / HTML 的文本 Agent 01

观测与动作
  1. 观测与动作：把 DOM / Accessibility Tree / 程序状态压成带编号文本，模型直接输出选择器、fill/type、CLI 或 API 调用——状态可读，也就可以用断言验证。
  2. 训练：SFT 学「页面 → 元素 → 动作」与工具选择（Mind2Web、WebArena），再在可验证环境做在线 RL——任务自动合成 + 程序断言给奖励（ScaleCUA、CUA-Universe）。
  3. 判断依据：程序状态先于像素，不把所有操作都逼上截图，Agent 应在截图 / DOM / CLI / MCP 之间路由（StateAct、Screenshots or Tools?）。
短板：DOM 文本长、token 成本高；桌面应用、Canvas 与图表没有可读 DOM，纯文本会丢失图标与布局语义。

路线二 · VLA：从截图直出动作 02

观测与动作
  1. 观测与动作：输入截图（可叠加 SoM / OCR / 候选框），一次前向输出归一化坐标与动作 token，把「看」和「点」合成一个策略，不依赖 DOM。
  2. 训练：视觉 grounding 预训练（SeeClick、GUI-Actor）→ 轨迹 SFT → 在线 RL；grounding 不确定性（Argus）可作为「是否点击 / 是否追问」的信号。
  3. 自蒸馏与记忆：on-policy self-distillation 用自身交互纠正单步决策与任务记忆（GUI-SD-v2），把「失败后恢复」写进策略而非只学成功轨迹。
短板：视觉编码器把误差注入 state，坐标精度对分辨率敏感；纯截图看不到后端真实状态，长程误差累积。

依据：Mind2Web 2306.06070 · WebArena 2307.13854 · StateAct 2607.22798 · ScaleCUA 2607.11185 · CUA-Universe 2609.05374 · Screenshots or Tools? 2608.03327 · SeeClick（ACL 2024）· GUI-Actor 2506.03143 · Argus 2606.25760 · GUI-SD-v2 2609.27307。

REWARD结果奖励只判终态（环境断言、文件与 DOM 状态）；路径奖励给中间子目标、步数效率与无残留副作用；同一任务的多条合法轨迹同等给正分，路径不同不扣分，只有越权、破坏状态、绕过确认的路径为负。

路径奖励需配可验证的中间断言，防「凑子目标」刷分；同题多条 rollout（GRPO / DAPO 式）用于保住多解。文献依据大纲第 15.3 节，训练设计为本方案建议，未独立实验验证。
