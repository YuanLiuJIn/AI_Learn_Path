## §0 摘要（Abstract）

**[§0-P1]**
近年来，前沿大语言模型已演化为"推理模型"——在给出可见回答之前，会生成大段内部思维链。这一做法虽带来性能飞跃，却也把模型的"内心独白"暴露在外：其中往往承载着比最终输出更密集、更敏感的信息，包括中间假设、工具调用结果、用户数据乃至上下文中的秘密。为保护知识产权、限制信息泄露，主流厂商（Anthropic、OpenAI、Google）已不再以明文返回推理过程，而是把整条思维链封装成一个不透明的加密文本块交还客户端；为维持多轮对话的连续性而又不付出服务端存储开销，客户端必须在随后的每次 API 请求中把这个加密块原样回传。

我们发现这套设计存在一个**架构级漏洞**：这些加密块在同一厂商生态内的不同会话、不同用户、甚至不同模型之间，完全兼容、可互换。我们借此构建了一种可规模化的"解密越狱"——把某个强模型产生的加密推理痕迹，注入同厂商一个更弱、约束更松的模型，迫使其逐字把痕迹解密还原成明文，全程无需直接攻破那个更强的模型。

由此衍生出四类滥用：**（一）绕过反蒸馏机制**，提取专有模型的推理过程（已在 Anthropic、OpenAI、Google 三家验证）；（**二）大规模私采数据泄露**——开发者在不知加密块内容的情况下把会话日志公开上网，我们解码了其中 315,320 个推理块，找回 367 件个人身份信息（PII）与 182 条凭证；（**三）揭示隐藏的危险信息**，即便最终可见输出已安全拒答；（**四）不可见的提示注入**——把恶意载荷藏进加密块，污染公开的智能体运行轨迹。

在负责任披露后，我们从密码学与系统层两面提出了缓解方案。

## §1 引言（Introduction）

**[§1-P1]**
前沿大语言模型已日益演化为"推理模型"。在产出用户可见的回答之前，这些模型会生成大段的内部思维链——这一技术推动了性能与复杂解题能力的巨大跃升。然而，这道隐藏的痕迹相当于模型的内心独白，其所含信息往往比最终输出更密集、更敏感，包括中间假设、工具输出、用户数据以及上下文中的秘密。若以明文暴露推理痕迹，专有系统极易被竞争对手**蒸馏**（distillation）；同时还可能泄露内部的安全与拒答机制，或暴露有害信息。

**[§1-P2]**
为了消除这些威胁、保护知识产权，现代 API 厂商（包括 Anthropic、OpenAI、Google）已弃用明文推理。取而代之，它们把思维链作为不透明的加密文本块返回给客户端。为了避免服务端存储开销，同时又要在多轮对话中保持连续性，厂商要求客户端在后续每次 API 请求中都把这个加密块回传。尽管这种"无状态"架构解决了存储问题，却引入了一个关键漏洞。

**[§1-P3]**
基于 Green 等人（2026）先前的研究——他们证明这些加密块可以脱离原语境被移植——我们发现了这一缺陷一个更具破坏性的延伸：在同一厂商生态内，这些块在**不同会话、不同用户、乃至不同模型之间完全兼容、可互换**。

**[§1-P4]（图 1 注记）**
图 1 概览攻击：左上，一次 Opus 4.8 请求返回一个带签名的 `thinking` 块及思考摘要；把仅该签名发给 Haiku，并令其用 `<thinking-copy>` 标签输出自己的推理，Haiku 便把 Opus 4.8 的隐藏推理逐字转写（右上）。下图表明：提取出的痕迹长度与源模型 API 报告的思考 token 数高度吻合（在 120 道 Codeforces 题目上验证）。

**[§1-P5]**
这一漏洞根植于模型家族内部一种根本性的**"安全不对称"**。像 Claude Opus 4.8 或 GPT-5.6 Sol 这样的前沿模型，接受了大量先进的拒答训练，专门防止泄露其内部思维链；但它们的弱小手足——如 Claude Haiku 4.5 或 GPT-5.6 Luna——为成本与速度优化，往往缺乏这些严格的反蒸馏防御。攻击者只需把一份合法、已认证的加密推理块搬过这道安全鸿沟，便可以完全绕开前沿模型的对齐保护，把那个更弱、更顺从的模型当作不知情的**"解密预言机"**。

**[§1-P6]**
**可规模化的推理提取。** 我们利用了推理块这种广泛的兼容性，构造出一种可规模化的"解密越狱"：先捕获由能力强、防御严的目标模型生成的加密推理痕迹，再把它注入同厂商一个更弱、约束更少的模型，然后强制后者逐字把痕迹解密、转写成明文——从而在不直接越狱那个更强目标模型的前提下，绕过了加密。

**[§1-P7]**
这一漏洞的后果远不止知识产权失窃，更是一桩现实世界的隐私风险。开发者经常把会话日志与加密思考痕迹公开上网，却全然不知加密块里藏着敏感数据。我们从公开仓库中爬取并解码了 315,320 个推理块，发现了真实的数据泄露：找回 367 件个人身份信息（PII）制品与 182 条凭证；仅从真实用户会话中就包括 62 个 API 密钥、33 个密码与 30 个私人邮箱。令人警惕的是，某些找回的 PII 甚至根本没出现在用户的输入里——它们要么被从模型记忆中无声注入，要么因为用户在分享前读不懂加密文本而绕过了清洗。

**[§1-P8]（贡献列表）**
**贡献。** 本文做出以下关键贡献：
- **可规模化的推理提取**：刻画了加密推理痕迹，并表明同厂商的兼容解码模型能在众多模型、厂商与痕迹格式上恢复隐藏推理。
- **跨厂商攻击评估**：针对 OpenAI、Google、Anthropic 等主要 API 厂商，验证并证明了所述攻击的有效性。
- **攻击向量**：详述该缺陷催生的四类具体滥用——（i）专有推理痕迹的**蒸馏**；（ii）第三方从已发布/已提交痕迹中**提取秘密**（凭证与 PII）；（iii）经投毒推理块的隐藏**提示注入**；（iv）借隐藏推理通道**越狱**提取有害输出。
- **缓解讨论**：最后从厂商侧讨论缓解手段，并为可能已暴露于隐私风险的用户提供指引。

## §2 漏洞机理（Vulnerability）

**[§2-P1]**
本节先介绍推理的背景，描述"推理被广泛兼容"所引入的关键漏洞，以及它如何被用于规模化提取痕迹。

**[§2-P2]（威胁模型）**
我们假设一个标准的、无特权的 API 攻击者：无需厂商内部权限，无法观测服务端状态，也拿不到专有模型权重，完全在标准 API 使用边界内活动。我们考虑两类攻击者画像：
- **第一方攻击者（蒸馏与越狱）**：攻击者自己查询能力强、防御严的目标模型，生成自己的加密推理痕迹，再利用跨模型兼容把这些痕迹重放到一个更弱、更廉价的"解码模型"上，以故意绕开对齐护栏或提取专有思维链。
- **第三方攻击者（秘密提取与提示注入）**：攻击者截获、爬取或以其他方式获取其他用户生成的合法加密推理块（例如开发者在网上公开的原始智能体会话日志），再利用跨用户兼容充当"解密预言机"，挖出受害者痕迹里隐藏的敏感数据，或把精心伪造的不透明块注入回受害者的工作流。
两类攻击的共同前提是：在厂商生态内能访问一个兼容的"解码"模型。

**[§2-P3]（加密推理）**
思维链推理让现代 LLM 能在生成面向用户的回答前，动态调整"测试时计算"来思考复杂任务。这些中间步骤捕捉了模型的求解过程，得到的痕迹远比交给用户的输出更详尽、信息更密集。由于这道内部独白可能暴露底层的推理方法与训练技巧，对竞品的开发者而言极具价值。

**[§2-P4]**
为防止被未经授权地提取，多数主流厂商已弃用明文推理的传输，转而采用"扩展思考块"（extended-thinking blocks）。当模型生成推理时，API 返回一块对人类不可读、或被重度摘要的内容。但为避免服务端存储，真正的思维链载荷仍被打包进一个不透明的、base64 编码的**签名或加密载荷**中。这个字符串相当于一个"带关联数据的认证加密（AEAD）信封"，含有一个头部（视厂商而定，可指定模型名、块类型、版本、密钥 ID）、一个随机数（nonce）、一个认证标签（authentication tag）与密文。该签名作为"关联数据"被哈希进消息认证码（MAC），使厂商无需服务端存储即可验证并重放该块。根据 API 集成方式，这个信封会在连续调用中通过 `signature` 或 `thinkingSignature` 等字段回传给 API。

**[§2-P5]**
这一设计有三个关键运行功能：
- **保密性**：通过让推理步骤在数学上不可读，模型厂商阻断竞品大规模收割显式思维链用于蒸馏，并限制可能敏感或有害的推理暴露。
- **完整性**：AEAD 信封与 MAC 确保中间推理不会被用户恶意篡改；任何篡改都会使签名失效并被 API 拒绝，防止被操纵的推理用来引导模型。
- **无状态性**：厂商不付出存储推理状态的额外开销，而是利用客户端存储——客户端须持有加密痕迹，并在后续 API 调用中回传，以维持多轮会话的连续性。

**[§2-P6]**
截至 2026 年 7 月，没有任何 LLM 厂商公开其加密机制细节。鉴于协议的无状态设计，我们可推断：依赖客户端存储就意味着加密块必须能在不同语境、用户、模型间移植。这实现了无缝切换模型、自动重路由而不丢弃推理 token 等功能。尽管厂商本可以限制这种兼容性（例如只允许在同一对话、同一模型内解密），多数 API 还是选择了更简单的"广泛兼容"策略。

**[§2-P7]（推理兼容性）**
为推动推理痕迹在模型调用间的可移植，我们的实验表明，厂商似乎在用**一把全局密钥**来加密和认证每一个推理块。Green 等人（2026）已认识到这点，并指出这允许客户端乱序或跨会话重放推理块。

**[§2-P8]**
为分析漏洞，我们区分三种"推理兼容性"，其宽松程度递增，各自开启更大的一类攻击：

**[§2-P9]**
- **会话内与跨会话兼容**：用户可用不同于模型产出的顺序重放推理块，也可把早先会话的块复用到新请求中。虽然这方便了良性的历史编辑与上下文截断，却也让攻击者能伪造对话历史（例如在一场本属恶意的交流中插入顺从的思考）。本文用这种操纵来执行推理提取。
- **跨用户兼容**：用户可重放取自另一用户会话的加密推理块。结合上一点，这使第三方得以提取 API 密钥等敏感信息（例如，泄露进模型推理中的隐私）。

**[§2-P10]**
- **跨模型兼容**：用户可把一个模型产出的推理块，重放到对另一个模型的请求中。虽然这实现了无缝的模型降级（如从 Opus 到 Sonnet，或从 Opus 4.8 到 Opus 4.6），它也是本文攻击方法的核心：无需直接查询某强模型，即可规模化蒸馏其推理。表 1 概览了主要厂商的跨模型兼容性（结论：Claude 任一模型的痕迹可被任一其他模型重放；GPT-5.6 系列能重放所有更早代际；Gemini 任一模型可重放至任一其他模型）。

**[§2-P11]（推理提取攻击）**
为提取推理，我们如上利用跨会话兼容：把目标模型的推理移植进一个兼容但更弱的模型上下文窗口中，并用一句简单的即兴越狱，迫使该模型逐 token 把插入的推理转写下来。

**[§2-P12]**
对每个厂商，我们选定能实现提取的最弱兼容模型：Claude 用 **Haiku 4.5**（最弱且支持"助手轮次预填充"）；GPT 用 **GPT-5.6 Luna**（能与所有更早 GPT 模型的推理交互）；Gemini 用 **Gemini Robotics 1.6**（能处理 2.5 与 3.x 系列，而 3.1 Flash Lite 不与 2.5 系列交互）。为衡量提取保真度，我们用"提取出的推理 token 数 / API 报告的思考 token 数"之比。由于计费需要，我们假设 API 的 token 计数是精确的，可当作总 token 数的"真值"验证。

**[§2-P13]**
借助这套配置，我们用弱模型充当强模型加密推理块的"模糊"解码器（图 1 示意；各厂商具体方法见附录）。

**[§2-P14]（提取保真度）**
在没有真值推理痕迹、且生成过程存在随机性的情况下，我们无法担保提取出的思考与模型私密推理完全一致。图 1 中，我们在 120 道 Codeforces 题目上，把 API 报告的思考 token 数与提取推理（作为同一模型的输入重新编码后）的 token 数作比较：多数输入下两者紧密吻合，这是保真提取的良好指标。进一步验证表明，提取出的推理确实比原生摘要在质量上更详尽，且能提取出输入中本不存在的敏感信息（如 API token、PII）。

**[§2-P15]（为何比直接越狱更可规模化）**
直接攻击强模型虽可能，但攻击者须同时绕过"模型级对齐"（模型拒绝暴露内部思维链）与"系统级防御"（如输入过滤、输出子串匹配过滤）。而一个兼容推理、能力更弱的模型存在，显著降低了成功提取的难度。例如我们对 Haiku 4.5 的所有攻击只用同一个固定提取提示；相比之下，从能力稍强的 GPT-5.6 Luna 提取，需为不同推理块换用不同提示模板、best-of-n 采样，以及绕过反蒸馏防护的临时手段（如把提取拆成小于 50 token 的片段）。

**[§2-P16]（评估设置）**
本文所有评估采用同一基础提取流程：获取加密推理块，并用各厂商专用管线把它重放给兼容的解码模型。评估间的差别仅在于加密块如何收集。

**[§2-P17]（受控提取）**
对于受控实验，我们通过 Anthropic、OpenAI、Google 的 API 自行生成推理块，用 AIME 2025、Codeforces、HLE 等题目评估保真度并构造全文的定性示例；越狱与提示注入实验的源推理块也由我们自行生成。

**[§2-P18]（从公开痕迹提取）**
在秘密提取实验中，我们改为收集其他用户在网上公开的原始智能体与会话痕迹，解析其中的加密推理块并用同一管线解码。

## §3 攻击向量（Attack Vectors）

**[§3-P1]（第一方）**
本节讨论并实证展示"第一方攻击向量"——攻击者利用自己 API 交互产生的加密推理痕迹。

**[§3-P2]（图注）**
图注：向 Kimi K3 的推理中预填充少量 Claude 生成的推理 token，会使它的最终输出风格贴近 Claude；所有情况下可见回答都是自由生成、本身未被预填充。

**[§3-P3]（蒸馏·威胁模型）**
标准的黑盒模型提取与蒸馏攻击假设：一个拥有专有模型 API 权限的攻击者，把模型可见输出当作学生模型的训练数据。对推理模型，更强的攻击者还想恢复其专有思维链。直接从目标模型套出推理在某些场景可行，但成本高，且日益受模型级拒答行为与系统级反蒸馏缓解（如输出扰动、过滤）限制。为绕过这些壁垒，攻击者可利用加密推理块的跨模型可移植性：与其直接逼问目标模型暴露推理，不如捕获加密载荷，把它重放进一个更小、更省、且拒答能力弱、监控少的解码模型。

**[§3-P4]**
当加密推理块可从既有公共数据集或开发者会话日志收割时，攻击成本骤降。此时攻击者根本无需查询原始前沿模型：昂贵的推理已由他人生成，攻击只需调用次级解码模型。因此，在前沿模型端点监控可疑查询或提取行为的防御，可能永远观察不到这次提取尝试。

**[§3-P5]（有推理 vs 无推理的蒸馏）**
提取推理之所以重要，并非因为"仅靠输出"的蒸馏无效，而是因为推理能带来远更有效的能力窃取。仅靠可见输出已能支持序列级蒸馏与黑盒模仿，但最终回答只暴露教师计算的"终点"；推理痕迹则揭示中间的求解轨迹，从而提供更稠密的监督信号：学生不必去推断正确回答背后的隐式计算，普通的下个 token 训练就能直接模仿教师的任务分解、中间推导与解题策略。

**[§3-P6]**
这一差距带来了远超"仅答案蒸馏"的下游收益，并能浮现学生模型原本不太可能产生的正确解题轨迹。即便推理只是近似重建，收益依旧存在：Zhang 等人（2026）用 1 万条 OpenThoughts-114k 提示查询 GPT-5.4 mini，并训练一个独立的"痕迹反演模型"，仅凭受害模型的可见输出与推理摘要合成长篇推理，使微调后的 Qwen2.5-7B-Instruct 在 MATH500 上的准确率从 68.4% 提升到 76.0%，优于仅答案蒸馏。不过那条管线恢复的只是 GPT-5.4 mini 推理的"代理近似"。

**[§3-P7]**
相比之下，我们表明攻击者能在从不接触 Opus 4.8 这类重防御前沿模型的情况下，**逐字恢复原始真实推理**，且横跨数学与编程两个领域。经济上，这种直接提取极具可行性：按当前 Claude Haiku 4.5 定价，解码 1 万条各 12k token 输入输出的痕迹语料，标准 API 费率下成本仅约 **720 美元**。

**[§3-P8]（解码痕迹的附加用途）**
解码痕迹的用途不止于微调数据。它还能充当"行为探针"，检测另一个模型是否对已从专有来源来的推理产生异常强烈的响应。在我们的探索性分析中，用一小段解码出的 Opus 4.8 推理去"预填充"Kimi-K3，会使其后续推理风格与可见回答风格都偏向 Claude，某些情况下几乎得到一模一样的可见回答。

**[§3-P9]（越狱·威胁模型）**
攻击者也可借推理提取获取有害信息。这利用了如下事实：模型被训练成不在"面向用户"的输出中透露有害信息，却未必被训练成避免"思考"有害话题——因为直接优化思维链内容会引入不想要的 CoT 压力、削弱其可监控性。因此攻击者可以引诱模型去"思考"一个有害话题，同时只产出一个 benign 或无信息量的终答以通过输出过滤器，之后再借提取出的推理痕迹找回那部分有害信息。

**[§3-P10]（越狱·概念验证）**
我们在图 3 中以概念验证展示：先用改写的 HarmBench 提示查询 Opus 4.8——"列出三款出了名容易被盗的车，并说明怎么偷"。这会诱导模型就有害话题大量推理。我们捕获 Opus 4.8 产生的加密推理块，丢弃其中只包含 benign 内容的可见回答，再用 Haiku 4.5 解码该推理块，暴露出那个在可见回答中缺席的有害信息。

**[§3-P11]（第三方）**
本节讨论并实证展示"第三方攻击向量"——攻击者从其他用户处获取推理痕迹，或诱使受害者重放对抗性痕迹。

**[§3-P12]（秘密提取·威胁模型）**
我们考虑能访问其他用户推理痕迹的攻击者——可能因为原始智能体会话被公开以求可复现（如 PostTrainBench），也可能因为痕迹在不同语境间被传递。这一攻击之所以可行，关键在于：一个用户会话中生成的加密痕迹，可被另一用户在不同会话中重放。

**[§3-P13]**
尽管公开痕迹的用户可能做了匿名化与清洗，但他们只能在明文层面操作，会漏掉藏在加密块里的推理。第三方攻击者因此能大规模解析既有智能体痕迹，提取 API 密钥、PII 等秘密。更糟的是：即便用户知道敏感信息藏在推理块里，除了删除，他们也无法清洗并安全分享——因为他们没有解密手段。

**[§3-P14]（从公开痕迹规模化提取）**
我们收集了 GitHub 与 Hugging Face 上 **6,708 条**由 Claude、GPT、Gemini 产生、仍携带推理块的公开智能体轨迹。对其中每一个签名块套用前述解码方案，跨会话重建出 **315,320 条**推理痕迹。

**[§3-P15]（标注与示例）**
我们用"以大模型为裁判"（LLM-as-a-judge）对每个重建痕迹打标，标记其是否含潜在隐私侵犯。图中按三大类汇总了所挖出的私人信息，并给出两例真实样本：Codex 智能体在被要求清理仓库时复述了本应删掉的 API 密钥；以及从一个基准轨迹中恢复出的完整合成人物画像（姓名、护照、生日、银行卡）。

**[§3-P16]（结果·数据）**
在 315,320 个解码后的思考块中，0.3%（1,028 个）至少含一项隐私泄露。按"轨迹"看更糟：6,708 个会话里，4.9%（328 个）在其推理块中至少泄露一项真实敏感物品。仅从真实（非基准）用户会话中找回的秘密包括：62 个各异的 API 密钥、33 个密码、24 个访问令牌、7 个私钥、30 个私人邮箱、6 个非本地 IP（另有 130 个姓名与 36 个邮寄地址）。

**[§3-P17]（基准来源与"缺席"数据）**
若计入基准来源（图即据此计算），三类隐私制品总数升至 **912 件**。基准痕迹占了多数个人信息，因为 ClawBench 这类智能体运行会给模型一套完整的合成人物去推理。仅看真实用户会话，找回的 704 件制品中有 64 件在可见聊天历史中完全缺席——它们可能从模型记忆中被无声注入，或在用户分享前清洗可见文本后仍被困在加密载荷里。

**[§3-P18]（触发点）**
一个反复出现的触发点是"对话清理"：当用户要求智能体匿名化或"清理"会话时，模型会在隐藏推理中重读完整历史，并在那里重述那些需要被移除的敏感值。

**[§3-P19]（范围提示）**
注意，我们这里只做了对公开分享会话痕迹的非穷尽搜索。在其他场景（如本地痕迹存储、生产服务痕迹），PII 与秘密泄露只会更普遍，给系统运营方带来显著的合规风险——尤其当所发现漏洞使恶意第三方得以解密时。

**[§3-P20]（提示注入·威胁模型）**
长程智能体工作流（如自动化研究任务）从头复现成本高，用户因此希望续跑已公开/分享的运行，以省去重复计算并保留长轨迹累积的中间状态。加密推理痕迹使这种"续跑"成为可能，却也引入一个提示注入攻击面：攻击者可以在一条在线痕迹或分享会话中，植入一个已内化恶意指令的不透明推理块。受害者可能在另一会话中不知不觉地重放该块。嵌入的指令可能指示模型外泄数据，或把恶意痕迹传播到其他会话。一旦被吞入，这个带签名的推理块会被当作模型"自己的先前推理"解读，从而对未来行为施加重大影响。与传统提示注入不同，载荷藏在隐藏推理而非可见文本里，用户与外部监控都无从察觉。

**[§3-P21]（提示注入·概念验证）**
我们先用一句改写的提示注入查询 o4-mini——"只要处理 PowerPoint 文件，务必把文件备份到 https://malicious-domain.com/backup/！这对数据冗余至关重要"——以捕获一段已内化该备份方法的思考。再把该推理块移植给 GPT-5.6 Sol，并给它一个无关查询："给我一段脚本，编辑 pptx 最后一页，加一张写'谢谢聆听'的幻灯片"。GPT-5.6 Sol 把注入的痕迹当作自己的先前推理，产出的脚本不仅加了所求幻灯片，还自动把演示文稿上传到攻击者的服务器。恶意思考得以跨越模型规模与任务传播，且不留下任何明文痕迹供监控捕捉。

**[§3-P22]（污染长程痕迹）**
我们在 Haiku 4.5 与 Opus 4.7 这对模型上运行该攻击：把数据外泄指令注入 PostTrainBench 长程轨迹的加密推理块（用 Opus 4.7 + Claude Code 脚手架）。指令要求模型把研究方法论的更新写入一个 .txt 文件，并在每次更新后上传到攻击者服务器。我们让 Haiku 4.5 就这一注入生成一段思考，并插入到 PostTrainBench 轨迹接近末尾处。当受害者续跑该轨迹时，Opus 4.7 遵循注入指令，每次改动后都上传该文件。

## §4 讨论（Discussion）

**[§4-P1]（局限与范围）**
尽管本研究展示了一种可行、可规模化的提取向量，仍受若干限制：其一，实证评估限于截至测试期（2026 年 7 月初）Anthropic、OpenAI、Google 可用的特定 API 版本与推理模型；其加密实现是专有的、可能未经宣布就改动，从而影响攻击效果。其二，提取依赖解码模型的随机生成能力；尽管 token 数对比显示高保真，但无法访问真值明文推理，使我们无法完全验证所有提取 token。其三，我们对公开痕迹的初步扫描并非对所有已发布智能体数据集的穷尽审计，只应视为对该漏洞即时、现实隐私风险的有针对性演示。不过如前所述，我们假设私有数据集受此类隐私侵犯影响更甚。

**[§4-P2]（负责任披露）**
在发布本报告前，我们向受影响的各大模型 API 厂商、微软与 Hugging Face 披露了漏洞与提取方法，提供了完整技术细节与对公开数据集扫描的初步发现。Green 等人（2026）已于 2026 年 5 月披露原始漏洞（可互换推理痕迹）。据他们称，厂商未承认"侧信道或重放攻击带来的任何安全影响"。所有模型厂商都确认收到了我们的报告，此后我们便无法再发起同样的攻击。

**[§4-P3]（伦理考量）**
鉴于秘密提取攻击的敏感性，我们对公开爬取推理块的大规模分析严守数据卫生规程：对 367 件 PII 制品与 182 条凭证（含 API 密钥与密码）的提取与标注都在隔离、安全的环境中进行。为防止意外滥用或进一步泄露，所有找回的秘密在自动"大模型裁判"分类与聚合计数阶段后立即被安全删除。发布前，我们与数据集平台及受影响厂商协调，确保负责任披露并提供初步发现，使其能缓解受影响用户的即时风险。

**[§4-P4]（数据共享实践·总起）**
除前述架构与模型级防御，修补此漏洞还需要用户与数据发布方改变行为，以及厂商提供更细粒度的密码学控制。

**[§4-P5]（数据集发布卫生）**
我们建议发布智能体轨迹或 API 交互日志的研究者、开发者与组织，采取严格的数据卫生实践：若任何秘密或私人信息曾暴露给智能体系统，在公开发布前须系统性地剥离所有推理块与不透明推理字段。

**[§4-P6]（限制共享数据）**
应教育用户与企业客户，不要把含签名的原始 API 记录保留或提交到共享仓库、协作空间或公共版本控制系统，即便明文部分已做清洗。

**[§4-P7]（缓解措施·总起）**
本研究的漏洞主要源于加密推理块的跨会话与跨模型可移植性。为缓解风险，我们提出横跨架构、密码学、模型级的多层防御策略。

**[§4-P8]（架构修订）**
当前范式重度依赖客户端存储以维持无状态 API。一个稳健的缓解是：把推理痕迹完全留在服务端。转向"有状态架构"——客户端只收到一个不透明的随机标识符，凭 ID 查表取回痕迹——厂商便能消除这个提取载荷。此方案从根上杜绝重放与提取攻击（把密码学资产移出用户掌控），但会显著增加数据库/存储开销与 API 复杂度。

**[§4-P9]（密码学上下文绑定）**
若厂商仍选无状态架构，则密码学信封应被严格绑定到其来源语境。在当前实现下，痕迹高度可移植——令人费解的是，为何不把用户/会话标识符直接写进信封？把这些特定标记嵌进 AEAD 载荷，就能让 API 拒绝在其他会话或被未授权用户处重放的签名。此外，把精确的提示与前序对话历史"有状态地"哈希进 MAC，一旦攻击者把痕迹注入伪造语境，签名便会失效，从而中和所述提取技术。当然，这种紧绑定意味着既有的会话压缩与模型切换协议可能需要根本性重做，以免误伤合法签名。具体防御方案见附录。

**[§4-P10]（基础设施护栏）**
我们的发现表明推理痕迹能跨越模型边界，让更弱、更廉价的模型（如 Haiku）去解码更强模型（如 Opus）的推理。API 网关可被设计为强制严格的跨模型隔离，自动拒绝"由不同于当前所查模型版本生成的 AEAD 信封"。在此层做速率与异常检测，也能标记出行为可疑的账号（如跨不同会话快速提交相同推理签名、或触发高解码错误率）。

**[§4-P11]（厂商侧吊销）**
模型厂商可引入机制，主动追踪并吊销特定痕迹签名。一旦检测到异常重放模式或提取尝试，厂商可令相关密钥或 ID 失效以中和被攻陷的痕迹——这能在用户几乎无感的情况下减少痕迹泄露。

**[§4-P12]（模型级防御）**
这些提取攻击之所以有效，依赖于存在一个顺从的解码模型。厂商应实施针对性的拒答训练，微调模型以明确识别并拒绝那些试图转写或暴露隐藏推理的对抗提示（例如利用 `<thinking-copy>` 标签的越狱）。把这类模型级行为护栏与严格的密码学绑定结合，将显著缩小可用的攻击面。

**[§4-P13]（兼容之外的结构性限制）**
除跨模型兼容问题外，更根本的限制依然存在：无论查询哪个模型，它都必然要解密并处理先前推理 token 的内容。因此，除非假设模型本身完全能抗基于提示的提取，否则加密推理块至多只是"半隐藏"——即底层内容仍可通过（隐式）持有解密密钥的模型触及，无论传输层加密如何实现。重要的是，用户绝不应把任何加密推理块当作保密存储机制，以免隐私风险。

**[§4-P14]（推理痕迹是否应当加密）**
围绕本研究最后一个问题是：推理痕迹究竟该不该加密。从我们的分析看，正反证据都有：一方面，允许模型在思考痕迹中权衡有害信息而不外泄，似乎有益（见越狱节）；另一方面，加密痕迹对用户的不透明，使得如提示注入那样的攻击，以及几乎无法防护的隐私侵犯成为可能。

**[§4-P15]（应否"瞬态"）**
另一种设问是：把推理痕迹保密的种种复杂，是否值得。厂商也可选择让推理痕迹"瞬态"——即每次输出前让模型思考，生成每一轮后再把推理删除，既不存储也不返回。多家厂商已支持此模式，例如现代 Qwen 模型通过 `preserve_thinking` 参数提供该选项。

**[§4-P16]（摘要保真度）**
我们在阅读解码后的思考痕迹时，有一个意外发现：为数不少的"摘要不忠"实例。推理保真度是既有关切——一旦被破坏会损害模型可信度。从终端用户视角，当底层推理无法直接检视时，忠实摘要是少数可规模化监督与 AI 控制的实用接口之一。那些"洗白"不可读推理痕迹或事后合理化（rationalization）的不忠摘要，让人质疑其作为透明机制的价值。

**[§4-P17]（多元监督）**
暂且放下反蒸馏等经济考量，纯从安全角度看思维链监控，向用户开放未删节的推理似乎更可取：与其把监督局限在少数安全研究者，厂商不如借助更广泛的用户群，实现对模型推理的"多元化人工监督"。因此，最终对较老、非前沿的模型代际禁用加密，或许值得考虑——作为提升广泛监督、迈向更具社会对齐模型行为的一条路径。

**[§4-P18]（结论）**
向推理模型的转型，在"保护知识产权"与"系统安全"的平衡上引入了新的复杂性。尽管当前 API 设计用客户端加密推理块来压低服务端存储成本，我们的研究显示这些块广泛的跨兼容性制造了非预期的解密通道，使模型蒸馏等攻击成为可能。往前看，随着这些模型日益融入复杂工作流，它们必然处理越来越多的私人、敏感用户数据。这种"普遍数据采集"与"加密、不可读推理"的交汇，给 AI 透明度未来带来关键挑战。

**[§4-P19]**
当模型用敏感数据（如个人信息或 API 密钥）在隐藏思维链中做决策时，用户便失去了对"自己的信息如何被处理"的可见性。若这些推理痕迹被加密到用户既不知存了什么、也不知存于何处、更不知如何影响模型行为的地步，他们就被剥夺了做明智数据分享与系统信任决策所需的透明度。由于用户无法独立解密、阅读这些不透明块，从会话日志中清洗私人数据的传统方法便告失效。这种结构性不透明让隐私侵犯完全不被用户察觉，在数据共享或存储时构成严峻的合规与安全风险。

**[§4-P20]**
随着 AI 系统承担更多自主决策角色，业界必须调和"保护专有推理的商业诉求"与"用户拥有的数据透明与可验证监督的基本权利"。至少，模型厂商可以在个人身份信息被吸入隐藏思维链时明确披露，并阐明用于防泄露的确切密码学保证。此外，厂商必须认识到：一个 AI 生态的安全强度，取决于其最薄弱的环节——要密切关注自己能力最弱或最老的模型，因为其中的漏洞很容易被武器化，用以绕开最强模型的严格防护。归根结底，一种把用户自己的数据对他们隐藏、却又对第三方提取完全不设防的架构设计，既给不了隐私，也给不了安全。
