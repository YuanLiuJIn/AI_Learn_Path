# 04. 循环控制

> 目标：理解 Agent 循环的步进式执行模型、三层防护机制、状态追踪和智能终止。

## 1. 循环设计的三大目标

```text
可控性 ←→ 完整性
  ↑          ↑
  └── 效率性
```

| 目标 | 含义 |
|---|---|
| 可控性 | 每步可追踪、可中断，状态转换清晰，支持断点恢复 |
| 效率性 | 避免无效重复，减少冗余操作，快速完成任务 |
| 完整性 | 能完成复杂任务，不过早终止，优雅处理边界 |

## 2. 核心挑战

### 挑战 1：无限循环风险

```text
典型场景：
  Step 1: 执行工具 → 失败
  Step 2: 重试工具 → 失败（同样错误）
  Step 3: 再次重试 → 失败
  Step 4: 继续重试 → 失败
  ... 无限循环

根因：没有循环检测机制、缺少明确终止条件
```

### 挑战 2：步数限制的两难

```text
限制过严：复杂任务无法完成，用户需要拆分任务
限制过松：可能陷入循环，资源消耗过大

核心矛盾：任务完成率 ↔ 资源可控性
```

### 挑战 3：终止时机判断

```text
过早终止：LLM 误以为任务完成，实际还有工作未完成
过晚终止：LLM 不知道该停止，继续做无用操作

核心问题：LLM 自己难以判断任务完成度
```

## 3. 步进式执行模型

将复杂任务分解为原子化的步骤：

```text
用户输入任务
  ↓
初始化（加载上下文、准备工具列表、设置状态）
  ↓
多步执行循环：
  Step N 开始
  ├─ 检查 1：是否需要裁剪上下文？
  ├─ 检查 2：是否达到步数限制？
  ├─ 检查 3：是否检测到循环？
  ├─ 调用 LLM（输入：上下文 + 历史）
  ├─ LLM 返回文本 or 工具调用
  │   ├─ 返回文本 → 流式输出给用户
  │   └─ 返回工具调用 → 执行工具 → 结果加入历史
  └─ 判断是否继续
      ├─ 继续 → 下一步
      └─ 停止 → 返回结果
```

### 原子化步骤的特征

```text
每个步骤：
  有明确的输入（上下文状态）
  有明确的输出（文本或工具调用结果）
  有独立的状态（成功/失败/进行中）
  可被追踪（ID + 步数）
  可被中断和恢复
```

## 4. 三层循环控制

### 第一层：硬限制

```text
机制：
  设置最大步数
  达到限制时强制终止

作用：
  所有任务的兜底保护
  资源消耗上限可控
```

### 第二层：循环检测

```text
机制：
  记录最近 N 个操作
  检测是否存在重复模式
  识别无效的重复尝试

检测算法：
  提取最近 N 个工具调用
  计算唯一操作数
  如果唯一数很少（如 ≤ 2）→ 判定为循环

触发动作：
  警告 LLM："检测到可能的循环"
  建议："尝试不同的方法或寻求澄清"
  如果继续重复，提前终止
```

### 第三层：智能终止

```text
机制：
  在接近步数限制时提前 1-2 步提示
  引导 LLM 主动总结和结束

提示内容：
  "我们正在接近步数限制。请总结已完成的工作并结束。"

作用：
  优雅终止而非强制中断
  提供有用的总结信息
  用户体验更好
```

## 5. 状态追踪

### 三级 ID 体系

```text
conversationId → 整个会话的所有历史
  ├─ requestId → 单次执行的所有步骤
  │   ├─ messageId → Step 1
  │   ├─ messageId → Step 2
  │   └─ messageId → Step N
  └─ requestId → 下一次执行
```

### 状态转换

```text
idle → running → finished（正常完成）
              → canceled（用户取消）
              → aborted（步数/Token 超限）
              → error（异常错误）
```

## 6. 多 Agent 协作（Sub-Agent）

当单个 Agent 面临复杂任务时，通过专业化分工处理：

```text
主 Agent
  ├─> Sub-Agent A（独立上下文，专业领域 A）
  │   └─> 返回结果
  ├─> Sub-Agent B（独立上下文，专业领域 B）
  │   └─> 返回结果
  └─> 整合结果，继续执行

优势：
  上下文隔离：主对话保持简洁
  专业化：定制系统提示词和工具集
  可复用：一次定义，多处使用
```

## 7. 循环设计关键原则

```text
原则 1：可控性优先于智能性
  宁可让人类控制，也不要完全自主

原则 2：小步快跑优于大步慢走
  每步做一件事，问题早发现、易回滚

原则 3：优雅终止优于强制完成
  不完美的总结 > 无限循环

原则 4：状态透明优于黑盒执行
  用户应该清楚每步在做什么
```

## 8. 一句话总结

> 循环控制的核心是在"完成任务"和"控制资源"之间找平衡。步进式执行让每步可追踪，三层防护（硬限制 + 循环检测 + 智能终止）防止失控，三级 ID 实现完整状态追踪，Sub-Agent 通过上下文隔离处理复杂任务。
