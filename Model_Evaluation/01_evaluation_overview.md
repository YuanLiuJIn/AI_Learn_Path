# 01. 模型评测全景：为什么需要评测？

> 目标：理解模型评测的必要性、分类体系、四大挑战。

---

## 1. 为什么需要模型评测？

```text
没有评测的世界：
  公司 A："我们的模型最好！"
  公司 B："不，我们的最好！"
  用户："到底谁好？" → 不知道

有评测的世界：
  在 MMLU 上，模型 A 得分 85，模型 B 得分 82
  → 知识理解能力，A > B
  但在 HumanEval 上，B 得分 90，A 得分 78
  → 代码生成能力，B > A

评测的本质：
  不是"谁最好"，而是"在什么任务上谁最好"
```

## 2. 评测的三层目标

```text
第一层：能力摸底
  "这个模型会什么？不会什么？"
  用标准 Benchmark 测出能力剖面

第二层：版本对比
  "新版本比旧版本强了吗？"
  同一评测、同一条件，对比分数变化

第三层：生产把关
  "能不能上线？"
  安全评测、对抗测试、长期稳定性评测
```

## 3. 评测的分类体系

### 按评测维度

```text
┌──────────────────────────────────────────────────┐
│                  LLM 评测全景                      │
│                                                  │
│  知识理解：MMLU、C-Eval、AGIEval                   │
│  推理能力：GSM8K（数学）、ARC（逻辑）、BBH（综合）   │
│  代码能力：HumanEval、MBPP、SWE-bench              │
│  指令遵循：MT-Bench、AlpacaEval                    │
│  安全对齐：TruthfulQA、ToxiGen、RealToxicity        │
│  多语言：   FLORES、MEGA、Belebele                  │
│  多模态：   MMBench、MMMU、Video-MME               │
│  Agent：    SWE-bench、WebArena、AgentBench         │
│  长上下文： Needle-in-a-Haystack、LongBench         │
│  对话能力： Chatbot Arena（人类投票）                │
└──────────────────────────────────────────────────┘
```

### 按评测方式

```text
静态评测（Static Benchmark）：
  固定测试集 → 模型预测 → 和标准答案对比
  例：MMLU（选择题）、HumanEval（代码通过率）
  优点：便宜、可复现
  缺点：数据污染、不反映真实使用

动态评测（Live Benchmark）：
  实时生成新题 → 防数据污染
  例：LiveBench、Chatbot Arena
  优点：不受污染影响
  缺点：成本高、难标准化

人类评测（Human Evaluation）：
  真人打分 → 和人工评估对比
  例：Chatbot Arena（用户投票盲评）
  优点：最接近真实体验
  缺点：贵、慢、主观

LLM-as-Judge：
  用更强的 LLM 自动评分
  例：MT-Bench、AlpacaEval
  优点：快、低成本
  缺点：裁判可能偏袒、评分标准不透明
```

## 4. 评测的四大挑战

```text
挑战 1：覆盖性
  MMLU 有 57 个学科 → 但真的覆盖了"所有知识"吗？
  学完 57 科的题目 ≠ 懂所有知识
  → 需要更多维度、更新的评测

挑战 2：公平性
  模型 A 在英文 MMLU 上 85 分，模型 B 在中文 C-Eval 上 82 分
  → 谁更好？不可比
  → 需要统一的评测框架和协议

挑战 3：可靠性
  "这个模型的 MMLU 分数是 85"
  → 它是"真理解了"还是"背了题"？
  → 数据污染使很多 Benchmark 分数失真

挑战 4：时效性
  2023 年的评测测不出 2025 年模型的新能力（Agent、长上下文、多模态融合）
  → 评测标准也需要持续更新
```

---

## 5. 评测的两个"铁律"

```text
铁律 1：一个分数不够
  不能只看 MMLU 总分就说"这个模型强"
  必须看多个维度、多个指标的能力剖面
  HELM 的核心思想：不只给一个分数，给一张"能力雷达图"

铁律 2：高分 ≠ 真实好用
  评测分数高 ≠ 用户实际体验好
  排行榜在特定数据上"刷分"是常见现象
  最终标准：在真实业务场景中的表现
```

---

## 6. 一句话总结

> 模型评测不是"找一个排行榜看排名"，而是理解：测什么（维度）、怎么测（方法）、测得准不准（可靠性）。最终目标是为选型、优化和上线提供可信的数据支撑。
