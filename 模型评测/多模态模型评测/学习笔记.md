## 1. 前置基础知识（VLM 架构决定了评测怎么设计）

### 1.1 主流 MLLM 架构

```
图像 ──► Vision Encoder ──► Connector ──► LLM ──► 文本输出
        (CLIP-ViT/SigLIP)   (MLP/Q-Former/    (Qwen/Llama)
                             Perceiver/Pixel
                             Shuffle)
```

三种连接方式与各自的评测含义：

| 架构 | 代表 | 评测上的表现特点 |
|---|---|---|
| MLP Projector | LLaVA 系 | 简单高效，细粒度感知依赖 encoder 分辨率 |
| Q-Former（可学习 query 压缩） | BLIP-2 / InstructBLIP | token 少、成本低，但**细节丢失**，OCR/计数类任务弱 |
| 原生多模态（early fusion） | Gemini / GPT-4o / Chameleon | 跨模态融合更深，评测需覆盖交错图文输入 |

**关键推论**：Connector 会压缩视觉信息 → 所以**计数、OCR、空间位置**是通用弱项，评测集必须专门覆盖这几类。

### 1.2 影响多模态评测分数的关键变量

| 变量 | 影响 | 应对 |
|---|---|---|
| 图像分辨率 / 切图策略（AnyRes、动态分辨率） | 直接决定 OCR、小目标、文档理解上限 | 记录模型的最大分辨率配置 |
| 视觉 token 数 | token 越多细节越好、成本越高 | 报告效果-成本曲线 |
| 图像预处理（resize/pad/归一化） | 不同实现分数差异明显 | 用官方 processor |
| Prompt 模板 | MLLM 对模板极敏感 | 统一模板，公开 |
| 多图 / 交错输入支持 | 不支持则整类任务归零 | 能力矩阵先做支持性摸底 |
| 输出格式 | 抽取失败率高 | 报告抽取失败率，别静默算错 |

### 1.3 视觉语言模型的三类典型失败

1. **语言先验压制视觉**：模型不看图，靠常识猜（"香蕉是黄色的"）→ POPE / MMStar 专测
2. **视觉错觉**：图里有反常识内容，模型仍按常识答 → HallusionBench 专测
3. **细粒度感知不足**：计数错、空间关系错、小字看不清 → BLINK / OCRBench 专测

## 2. 评测维度体系

```
MLLM 能力
├── 感知 Perception
│   ├── 存在性/属性/颜色/计数        MME, MMBench, POPE
│   ├── 空间关系与深度               BLINK, MMBench
│   └── OCR / 文档 / 图表            OCRBench, DocVQA, ChartQA, AI2D
├── 认知 Cognition
│   ├── 学科知识（大学级）           MMMU, MMMU-Pro, CMMMU
│   ├── 视觉数学推理                 MathVista, MathVerse
│   └── 图文联合逻辑                 MM-Vet, MMBench
├── 视频理解
│   ├── 短/中/长视频综合             Video-MME
│   ├── 时序动作与事件               MVBench, EgoSchema
│   └── 视频中的知识获取             Video-MMMU
├── Grounding / 定位                 RefCOCO (IoU@0.5)
├── 幻觉与可信                        POPE, HallusionBench, MMHal
├── 多模态 Agent / GUI                ScreenSpot, OSWorld
└── 安全与合规                        多模态越狱、敏感图识别
```

### 维度设计的两条特有原则

1. **必须做「纯文本消融」**：去掉图片后，模型准确率若接近原分，说明题目不依赖视觉，是无效题（MMStar 的核心发现）
2. **必须抗选项偏置**：MLLM 猜答案倾向严重，用 CircularEval（MMBench）或选项打乱验证

## 3. 指标与判分方法

| 题型 | 指标 | 注意事项 |
|---|---|---|
| 多选题 | Accuracy | 用 CircularEval 降低瞎猜收益 |
| Yes/No（MME、POPE） | Accuracy + Precision/Recall/F1 + **Yes-ratio** | Yes-ratio 揭示"讨好性偏置"，只报 Acc 会掩盖问题 |
| 开放式（MM-Vet、MMHal） | GPT-4(V) as judge，0-1 连续分 | 需固定 judge 版本，报与人工一致率 |
| Grounding | IoU@0.5 / Acc@IoU | 坐标归一化方式要统一 |
| Caption | CIDEr / SPICE / CLIPScore / CHAIR(幻觉率) | 老指标与人评相关性弱，仅作参考 |

### CircularEval 详解（MMBench 提出）
一道 N 选项的题，把选项循环移位 N 次分别提问，**N 次全对**才算通过。
- 随机猜通过率从 1/N 降到 1/N^N
- 能暴露模型的位置偏好
- 代价是 N 倍推理成本 → 工程上要做批处理优化

### 幻觉指标（POPE）
POPE 把幻觉评测转成**二分类判定**："图中有 X 吗？"
- 三种负样本采样策略：**random**（随机物体）/ **popular**（数据集高频物体）/ **adversarial**（与图中物体高共现的物体）
- adversarial 最难，最能暴露语言先验依赖
- 报 Accuracy + F1 + Yes-ratio 三件套

> 这个「把开放式幻觉转成可判定二分类」的思路，是评测方法论的通用武器。

## 4. 核心论文精读要点（doc/）

### 4.1 MMStar（`MMStar_*.pdf`）★方法论最重要
提出两个致命问题：
1. **视觉内容对很多样本是不必要的**：纯 LLM（无图）在 MMMU 等榜单上能拿到接近甚至超过 MLLM 的分数
2. **训练数据中存在无意识的数据泄露**

解决方案：
- 人工精选 1500 道**必须看图**的题，覆盖 6 大核心能力 18 个细分维度
- 提出两个新指标：
  - **MG（Multi-modal Gain）**：多模态训练带来的增益 = MLLM分 − 对应LLM分
  - **ML（Multi-modal Leakage）**：数据泄露程度 = LLM(无图)分 − 原始LLM分
- **面试价值极高**：能讲清 MG/ML 说明你懂评测的方法论批判

### 4.2 MMMU / MMMU-Pro（`MMMU_*.pdf`, `MMMU-Pro_*.pdf`）
- MMMU：6 学科 30 领域 183 子领域，11.5K 题，含 30 种图像类型（图表、乐谱、化学结构、医学影像）
- MMMU-Pro 的三步加固（**升级 benchmark 的标准流程，可直接复用**）：
  1. 过滤掉「纯文本模型也能答对」的题
  2. 候选项从 4 个扩到 **10 个**
  3. 引入 **vision-only 输入**：把题干文字也渲染进图片，模型必须真正"读图"
- 结果：模型分数下降 16.8%~26.9%，区分度大幅提升

### 4.3 MMBench（`MMBench_*.pdf`）
- 双语（中英）、层次化能力分类（L1/L2/L3）
- **CircularEval** + **LLM 辅助答案抽取**（把自由文本对齐到选项，解决抽取失败）
- 这两个工程设计是评测平台必备组件

### 4.4 POPE（`POPE_*.pdf`）与 HallusionBench（`HallusionBench_*.pdf`）
- POPE 见 §3
- HallusionBench 的贡献是**区分两类错误**：
  - **Language Hallucination**：语言先验凌驾于图像（模型没看图）
  - **Visual Illusion**：图像被误解（模型看了但看错）
  - 通过配对图（原图 vs 编辑图）+ 配对问题（Yes/No 反向）来判定，指标含 **question pair accuracy** 和 **figure accuracy**
- 启发：**配对/对照设计**是排除猜测、定位错因的强力手段

### 4.5 MathVista / MathVerse（`MathVista_*.pdf`, `MathVerse_*.pdf`）
- MathVista：6141 题，视觉数学推理事实标准
- MathVerse 的巧思：把同一道题改造成 **6 个版本**，逐步把文字信息挪进图中（Text-dominant → Vision-only），观察分数衰减 → 精确测出模型「到底有多依赖文字捷径」
- 还提出 **CoT 评估策略**：用 GPT-4 逐步拆解推理链打分，而不只看最终答案
- 启发：**信息量梯度设计** 是探测能力边界的有效手段

### 4.6 Video-MME（`Video-MME_*.pdf`）
- 首个全谱系视频评测：6 大领域 30 子类，视频时长从 11 秒到 1 小时（短/中/长三档）
- 900 视频 2700 QA，**全人工标注**
- 三组消融：有无字幕、有无音轨、抽帧数量 → 揭示「长视频 + 多模态信息整合」是最大短板
- 视频评测的工程要点：**抽帧策略**（均匀 vs 关键帧）、帧数上限、是否用字幕，这些必须在报告中说明，否则不可比

### 4.7 MME / MM-Vet / BLINK
- **MME**：14 个子任务，Yes/No 判定，指标 = Accuracy + Accuracy+（同一图两问全对），简单稳定适合快速回归
- **MM-Vet**：定义 6 种核心视觉语言能力（识别、OCR、知识、语言生成、空间感知、数学）及其 **16 种组合**，用 LLM judge 给 0-1 分，评测"能力集成"
- **BLINK**：14 个"人类瞬间可解、模型极差"的经典视觉感知任务（相对深度、多视角对应、视觉相似性），人类 95.7% vs GPT-4V 51.3% → 揭示 MLLM 的**感知层根本缺陷**

## 5. 多模态评测集构建实操（JD：「评测数据集设计与标注规范」）

### 5.1 数据来源与风险
- 网络图片：**版权 + 污染**风险高（很可能在训练集里）
- 自拍/自采图：最安全，抗污染最佳
- 合成图（渲染/PPT/图表生成）：可控且可自动生成标签，适合规模化
- 编辑图（HallusionBench 做法）：制造反常识样本，最能测幻觉

### 5.2 标注规范要点
- 每题必须标：**能力维度标签、难度、是否依赖视觉、图像类型**
- 多选题要设计**强干扰项**（与正确答案在图中共现或语义相近）
- 开放题需给出参考答案 + 评分 Rubric（分档行为描述）
- 试标算 κ，< 0.6 回炉

### 5.3 质量校验实验（做完必须跑）
1. **纯文本消融**（去图）→ 剔除高分题
2. **纯图消融**（去题干）→ 检查是否可猜
3. **CircularEval** → 检查选项偏置
4. **污染检测** → 图像哈希比对 + 文本 n-gram
5. **人类基线** → 请标注员做题，人类分数太低说明题目有歧义

## 6. 工程化落地

### 6.1 框架
| 框架 | 说明 |
|---|---|
| **VLMEvalKit**（open-compass）| **首选**，70+ benchmark、主流开源与 API 模型一键接入，配套 OpenVLM Leaderboard |
| **lmms-eval**（LMMs-Lab）| harness 风格，与学术论文对齐好 |
| OpenCompass | 统一调度，与 VLMEvalKit 同源 |
| 各 benchmark 官方 repo | 复现官方数字时必查 |

### 6.2 多模态特有的工程难点
- **数据体量大**：视频评测动辄 TB 级，需要缓存与分片
- **抽帧成本**：预抽帧缓存为 npy/jpg，避免重复解码
- **API 图像传输**：base64 体积大、限流严，需压缩与并发控制
- **答案抽取**：MLLM 输出格式最散乱，建议「规则抽取 → 失败则 LLM 抽取 → 仍失败记为 fail」三级策略，并单独统计 fail rate
- **多图/交错输入**：不同模型接口差异大，需适配层

## 7. 结果分析要点

写多模态评测报告时，除了分数表，必须给出：
1. **MG / ML 指标**（多模态增益与泄露）——证明分数是"真视觉能力"
2. **分能力维度雷达图**：感知 vs 认知 vs OCR vs 幻觉
3. **Yes-ratio 分析**：模型是否倾向说 Yes（POPE/MME 场景）
4. **分辨率/帧数敏感性曲线**：定位是能力问题还是输入配置问题
5. **Bad case 分类**：语言幻觉 / 视觉错觉 / 细粒度感知 / 格式抽取失败
