# 03 自动化评测工具开发及维护

> 对应 JD：「评测相关自动化评测工具开发及维护」。
> 评测岗从"会跑评测"到"能造评测工具"，是工程能力的分水岭（字节/美团框架岗核心要求）。

---

## 0. 为什么评测岗要会写工具

- 论文里的评测脚本**不能复用**到内部模型/业务；
- 手工跑评测不可复现、不可规模化、无法接 CI；
- 大厂评测岗日常 50%+ 时间在写/维护评测工具，而非跑分。

工具形态分三类：**CLI 脚本**（个人/单任务）、**评测框架**（多数据集多模型）、**Web 平台**（多人协作 + 看板）。

---

## 1. 评测工具分类

| 类型 | 受众 | 例子 | 你扮演的角色 |
|---|---|---|---|
| 单机 CLI/脚本 | 自己/算法 | 跑 MMLU 的 py | 开发者 |
| 配置化框架 | 评测团队 | OpenCompass | 二次开发者/维护者 |
| Web 平台 | 全员 | 内部评测中台 | 平台工程师 |
| 标注平台 | 人评团队 | 内部标注系统 | 规范设计 + 对接 |

## 2. 通用架构（七层 Pipeline）

```
配置层 (YAML: 模型/数据集/prompt/解码参数)
   │
任务调度 (分片、并发、断点续跑、失败重试)
   │
推理层 (vLLM/SGLang 本地 | OpenAI-compatible API)
   │
后处理 (答案抽取、归一化、抽取失败标记)
   │
判分层 (规则 | 代码沙箱 | LLM-Judge | RM 打分)   ← 插件化
   │
聚合层 (分维度得分、置信区间、bootstrap)
   │
报告层 (对比表、雷达图、bad case、回归曲线)
   │
闭环层 (接 CI：checkpoint 触发评测 → 回写看板)
```

> 这就是 `语言模型评测/学习笔记.md` §6.1 的架构图，是几乎所有评测工具的蓝图。

## 3. 关键工程问题（面试必问）

### 3.1 可复现性
记录 **model hash + 数据集版本 + prompt 模板 + 解码参数 + 框架 commit**。任何一项变了，分数不可比。

### 3.2 并发与限流
API 模型有 RPM/TPM 限制，必须：指数退避重试 + 信号量限流 + 请求队列。

```python
import asyncio, aiohttp
sem = asyncio.Semaphore(20)  # 并发上限
async def call_judge(prompt):
    async with sem:
        for attempt in range(5):
            try:
                return await post(...)
            except RateLimit:
                await asyncio.sleep(2 ** attempt)  # 指数退避
```

### 3.3 判分缓存
LLM-judge 调用贵且慢。相同 (prompt, answer_a, answer_b) 命中缓存直接返回，可降本 80%+。

### 3.4 代码执行沙箱
SWE-bench 类评测必须**容器隔离 + 超时 + 网络隔离**，防止模型生成危险代码或作弊改测试。

### 3.5 断点续跑
大模型评测动辄几小时，中断要能从 checkpoint 续跑，而不是从头来。

### 3.6 抽取失败处理
MLLM/LLM 输出格式散乱，三级策略：规则抽取 → LLM 抽取 → 仍失败记 fail，并**单独统计 fail rate**（fail rate 高说明模型格式遵循差，本身也是结论）。

## 4. 开源框架选型（别重复造轮子）

| 框架 | 适用 | 何时直接用 / 何时二次开发 |
|---|---|---|
| **OpenCompass** | 中英数据集最全 | 中文场景首选，按其规范加数据集 |
| **lm-evaluation-harness** | 国际标准、loglikelihood 严谨 | 对齐论文数字，自定义任务写 task 配置 |
| **EvalScope**（阿里） | 评测+性能压测 | 需同时测效果与性能 |
| **DeepEval / Ragas** | RAG/Agent 应用层 | 业务侧 RAG 评测直接用 |
| **promptfoo** | prompt/模型回归对比 | A/B 对比、prompt 版本管理 |
| **EvalPlus** | HumanEval 增强 | 代码评测防泄漏 |

## 5. 自己造轮子的最小实现（伪代码骨架）

一个可复跑的单数据集评测 CLI：

```python
# eval_cli.py —— 极简但完整的评测工具骨架
@dataclass
class Config:
    model: str; dataset: str; shots: int; temperature: float

def load_dataset(cfg): ...          # 读数据集
def build_prompt(item, cfg): ...    # 拼 few-shot + 题目
def infer(prompt, cfg): ...         # 调 vLLM/API
def extract_answer(raw): ...        # 正则抽 "A"
def grade(pred, gold): ...          # 判分

def main():
    cfg = load_config("config.yaml")
    items = load_dataset(cfg)
    scores = []
    for it in tqdm(items):
        raw = infer(build_prompt(it, cfg), cfg)
        pred = extract_answer(raw)
        scores.append(grade(pred, it.gold))
    report(scores, bootstrap_ci=True)   # 带置信区间
```

> 进阶：把 `infer/grade` 做成插件接口，加 YAML 注册，就是迷你 OpenCompass。

## 6. 维护：让工具活下去

- **版本管理**：评测框架本身要有版本，模型分数带"框架版本"标签。
- **回归测试**：工具改了要跑小集回归，防止"评测工具自己改了分数"。
- **监控告警**：judge API 成本/失败率超阈值告警。
- **文档与 onboarding**：Rubric、指标定义、跑法写清，否则别人不敢用。
- **成本看板**：每次全量评测的 token 成本，优化缓存与分层评测（先小集筛再大集验）。
