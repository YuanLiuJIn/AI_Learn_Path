## 9.1 评测体系构建方法论

### 9.1.1 四大评测要素（任何评测方案都逃不开）

| 要素 | 含义 | 常用指标 / 手段 |
|---|---|---|
| **准确性** | 任务做对没 | Exact Match、ROUGE/BLEU、Pass@k、准确率 |
| **鲁棒性** | 输入扰动后性能掉多少 | 字/词/句篡改、对抗扰动下的得分衰减 |
| **校准度** | 模型"知不知道自己不知道" | **ECE（Expected Calibration Error，期望校准误差）**——把置信度分桶，比较桶内准确率与平均置信度 |
| **效率** | 资源/成本 | 训练/推理 FLOPS、延迟、Token 消耗、参数量 |

> 校准度是评测岗常被忽视但极关键的一维：高置信低正确 = 模型"幻觉且自信"，比低置信更危险。ECE 公式：`ECE = Σ_b (n_b/N)·|acc(b) − conf(b)|`。

### 9.1.2 评测目的三元分类（决定你用什么方法）

- **能力评测（Benchmark Evaluation）**：标准化题目 + 自动判分，量化基础能力差距；趋势是从"学术基准"走向"真实场景评测"。
- **人工评测（Human Evaluation）**：人类洞察找缺陷（逻辑漏洞、风格问题），定位训练优化方向，贵但不可替代。
- **产品评测（Product Evaluation）**：站在用户视角，测功能性 / 可信度 / 个性化——代表**用户偏好**而非纯模型能力，是 AI Native 应用迭代的核心驱动。

### 9.1.3 "能力 — 任务 — 报表"三维测评系统

- **多粒度能力映射**：一级能力（如"文本生成"）拆二级（通用写作 / 续写生成…），形成能力树。
- **混合标注体系**：人工背靠背标注 + 强模型自动标注协同，兼顾质量与规模。
- **动态测评模式**：单模型测评 / 多模型竞技场（Arena）/ 普考对比，按场景切换。
- **HELM 本地化升级**：在 HELM 的"场景 × 指标"矩阵上加**中文特性问题库**，强化开放生成能力评估（见 `06_数据化思维与基础评估指标.md`、`核心论文阅读路线.md` A3）。

### 9.1.4 评测题标签体系（解决"题目归属模糊"）

采用 **任务（Task）× 领域（Domain）× 难度（Difficulty）** 三维标签：
- **任务**：知识问答、逻辑推理…再拆二级（如知识问答下分"事实查找""概念解释"）。
- **领域**：基于"个人—社会—世界"分层（教育求职 / 科学技术 / 日常交互…）。
- **价值**：复合型题（如"宇宙科普游戏"）可同时标"代码 + 天文"，避免强行归类。

### 9.1.5 评测集构建策略（从哪来、怎么出）

- **题目来源**：
  - 用户日志挖掘（高价值负反馈数据，最贴近真实失败）
  - 公网舆情（极端案例补充）
  - 学术 Benchmark（横向对齐）
  - 垂类数据自建（攻克业务痛点）
- **出题逻辑**：
  - **自上而下**：海量数据 → 去噪 → 难度过滤 → 自动打标，填充"中药柜式"题库。
  - **自下而上**：定向补全长尾（冷门历史）、实时追踪热点（新政策 / 新游戏）。
- **题目价值法则**：**区分度 ＞ 难度**。用多模型表现筛题——全错（太难）或全对（太易）的题区分度低，应淘汰；保留能拉开模型差距的题。

## 9.2 评测方法的历史脉络（从 GPT 系列看演变）

归纳公开评测实践，能力评测随模型演化经历了清晰的方法升级：

| 阶段 | 评测重心 | 代表手段 |
|---|---|---|
| 早期（GPT-1/2） | 传统 NLP 任务 | GLUE 等标准集 |
| 规模期（GPT-3） | 数学 / 生成 / 少样本 | 人工主观评测（盲测辨伪）、Few-shot |
| 代码期（Codex） | 代码生成 | **HumanEval + pass@k**（单元测试通过率） |
| 对齐期（InstructGPT） | 安全 / 人类偏好 | 用户偏好率、RLHF 引入（注意"对齐税"：部分 NLP 任务下滑） |
| 多模态期（GPT-4） | 专业考试 / 多语言 / 视觉 | 考试分数、多语言集、毒性降低率 |

**核心方法沉淀（通用）**：
- **客观指标**：BLEU（翻译）、PPL（语言模型）、pass@k（代码）、考试分数。
- **主观评测**：新闻真实性盲测、7 分量表偏好排序。
- **安全性评估**：TruthfulQA（真实性）、RealToxicityPrompts（毒性）、Winogender / CrowS-Pairs（偏见）。
- **污染防护**：n-gram 过滤、考题去重，已成标准流程（详见 `08_常见评测数据集与方法.md` 防污染 best practice）。

> 关键洞察：RLHF 能显著抬升安全/偏好指标，但可能带来"对齐税"——评测时要分项看，不能只盯总分。

## 9.3 度量难题与人工评测局限

> 这一节是评测岗的"哲学必修课"：为什么给 AI 打分比想象中难。

### 9.3.1 偏好投票（Pairwise）的问题
- **模糊性**：维度权重不稳定、程度判定因人而异。
- **群体偏差**：专业 vs 非专业评测者结论可能分歧很大。
- **不可传递性**：A > B、B > C 不代表 A > C，排名依赖"对手池"（和竞技场 Elo 同理，见 `05_Agent工具链与竞技场数据飞轮.md`）。

### 9.3.2 平均意见分数（MOS，Pointwise）的问题
- **主观标尺差异**：不同评测者"5 分"的尺度不一致（需用 κ / 锚定样例校准）。
- **价值取向争议**："可用"的线因用户场景而异。
- **多维认知负担**：图文一致性、结构合理性等交叉影响，单分难以承载。

### 9.3.3 理论困境
- **概念本质模糊**："好/坏""美"难以抽象定义（苏格拉底 vs 希庇阿斯之辩的延伸）。
- **操作化挑战**：类比人类智商测试——智能边界不清，必须"操作化"成可测指标；但**单一总分会简化复杂智能、忽略场景多样性**。

### 9.3.4 实践解法
- **动态定义 + 多元视角**：能力扩展（如生图）要求评测维度从"质检单"升级为"天才解剖图"。
- **场景目标定制**：深植业务场景，区分"基础模型标准"与"产品用户价值"，避免认知鸿沟。
- **人机协同**：机器预判（如 VQA 拆解提示词）+ 人工校准，聚焦人类才擅长的美学/价值判断。

## 9.4 预训练（Base）模型评测：三位一体体系

> 基座模型处于"混沌"状态，评测核心目标是：**定义的指标要能预测模型经过后训练（SFT/RL）后的最终表现**。难点是"元评估缺失"——评估方法本身缺乏验证标准。

### 9.4.1 三大评估组成

| 方法 | 角色 | 怎么做 | 关键洞察 |
|---|---|---|---|
| **端到端评估（金标准）** | 最准 | 不同 Base 用**完全一致**的后训练配置（同 SFT 数据/参数），比下游 pass@n | SFT 数据量越大，模型间 Gap 越小——小数据量（如 40w）更能放大差异，建议"分级评估 + 关键版本压测" |
| **ICL 评估（轻量探测器）** | 省算力 | 用模型 In-Context Learning（Few-shot）能力做任务，作为后训练潜力代理 | 需元评估验证其与端到端的一致性 |
| **PPL 评估（基础诊断）** | 底层 | 在高质量、多样化、**OOD** 数据上测 next-token 困惑度 | 监控训练收敛、指导数据配比、做细粒度可解释诊断 |

### 9.4.2 元评估方法论（验证"评测方法本身可不可信"）

提出三大假设用于校准评测体系：
- **Model Scaling 假设**（验证通过）：同族模型参数越大 ICL 越好（Kendall 系数可达 1.0）。
- **Data Scaling 假设**（结果复杂）：
  - 知识类任务：通常满足（多集 Kendall > 0.8）。
  - 推理类任务：大多不满足（波动来自解码稳定性、解题模式与指令遵循的博弈）。
  - 代码类任务：部分满足。
- **端到端一致性假设**（诊断异常）：
  - 指令偏置干扰：高指令遵循率 ≠ 高 ICL 分数（数学推理尤甚），需同时看**准确率 + 模式遵循率**。
  - 一致性约束：ICL 与端到端背离可暴露评测集本身问题（Prompt 模板不合理、配置异常），指导校准与质量回溯。

### 9.4.3 PPL 的进阶用法
- **训练监控**：PPL 随训练 Token 衰减趋势判断收敛质量。
- **数据配比**：对比模型在不同领域（代码/论文/网页）PPL，指导数据优化。
- **可解释诊断**：
  - 热力图：对比不同模型对同一文本 token 的预测概率差异。
  - **Win-Rate 统计**：按 token 类型（公式符号、功能词、空白符）统计模型间预测胜率，揭示能力特长与短板。

> 趋势：探索 PPL 之外更底层的监控指标（注意力头激活、神经元激活），建立与任务能力的联系。

## 9.5 自动化评测：如何兼顾效率与质量

> 人工标注初期面临人力紧、效率低；自动化目标是在**保质量**前提下把效率提升数倍（一线实践报告 4–8 倍提升）。

### 9.5.1 评测任务三分法（决定用什么技术）

| 类型 | 例子 | 技术路线 |
|---|---|---|
| **主观内容** | 文采、逻辑连贯 | LLM-as-a-Judge + 指令微调统一评分标准，减少人工偏差 |
| **客观内容** | 单选、信息提取 | 规则匹配 + 大模型语义理解（如类型判定），拓展传统规则边界 |
| **复杂场景** | 产品方案推广 | 拆主客观维度综合打分，需更高人工干预 |

### 9.5.2 自动化全链路闭环

```
标准制定 → 自动执行 → 人工校验 → 能力评估 → 持续优化
```
- 沉淀"机评数据集"反哺评测标准与 Agent 性能，形成飞轮（见 `05_Agent工具链与竞技场数据飞轮.md`）。
- **关键技术组合**：
  - 主观：细化评分维度（如信息详细度），前端可视化对比 AB 模型，人机一致率可达 ~97%。
  - 客观：融合 UI 自动化（截图）、多模态模型（链接校验）、键鼠模拟（资源存在性检查），替代人工重复操作。

### 9.5.3 落地案例要点（去标识化）
- **信息抽取类评测**：多维度自动评分，效率提升约 8 倍（0.5 vs 4 人天），沉淀百级样本用于 Agent 优化验证。
- **插件/资源类评测**：强模型判漏召/错召 + 视觉模型校验跳转链接，覆盖 5000+ 样本，成本从 40 人天降至 5.5 人天。

## 9.6 评测流程演进：从"人拉肩扛"到"自动驾驶"

> 把评测团队的成熟度分成三阶段，可作为你搭建/描述评测体系的"成熟度模型"。

1. **人拉肩扛（人工 + 简陋工具）**
   - 产品 owner 全包（标准/标注），灵活但主观、资产分散、重复与信息孤岛。
   - 引入外包 + 在线文档后，协作成本仍高、数据泄露风险大，难撑高频评测。
2. **智能巡航（平台管控 + 工具助力）**
   - 流程自动流转（权限分配、状态通知、进度跟踪）。
   - 资产统一存储（多模态、版本锁定、溯源），标注工作台集成化（多格式渲染、划线引用、历史版本对比）。
3. **自动驾驶（产评析一体化 + 工作流）**
   - LLM 自动评估集成进工作流（如长文本质量监测），部分场景达成"生产—评估—分析"全链路自动化。
   - 目标：人只需设定目标，系统自动跑评测与归因。

## 9.7 LLM Agent 能力评估

> Agent = LLM（智能核心）+ Scaffold（交互脚手架），通过"感知—决策—行动"循环与环境互动。多轮、依赖工具、需外部环境，导致执行成本高、结果不稳定——评测比单轮任务难得多。

### 9.7.1 评估系统核心组成

| 组件 | 说明 |
|---|---|
| **任务 Task** | 如机票预订、代码开发等具体场景 |
| **尝试 Trial** | 多次执行测稳定性 |
| **轨迹 Trajectory** | 记录"思考—行动—观察"全流程 |
| **评分器 Grader** | 从结果正确性 / 成本 / 稳定性等维度打分 |

### 9.7.2 评估维度
- **结果准确性**：环境状态 + 回复双重检查。
- **执行成本**：Token 消耗 / 时间。
- **稳定性**：pass@k。
- **核心能力**：规划 / 工具调用 / 反思等专项评估。

### 9.7.3 评分器类型
- **规则型**：检查工具调用序列或环境状态（如数据库记录）。
- **模型/Agent 型**：LLM 评语义一致性（如 GDPEval）；趋势是 Agent-Judge（自动评分）。
- **人工**：高成本，适合科学等复杂场景。

### 9.7.4 典型场景基准（横向对比）
- 编程开发：单元测试验证（SWE-bench / SWE-Verified）。
- Web 交互：浏览器状态检查（WebArena、VisualWebArena）。
- 科研任务：多工具协同（ScienceAgentBench）。
- 移动/桌面：系统状态变化（OSWorld、AndroidArena）。

### 9.7.5 发展趋势
- 环境：静态文本 → 动态多模态（视频交互）、有状态任务。
- 协作：单代理 → 多代理（异构分工、竞争协作）。
- 精细化：人工 → Agent 自动评分；粗粒度结果 → 细粒度过程分析（决策耗时）；纯效果 → 兼顾效率（资源消耗）。

## 9.8 一页速查：本章可复用的"评测体系清单"

1. **四要素**：准确性 / 鲁棒性 / 校准度（ECE）/ 效率——方案必有这四项。
2. **三元目的**：能力评测 / 人工评测 / 产品评测——先定目的再选方法。
3. **三维标签**：任务 × 领域 × 难度——建题库的标准结构。
4. **题目价值**：区分度 ＞ 难度——用多模型表现筛题。
5. **人工度量三坑**：偏好不可传递、MOS 标尺不一、单一总分简化智能。
6. **Base 评测三位一体**：端到端（金标准）/ ICL（轻量）/ PPL（诊断）+ 元评估校准。
7. **自动化闭环**：标准→执行→校验→评估→优化；人机一致率应作为质量红线。
8. **成熟度三阶段**：人拉肩扛 → 智能巡航 → 自动驾驶。
9. **Agent 评估四组件**：任务 / 尝试 / 轨迹 / 评分器；评分器三类（规则/模型/人工）。
10. **污染防护**：n-gram 过滤 + 考题去重，贯穿全流程。
