# 04. LLM-as-Judge：用大模型当裁判

> 目标：理解"让 LLM 评测 LLM"的方法、优势和陷阱。

---

## 1. 为什么需要 LLM 当裁判？

```text
传统评测的限制：

选择题 → 只有"对/错"，不适用于"回答好不好"
人类评测 → 太贵、太慢、不可规模化
规则评测 → 只能测格式，不能测质量

很多场景下，没有标准答案：
  问题："解释什么是黑洞"
  A："黑洞是引力极强的天体，连光都无法逃脱"
  B："黑洞就是宇宙里一个很黑的洞"

  人类能判断 A > B，但机器怎么判断？
  → LLM 当裁判（LLM-as-Judge）
```

---

## 2. 三种裁判模式

```text
模式 1：单打分（Single Score）
  给裁判一个问题和回答，裁判打 1-10 分
  代表：AlpacaEval

模式 2：对比打分（Pairwise Comparison）
  给裁判一个问题 + 两个回答，裁判选更好的
  代表：Chatbot Arena、MT-Bench

模式 3：多维度评分（Multi-dimension）
  裁判从多个维度（准确性、完整性、流畅性）分别打分
  代表：MT-Bench（精评版）
```

---

## 3. 核心评测：MT-Bench

```text
MT-Bench（Zheng et al., 2023）

设计：
  80 个高质量多轮对话问题
  覆盖 8 大类：写作、角色扮演、推理、数学、代码、知识...
  
  使用 GPT-4 作为裁判
  对每个回答评分 1-10
  多轮对话分别评分

特点：
  ① 多轮对话评估（不是单轮）
  ② 精评 + 粗评两种模式
  ③ 和人类偏好相关性高
```

---

## 4. 核心评测：AlpacaEval 2.0

```text
AlpacaEval 2.0（Li et al., 2023）

设计：
  805 条指令
  裁判（GPT-4-turbo）评估回答相对于参考回答的质量
  输出胜率（Win Rate）

关键改进（Length-Controlled 版）：
  原始版本存在长度偏差：长回答得分更高（即使内容重复）
  LC 版用回归修正长度影响
  修正后和 Chatbot Arena 人类偏好排名相关度达 0.98

局限：
  只评估单轮对话
  裁判模型固定为 GPT-4-turbo
  参考回答质量影响评分
```

---

## 5. Chatbot Arena

```text
Chatbot Arena（LMSYS, 2023）

设计：
  用户任意提问 → 两个匿名模型同时回答
  → 用户投票选更好的 → 积累数十万投票
  → Elo 评分排名

特点：
  ① 完全开放域（任何问题都可提问）
  ② 人类投票（而非 LLM 打分）
  ③ 实时更新（持续有新模型加入）
  ④ 完全防数据污染（用户实时生成问题）

公认地位：
  目前最权威的对话能力排名
  但只能测"对话"，不能测"代码""数学"等专项
```

---

## 6. LLM-as-Judge 的五个陷阱

```text
陷阱 1：位置偏差
  裁判倾向于偏袒第一个回答
  解决：每次交换 A/B 位置，取两轮平均

陷阱 2：冗长偏差（Verbosity Bias）
  更长的回答得分更高（即使内容质量相同）
  解决：AlpacaEval LC 版做长度修正

陷阱 3：自增强偏差（Self-Enhancement）
  裁判倾向于给自己同系列的回答更高分
  GPT-4 裁判给 GPT-4 回答打高分 → 不公平
  解决：用不同家族的模型当裁判

陷阱 4：偏好泄漏（Preference Leakage）
  裁判和生成模型有共同训练数据
  → 裁判无意中偏袒
  → 2025 研究发现这是一个系统性问题

陷阱 5：风格偏好
  裁判倾向于一种回答"风格"（正式/幽默/简洁）
  不代表这种风格客观上更好
```

---

## 7. 一句话总结

> LLM-as-Judge 是评测开放域问答的最实用方案。MT-Bench 做精细评分，AlpacaEval 做快速对比，Chatbot Arena 做人类偏好基准。但要警惕五个陷阱：位置偏差、冗长偏差、自增强偏差、偏好泄漏和风格偏好。
